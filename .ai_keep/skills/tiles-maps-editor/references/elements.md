# elements.md — 元素识别结果怎么读

`scripts/elements.py` 输出的是「这张图由什么构成」。这份文档解释每一栏的含义、
以及判别背后的原理（为什么不能信 `category` 标签）。

## 输出结构

```
# 元素识别报告 — <地图名>
- 尺寸：43 x 56 格
## 元素构成（按像素材质判定）
| 元素 | 格数 | 涉及 gid（gid=格数） |
## 道路走向（L1 层，水平连续段）
## 建筑轮廓
## 活物清单
## gid → 材质全表
```

## 元素构成表

一行是一种「元素类别」，列出它由哪些 gid 构成、各占多少格。

- **格数多的说明**：改动影响面大，动手前先看 `material.txt` 确认位置
- **同一元素有多个 gid**：通常是同一素材的不同变体（自动生成的草地边缘、路面转角）
  —— **要整条统一替换时，必须把所有变体 gid 一起换掉**，否则会混色成碎花
- **gid 括号里的数字是格数**，不是坐标

## 材质判别原理

### 不可信：`category` 标签

图集描述文件 `compiled_tileset_32x32.json` 给每格标了 `category`，
但实测**严重失真**：

> L1 地面 1580 格草地，全部被标成 `building_wall`；L2 的 228 格树也被标成 `building_wall`。

所以 **`category` 只能当最后兜底**，主判据是**像素色**。

### 不可信：`avg_color`

`avg_color` 是整格平均色，对「主体 + 少量点缀」的道具会算偏：
搜 `--grey` 时返回了路灯、剑、书架。

**解法**：加 `--min-uniform`（像素标准差阈值）。
纹理均匀（std < 0.6）= 路面/墙面/地板；不均匀（std < 0.5）= 家具/角色。

### 可信：像素色

元素识别实际使用的调色板（来自 dawnlike 图集实测）：

| 色 | RGB | 判为 |
|---|---|---|
| 草地绿 | (109,170,44) | 地面/草地 |
| 绿篱深绿 | (71,112,76) | 绿篱/灌木 |
| 树冠墨绿 | (86,104,65) | 树 |
| 木橙 | (211,125,44) | 木构件/木地板/土路 |
| 建筑暖棕 | (180,114,53) | 建筑墙体/屋檐 |
| 中性灰 | (117,113,97) | 石块/围墙 |
| 石板蓝灰 | (134,150,162) | 石板路/金属 |
| 水泥深灰 | (77,73,77) | 水泥路面/铁件 |
| 描边紫黑 | (20,12,28) | 轮廓线（中性，不判材质） |

> 判别口诀：**绿 = 植物，橙 = 木/土，暖棕 = 建筑，灰蓝 = 石头/金属，深灰 = 水泥**。

## 道路走向表

每行是 L1 层上一段**水平连续**的路，列出 y 坐标、x 起止、宽度。

**用途**：
- 改路面材质时，**按整段替换**，不要只取中心线
  （只换中心线 → 橙白混排成碎花，这是上一轮的真实错误）
- 判断路口：多段在同 y 相交 = 丁字/十字路口
- 判断「断头路」：某段 x 起点比上一段突然缩进很多 = 路被建筑挡住了

**⚠️ 换路面时别忘了路缘瓦片**：老的土路两侧有「草地+土边」变体（延城一中 gid **7864**，
整格橙边）。把路面换成石板后，这些橙边会整条露出来变成一根橙线。
**换路面材质时，边缘变体必须同批一起换**（要么全换、要么全留）。

**注意**：垂直方向的道路不在这张表里（表只扫水平连续段）。
要看竖路，用 `material.txt` 或 `layer-L1.png` 逐列看。

## 建筑轮廓

识别**实心屋顶块**（4 邻域连通）。上一轮的关键发现：

> 延城一中的屋顶在 **y=13~15**，它**压住了** y=9~12 那个真正有门有家具的房间。
> 拆掉屋顶 y=13~15 之后，露出来的才是教室。

**所以**：拆屋顶前，一定要先确认「上下哪边才是有门有家具的那一侧」。
判据 = 那边的对象层里有 DOOR 对象、有家具类 gid。

## 活物清单

对象层（`objectgroup`）里的对象，标注 `entity_type` 与 gid。

- `DOOR` = 门（gid 569/570，横向/纵向）
- `CHEST` = 箱子
- `NPC` = 剧情角色
- 野怪用 `entity_types.json` 里的 `HT_FAKE_*` 类型

**门的位置就是建筑轮廓的权威来源** —— 比任何脚本推断都可靠。

## gid → 材质全表

按 gid 排序，每个 gid 对应一种材质判定。改地图时直接查这张表，
确认「我要换的 gid 是不是真的那类东西」。

## 实战顺序

```sh
# 1. 先看图
python cognitive-tiles-maps/scripts/inspect_map.py <map.json>
#    → 读 <name>.png（整图）+ material.txt（逐格）

# 2. 再盘元素
python tiles-maps-editor/scripts/elements.py <map.json>
#    → 拿 gid 清单 + 道路走向 + 建筑轮廓

# 3. 找替代瓦片
python cognitive-tiles-maps/scripts/find_tiles.py <atlas.png> --grey --min-uniform 0.6
#    → 拿到候选 gid 后，用上面两张表核对

# 4. 改完必须看图（铁律 #0）
python cognitive-tiles-maps/scripts/inspect_map.py <map.json>
#    → 用 Read 打开渲染 PNG 亲眼看
```
