# 赦夜人冥夜走廊-第二季 · 任务参考列表

> 用途：① 写地图集 `quests.json` / 事件脚本 `ctx.quest.*` 时直接抄 JSON；② 给「任务板 → AI 生成可接任务」提供**字段契约**（AI 输出会被收敛进本表枚举）。
> 每个任务的 JSON 都是**插件原生字段**（`entry.ts` 的 `QuestDef` / `QuestProgress`），可直接当 `quest_defs[]` 的元素使用。

---

## 1. 字段规范

### 1.1 `QuestDef`（任务定义 · 任务板上的一条）

| 字段 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| `id` | string | ✅ | 任务唯一 id，建议 `Q<两位数字>`。**重名会覆盖**，同一故事内不可重复 |
| `title` | string | ✅ | 任务标题。**最长 12 字**（`cleanTitle().slice(0,12)`），超了会被截断 |
| `type` | 见 1.2 | ✅ | 任务类型，决定进度怎么记、UI 怎么显示 |
| `giver` | string | ✅ | 发布者（`"任务板"` 或 NPC 名）。只做展示 |
| `map` | string | ⬜ | 任务**发布地图**（前端关卡名，如 `mulberryTown`）。空 = 全图可接 |
| `desc` | string | ⬜ | 任务描述（面板「详情」里显示，AI 问答也会拿到） |
| `level` | number | ⬜ | 推荐等级。低于该等级时面板标红提示 |
| `objectives` | `Objective[]` | ✅ | 目标列表（见 1.3），**全部达成才算完成** |
| `reward` | `Reward` | ✅ | 奖励（见 1.4） |
| `repeat` | boolean | ⬜ | 可重复接取（日常/委托类）。默认 false |
| `timeLimitTicks` | number | ⬜ | 限时（tick，1 tick = 100ms）。0 / 缺省 = 不限时 |
| `turnInMap` | string | ⬜ | 交任务地图。空 = 任意地图可交（默认回任务板交） |
| `flags` | `{accept?, done?}` | ⬜ | 完成时顺带写的玩家 flag（供事件系统 `flag_check` 用） |

### 1.2 `type` 合法取值

| 值 | 中文 | 进度来源 | 完成方式 |
|----|------|---------|---------|
| `kill` | 击杀类 | 宿主 `damage()` 击杀分支自动累加 | 自动（杀够即完成） |
| `gather` | 采集类 | 物品入包链（`sys_item_add` / `ctx.bag.give` / 开箱）自动累加 | 自动 |
| `escort` | 护送类 | 接取时生成货物跟随实体；玩家到达目的地**点「到达」** | 手动按钮 |
| `deliver` | 送达类 | 把指定物品送到指定地点/NPC，到点**点「交付」** | 手动按钮 |
| `explore` | 探索类 | 玩家进入目标区域/地图（半径判定） | 手动按钮（也可自动） |
| `talk` | 对话类 | 与目标 NPC 对话过（`sys_chat` 命中该 uid） | 自动 |

### 1.3 `Objective`（目标项）

| 字段 | 类型 | 说明 |
|------|------|------|
| `kind` | `"kill"\|"gather"\|"arrive"\|"talk"\|"explore"` | 目标种类 |
| `target` | string | `kill`=野怪名（模糊包含匹配，如 `"尸傀"`）；`gather`=物品名；`talk`/`explore`=NPC 名或 zone 名 |
| `count` | number | 需要数量（`kill`/`gather` 必填） |
| `map` | string | `arrive`/`explore` 的目标地图（前端关卡名） |
| `x` / `y` | number | `arrive` 的目标坐标（**米**，地图中心为原点） |
| `radius` | number | `arrive`/`explore` 判定半径（米），默认 3 |
| `confirm` | boolean | `true` = 必须玩家点按钮才算（护送/送达就靠它）；`false` = 走到就自动完成 |
| `uid` | string | `talk` 目标的 Tiled 对象 id |

### 1.4 `Reward`

```json
{ "exp": 120, "money": 80, "items": [{ "name": "暗核", "count": 1 }] }
```

- `exp` 走 `gainPlayerExp`（会触发升级判定，溢出保留）
- `items` 走 `addBagItemToCard`（真的进背包 + 写参数卡）
- 三项都可省略（缺省 0 / 空）

### 1.5 `QuestProgress`（运行时进度 · 存在 `s.quests[id]`）

```json
{
  "id": "Q01",
  "status": "active",
  "kill": { "尸傀": 3 },
  "gather": {},
  "arrived": false,
  "cargoId": "",
  "acceptedTick": 120,
  "acceptedMap": "mulberryTown",
  "turnedTick": 0
}
```

| 字段 | 说明 |
|------|------|
| `status` | `active` 进行中 / `done` 已完成待交 / `turned` 已领奖 / `failed` 失败（护送货物被打掉） |
| `kill` | `{野怪名: 已杀数}` |
| `gather` | `{物品名: 已采数}` |
| `arrived` | `arrive` 类目标是否已点「到达」 |
| `cargoId` | 护送货物实体 id（escort 专用） |

> ⚠️ 进度**只在宿主侧权威**（`t_plugin_session_data` 的 `sys_state`），前端只读不写。
> 掉线重连按 `id` 续上，不会因为刷新而清零。

## 2. 任务类型总表

| 类型 | 触发进度的地方 | UI 按钮 | 备注 |
|------|--------------|--------|------|
| `kill` | `entry.ts damage()` 敌人 hp≤0 | 无（自动） | 按名字包含匹配，杀「尸傀王」也算「尸傀」 |
| `gather` | 入包链 `addBagItemToCard` | 无（自动） | 采到就计数，**用掉不影响**（记的是累计获得） |
| `escort` | 接取即生成货物 | 「到达」 | 货物被打掉 → `failed`，可重接 |
| `deliver` | 到点 | 「交付」 | 交付时**扣掉**背包里对应物品 |
| `explore` | 进入半径 | 「到达」/自动 | 切图也能判（按 `map` + 坐标） |
| `talk` | `sys_chat` 命中 uid | 无（自动） | 需要地图 Actors 里有该 NPC 对象 |

## 3. 各类型 JSON 示例

### 3.1 击杀类（kill）

```json
{
  "id": "Q01",
  "title": "清剿夜行尸傀",
  "type": "kill",
  "giver": "任务板",
  "map": "mulberryTown",
  "desc": "乱葬岗的尸傀又多了。清掉五只，46 号按数结账。",

  "repeat": true,
  "turnInMap": "mulberryTown",
  "flags": { "done": "q01_done" }
}
```

### 3.2 护送类（escort）—— 到达后点「到达」

```json
{
  "id": "Q03",
  "title": "护送药材箱",

  "giver": "任务板",
  "map": "mulberryTown",
  "desc": "把这箱夜采药材送到桑林交接点。箱子掉了这单就黄了。",

```

> `cargo` 缺省时兜底 `{ name: "货物", hp: 50 }`。接取后在玩家身边生成跟随实体 `questcargo_Q03`，

## 5. 任务板交互协议（前端 ↔ 宿主）

| action | 参数 | 作用 | 返回 |
|--------|------|------|------|
| `sys_quest_pool` | `{ defs: QuestDef[] }` | 下发/覆盖任务定义（宿主、事件脚本、CLI 上传） | 任务数 |
| `sys_quest_board` | — | 打开任务板：返回可接 / 进行中 / 待交 / 已交 | 面板数据 |
| `sys_quest_accept` | `{ id }` | 接取（escort 会生成货物） | 提示 |
| `sys_quest_turnin` | `{ id }` | 交任务领奖（写 flag、发物品经验金钱） | 提示 |
| `sys_quest_abandon` | `{ id }` | 放弃（清进度、删货物；`repeat` 可重接） | 提示 |
| `sys_quest_arrive` | `{ id }` | 点「到达」/「交付」（校验半径 + 地图） | 提示 |
| `sys_quest_ask` | `{ id, question? }` | 问 AI 这个任务的详情/建议 | `questAiText` |
| `sys_quest_generate` | `{ map?, n? }` | AI 按故事生成本图可接任务，并入 `questBoard` | 新任务数 |

进度钩子（宿主自动，不需要事件脚本写）：

| 事件 | 进度 |
|------|------|
| 敌人 hp≤0 | `kill[目标] += 1` |
| 物品入包 | `gather[物品] += count` |
| `sys_chat` 命中 NPC uid | `talk` 目标 +1 |
| 护送货物实体死亡 | 该任务 → `failed` |

## 6. 三条硬约束

1. **`title` ≤ 12 字**，`entry.ts` 会 `slice(0,12)` 静默截断。
2. **`confirm: true` 的 `arrive` 目标必须玩家点按钮**——护送/送达就是靠这个，写成自动就少了「到达」这个仪式感。
3. **进度只认宿主**。`s.quests` 随 `sys_state` 持久化，前端改了也会被下一次 tick 覆盖。
