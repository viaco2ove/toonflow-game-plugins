# 任务板
走进任务板后 点击"任务" 可以接受任务 和完成任务 和放弃任务

ai 获取可接任务，程序获得已接任务。状态：进行中/已完成（点击获得奖励），可放弃任务，任务信息（点击查看信息，暂时任务详情，用户也可发送信息，ai回答）

## 1. 已实现（2026-10-16）

### 1.1 地图（任务板对象）

`.cache/add_quest_board_obj.py` 往两张地图的 **Actors 层** 加了对象（原文件已备份到 `maps/bak/`）：

| 地图 | Tiled id | 世界坐标 | 贴图 gid |
|------|:--:|------|:--:|
| `mulberryTown.json`（桑镇） | 900 | (6, 24) | 58（箱子） |
| `mulberryForest.json`（桑林） | 900 | (0, 0) | 58（箱子） |

关键属性：`entity_type=NPC`、`name/full_name=任务板`、可选 `dialog=BOARD`。
`mapConfig.normalizeTiledMap` 会把它生成 `mapnpc_900` 实体 → App.vue 走近显示「📜 任务」。
同时 `updateNearChat` 已排除任务板（`/任务板|委托板|公告板/`），不会跟「💬 聊天」撞车。

> 桑林也放一块是为了**护送类任务能就地交**（Q03/Q10 的目的地都在桑林）。

### 1.2 插件侧（`entry.ts`，权威）

| 新增 | 作用 |
|------|------|
| `QuestDef` / `QuestObjective` / `QuestProgress` | 数据契约（见 `任务参考.list.md` §1） |
| `s.questBoard` / `s.quests` / `s.questView` | 任务定义 / 玩家进度 / 前端视图；随 `sys_state` 持久化 |
| `normalizeQuestDef` | 任意来源（AI/JSON/参数卡）收敛：标题截 12 字、type 与 kind 走枚举、非法项丢弃 |
| `noteQuestKill` / `noteQuestGather` / `noteQuestTalk` | 进度钩子，分别挂在 `damage()` 击杀分支、`addBagItemToCard` 入包、`sys_chat` |
| `syncQuestArriveAuto` | 每 tick：非 confirm 的到达目标走进半径即完成 + 护送货物跟随玩家 |
| `questArriveOk` | 点「到达」时校验地图 + 半径 |
| `spawnQuestCargo` / `removeQuestCargo` | 护送货物 `questcargo_<任务id>`；**被打掉 → 任务 failed** |
| `buildQuestView` | 产出 `available / active / done / turned` 四栏 + `canTurnIn / canArrive / atDest / progress` |
| `setPlayerFlag` / `removeBagItemFromCard` | 完成时写 `player_flags`（供事件系统 `flag_check`）；交付时扣背包 |
| `ensureQuestDefs` | 开局读 `pluginData["quest_defs"]`（CLI 上传的故事任务表） |

**状态机**：`active → done（目标达成，待交）→ turned（已领奖）`；护送另有 `active → failed`（货物被打掉，放弃后可重接）。

### 1.3 action 协议

| action | 参数 | 说明 |
|--------|------|------|
| `sys_quest_board` | — | 打开任务板（重算视图；board 为空时先读 `quest_defs`） |
| `sys_quest_pool` | `{defs, mode}` | 下发/覆盖任务定义（`mode=replace` 整体替换，缺省按 id 合并） |
| `sys_quest_accept` | `{id}` | 接取（escort 生成货物；写 `flags.accept`） |
| `sys_quest_turnin` | `{id}` | 交任务：扣 `consume` 物品 → 发 exp/金钱/物品 → 写 `flags.done` |
| `sys_quest_abandon` | `{id}` | 放弃（清进度 + 删货物；`repeat` 可重接） |
| `sys_quest_arrive` | `{id}` | 点「到达 / 交付」：校验地图 + 半径才认 |
| `sys_quest_ask` | `{id, question}` | 问 AI 任务详情（结果写 `s.questAiText`，`_questAsking` 期间前端显示思考中） |
| `sys_quest_generate` | `{n}` | **AI 获取可接任务**：调 `task-speaker-agent` 按故事 + 本图生成委托并入 board |

## 2. 三条硬约束（踩过的坑）

1. **任务不是事件**。事件引擎只有 `enter_map` / `interact` / `area_enter` 三个挂载点，`kill_count` 之类写了永不触发。
   所以任务进度全部落在插件的伤害/入包/对话链路上，地图集只提供**数据**（`quests.json`）+ **板子位置**。
2. **进度只认宿主**。`s.quests` 随 `sys_state` 落库；前端改了也会被下一次 tick 覆盖。面板只读 `s.questView`。
3. **护送的仪式感靠 `confirm: true`**。写成自动完成就没有「到达」按钮了；`confirm=false` 走进半径即完成。
