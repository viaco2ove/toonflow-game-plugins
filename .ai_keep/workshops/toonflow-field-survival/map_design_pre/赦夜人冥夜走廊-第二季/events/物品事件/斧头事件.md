# 斧头的特殊能力事件-对障碍物进行破坏
斧头-使用后，对障碍物进行破坏
同时在未使用其他技能和物品的情况下，左键或者手机触摸屏幕点击障碍物进行破坏，然后不能通过的地方就能通过。
使用了其他物品或者技能，斧头的特殊能力事件-对障碍物进行破坏就会消失。

# 破坏物的还原
重新进入地图后，破坏物会还原。按现在的地图加载方式，破坏物其实更像是地图重载。所以无需做额外的处理。

---

# 实现说明（已落地，2026-10-16）

## 机制
- 后端在 `FieldSurvivalState` 新增 `axeMode` 标志。
- **使用斧类物品**（`useBagItem` 命中 `AXE_RE = /斧/`，如「斧头/铁斧/伐木斧」）→ 置 `axeMode = true`，不消耗、不攻击，回提示「举起斧头，进入破坏模式」。
- **使用其他任何物品**（非斧）→ `axeMode = false`（收起）。
- **释放任何技能**（HUD `castSkill` 走 `case "skill"`，AI `ai_command.useSkill`）→ `axeMode = false`（收起）。
- 前端 `onCanvasClick`：`axeMode` 为真时，若点中的格子是**障碍（walkGrid.blocked=1）且距玩家 ≤ 3m**，则该格 `blocked` 置 0（变为可通过），并 `walkGridEpochSeq++` 强制把新碰撞网格上报宿主（敌人碰撞同步打开）。点到空地/超距则按普通移动处理，不打断。
- HUD 顶部显示「🪓 斧头破坏模式」提示条；破坏成功飘字 + toast「🪓 障碍物已破坏，可通过」。

## 视觉同步（2026-10-16 修复「能通过但障碍还在画」）

**问题**：破坏只改了碰撞网格 `walkGrid.blocked`，而地图是**一次性烘焙**到离屏 canvas 的（`mapBake.bakeTiledMap`），树瓦片像素还在烘焙图上 → 逻辑放行、视觉仍在。

**修复**：破坏时同步改烘焙图（`mapBake.ts` 新增 `eraseBakedObstacle(gx, gz, isBlockedGid)`）：
1. 在烘焙图上 `clearRect` 掉该格 32×32 像素；
2. 按原层序重绘该格所有**非 blocked** 瓦片（底层地面露出来，树消失）；
3. 全障碍格（如边界墙，无底层可画）用地图主地面色兜底填充（`fallbackColor` = 烘焙时采样出现次数最多的瓦片中心像素），避免透明洞；
4. 同时清 `walkGrid.vision[idx]`（破坏后不再挡视野）并重建 `walkIndex`（该格从「站不下」变「站得下」，A*/连通域才会走这条新缺口）。

**还原**：烘焙缓存按关卡名做 key，切图换 key 会整体重烘焙 → 破坏物自动还原（符合本文档约定）；同一张图内破坏持续有效。

## 还原
- 碰撞网格 `walkGrid` 每次进图由 tileset 重建，破坏只改内存中的 `blocked` → **重新进入地图自动还原**，无需额外处理（符合本文档约定）。

## 如何给玩家一把斧头（测试 / 剧情挂载）
物品名含「斧」即被识别。建议参数卡 `items` 加一行 `"斧头×1"`，并补 `itemMeta["斧头"]`（永久工具，不消耗）：
```json
{
  "items": ["斧头×1"],
  "itemMeta": {
    "斧头": { "power": 0, "cost": 0, "cd": 0, "type": "atk", "range": "melee", "lv": 1, "buff_type": "", "durability": -1, "durabilityLeft": -1, "attribute_type": "", "attribute_value": 0, "quantity": 1, "description": "伐木斧", "effects_type": "normal" }
  }
}
```
> 注：`durability:-1` 仅作语义标注；实际 `useBagItem` 在斧头分支直接 `return`，**永不消耗数量**。

## 已知边界
- 「障碍物」= 当前碰撞网格里 `blocked=1` 的格子（墙/水/树/栅栏等）。没有独立的「可破坏对象」元数据，所以**一切 blocked 格都能被劈开**；如需限定只有特定物件可破，要额外给地图对象打 destructible 标签（本期未做）。
- 每次点击只劈 1 格（1 米宽），可连续点击拓宽缺口。

# 斧头拾取刷新
[mulberryForest.json](../../../../map_design/base/maps/mulberryForest.json)
tile [json](23,11)世界(-7,-9)  位置，每次进入mulberryForest 都会刷新一把斧头，靠近提示是否拾取，拾取后消失，物品栏斧头数量+1。

## 实现说明（2026-10-16）
- **地图对象**：`mulberryForest.json` Actors 层新增对象 `id:901 name:斧头 type:pickup`，像素坐标 `x:736, y:352`（= tile 23×32 / 11×32；编辑器世界 -7,-9，运行时 `normalizeTiledMap` 按统一 -1 偏移算作 -7,-10，与其它对象一致）。属性：`entity_type=NPC`、`full_name=斧头`、`name=斧头`、`pickup_item=斧头`。
- **解析**：`mapConfig.ts` 的 `MapNpc` 新增 `pickupItem?: string`；`normalizeTiledMap` NPC 分支读 `props.pickup_item` 写入 `npcs[].pickupItem`。
- **实体**：`App.vue injectMapNpcsToState` 给实体补 `pickupItem` 字段（随 `mapnpc_901` 生成，side=neutral，坐标取对象位置）。
- **绘制**：`drawEntity` 命中 `pickupItem` 时走 `drawPickupAxe`（自定义地面斧头图标 + 脉动光环 + 「🪓 斧头」标签，与 `drawQuestBoard` 同风格；图集无斧头贴图，故纯手绘）。
- **靠近提示**：`updateNearPickup()`（半径 2.5m，10Hz）设 `nearPickup`；模板出 `ev-confirm` 风格的「🪓 是否拾取斧头？[稍后][拾取]」弹窗。`updateNearChat` 已跳过 `pickupItem` 实体（不会误弹「💬 聊天」）。
- **拾取**：点「拾取」→ `onPickupConfirm` 调 `evGiveItem("斧头",1)`（→ `sendTick("sys_item_add")`，mockHost/entry 均已实现，`斧头` 命中 `AXE_RE=/斧/` 直接驱动斧头破坏模式）+ 实体 `alive=false`（画面立即消失）。
- **刷新**：`switchLevel` 切图会清掉旧图全部 `mapnpc_*`，重进 mulberryForest 时 `injectMapNpcsToState` 从 `cfg.npcs` 重新注入 `mapnpc_901`（alive=true）→ **每次进入都会刷新**。同一张图内拾取后不再出现（`alive=false` + `updateNearPickup` 跳过死亡实体 + `onHostState` 回补过滤 `alive!==false`）。
- **同步副本**：`vue/public/maps/mulberryForest.json`、`ui/maps/mulberryForest.json`、`ui/game.html`，以及两处已安装副本 `toonflow-game-app/Toonflow-game/plugins/1/` 与 `toonflow-app-run-db/plugins/1/` 的 `ui/`。**需重启后端进程**才在浏览器生效。
