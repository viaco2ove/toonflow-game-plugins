# 击杀野怪-奖励
## 有一定几率掉落宝箱在地上。用户走进可以打开。打开后可以获得各种物资
## 物资中有一定几率获得暗核
## 使用暗核可以获得经验和有一定记录获得技能（触发ai 判断获得什么技能，程序判断是否重复技能如果是则升级技能）

## 1. 触发链（已实现）

```
击杀野怪（damage() 敌人 hp<=0）
   └─ 35% → 尸体坐标生成宝箱（Chest.loot = {exp, money, item}）
玩家走近 2m（CHEST_PICKUP_M）
   └─ 自动开启 → +exp / +money / 物资进背包（★原本只进 s.drops 日志，暗核点不到「使用」）
玩家点背包里的「暗核」→ sys_use_item
   └─ +40 经验 → 50% 骰子命中 → 问 AI「获得什么技能」
        └─ 已拥有该技能 → 升级 lv+1（威力 ×1.25）；没有 → 新增一格
```

| 环节 | 落点 | 文件 |
|------|------|------|
| 掉宝箱 | `dropKillChest(s, target)`（尸体周边散射 + `bornTick` 保护期） | `entry.ts` / `entry.js` |
| 开箱入包 | tick 内宝箱分支（`CHEST_GRACE_TICKS` 守卫）+ `addBagItemToCard()` | `entry.ts` |
| 暗核判定 | `isCoreItem(s, it)` | `entry.ts` |
| 暗核吸收益处 | `useBagItem()` 的 core 分支 | `entry.ts` |
| AI 判技能 + 重复升级 | `grantCoreSkill(s, ctx)`（async，走 `task-speaker-agent`） | `entry.ts` |
| 技能池下发 | `case "sys_skill_pool"` | `entry.ts` |

### ⚠️ 为什么不写成 `events/maps/*.events.json` 里的事件行

事件引擎只有 3 个挂载点：`enter_map` / `interact` / `area_enter`
（`eventEngine.ts` 的 `onMapEntered` / `onInteract` / `tickZones→onAreaEnter`）。
**`kill_count` 写了永不触发** → 击杀奖励必须落在插件的伤害/击杀链路里，不能写成事件行。
地图集能参与的只有「数据」：掉落表、技能池（见 §2/§4）。

## 2. 数据字段（全部可配，没有把本剧名字硬编码进插件）

| 数据 | 来源 | 说明 |
|------|------|------|
| 掉落表 | 地图 `enemy_archetypes[].dropTable`（`{name,w}[]`）→ 实体 `dropTable` | 优先级最高，BOSS 可只掉暗核 |
| 掉落表 | `s.dropTable`（全局） | 次优先 |
| 掉落表 | `DEFAULT_DROP_TABLE` | 兜底：干粮26 / 荧光石18 / 兽骨16 / 野兽皮14 / 锋利的爪12 / **暗核14** |
| 技能池 | `s.skillPool`（action `sys_skill_pool` 下发） | 有池 → AI 只从池里挑；**无池 → AI 按故事自由生成** |
| 核类物品 | `itemMeta[name].grant === "skill"` 或 `.core === true` | 数据驱动优先 |
| 核类物品 | 名字命中 `CORE_ITEM_RE = /暗核\|湮核\|源核\|核晶\|兽核/` | 兜底 |

### 概率 / 数值常量

| 常量 | 值 | 含义 |
|------|----|----|
| `KILL_DROP_CHEST_P` | 0.35 | 击杀掉宝箱概率 |
| `CHEST_PICKUP_M` | 2 | 走近多少米自动开箱 |
| `CHEST_GRACE_TICKS` | 12 | ★ 击杀掉落宝箱的开启保护期（100ms/拍 → 1.2s 内不许自动开，先让玩家**看见**它落在地上） |
| 掉落落点 | 尸体周边 0.7–1.7m 随机散射 | ★ 不再与尸体坐标重合（否则近战击杀时下一拍就被自己踩开） |
| 暗核权重 | 14 / 100 | 开箱物资里出暗核的比例 ≈ 14% |
| `CORE_USE_EXP` | 40 | 使用一个核类物品给的经验 |
| `CORE_SKILL_P` | 0.5 | 触发 AI 判技能的概率 |
| `CORE_AGENT_TIMEOUT_MS` | 20000 | 问 AI 的超时，超时走兜底不卡玩家 |
| `CORE_FALLBACK_SKILLS` | 碎石击 / 疾风步 / 回气术 | AI 完全不可用时的兜底 |
| 宝箱 loot | exp = 赏金×0.5，money = 赏金×0.5 | 赏金来自 archetype `bounty` |

## 3. AI 判技能的实现口径

- 走 **`task-speaker-agent`**（后端已注册，插件唯一可用的通用大模型通道），
  persona 设为「湮源」，`context.storyDigest` 带上故事摘要 → 输出贴合本剧。
- **有 `skillPool`**：提示词只要求输出一个技能名；插件做「池内包含匹配」，
  池外名字一律拒绝 → 回退随机（保证故事一致性）。
- **无 `skillPool`**：提示词要求输出 JSON
  `{"name","power","cost","cd","type","range","effects_type","desc"}`，
  插件做字段收敛：`name ≤12 字` / `type ∈ atk|heal|buff` / `range ∈ melee|ranged` /
  `effects_type` 进合法枚举 / `buff_type ∈ Defense|Attack|Sustained_Damage|Stunning|Invincible|Accelerate`。
- **重复技能判定**：`skillKey()` 归一化后比对，命中已拥有技能 → **不新增格位**，改为
  `lv+1`、威力 ×1.25，参数卡写 `湮蚀爆发（lv2）`；`skillMeta` 同步覆盖。
- 写入：`skillMeta[<去括号小写名>]` + 参数卡 `skills` 数组，`patchCard` 自动重建快捷栏。
- 失败/超时全部有兜底，**不会卡住玩家**。

## 7. 排障：为什么「把整张图的野怪杀光也不见地上有宝箱」

> 用户实测反馈：*「我把一整个地图的野怪杀了也没看见地上有宝箱。」*
> 追查后确认是 **4 个独立 bug 叠加**——链路本身是对的，但 3 个把它整条吃掉了、1 个让它永远不生效。

### 7.1 后端进程里跑的是旧模块（**这是「完全没反应」的主因**）

真实后端 `toonflow-game-app/src/app.ts`（Express，端口 60002）用 `tsx` 启动，插件 `entry.js`
由 `PluginExecutor.ts` 动态 `import()` 加载。当时的「mtime 失效」逻辑只清了内存里的
`entryModuleCache` map，**再 import 的还是同一个 `file:///…/entry.js` URL** ——
Node 的 ESM 模块登记表按解析后的 URL 缓存，同一 URL 永远返回**首次求值**的那个模块对象。

实测（`probe3.mjs` 最小复现）：

```
写 V1 → import → 拿到 V1
改文件为 V2 → 同 URL import → 仍是 V1   ❌
```

更糟的是本工程跑在 **tsx** 下，tsx 的 load hook 会把 query 剥掉，
连标准的 `import(url + "?t=" + mtime)` 缓存击穿都失效（`?t=1` / `?t=2` 返回同一个对象）。

**后果**：插件新功能（野怪击杀掉宝箱）虽然已经 esbuild 进 `entry.js`，
但后端进程里跑的还是启动那一刻的旧代码 → 击杀根本不掉宝箱。
DB 实证：最后一条 `plugin_state` 里 `chests = 3`（只有地图自带的 `chest_map_0/1/2`）、
`chest_kill_* = 0`、`kills = 0` → 后端**从未执行过**击杀奖励代码。

**修复**：`PluginExecutor.ts` 新增 `importEntryModule()` —— 把自包含的 `entry.js`
复制到 `os.tmpdir()/toonflow-plugin-entry/<pluginKey>.<mtimeMs>.mjs` 再 import，
URL 天然不同 → tsx 与原生 Node 都会真正重新求值。
（`entry.js` 若含 `import` / `import.meta` 则无法影子加载，此时打印告警并退回直接 import。）

### 7.2 宝箱掉在玩家脚底下（**就算生效了也「看不见」**）

`dropKillChest()` 原本把宝箱放在**尸体坐标**上。近战击杀时玩家就贴在尸体旁
（距离 < `CHEST_PICKUP_M = 2`），于是**下一拍（100ms 后）的「走近自动开箱」立刻把它吃掉** ——
宝箱确实存在过，但 `opened` 在它出现的那一帧就是 `true`，玩家**永远看不到**。

E2E 铁证（修复前）：`chest_kill_132_3 … "opened":true`、`chest_kill_169_4 … "opened":true`。

**修复**：落点改为尸体周边 **0.7–1.7m 随机散射** + 新增 `CHEST_GRACE_TICKS = 12`（1.2s 保护期），
保护期内即使站在箱子上也不开 → 玩家先看到它落地。
修复后同一 E2E：3 个击杀宝箱里 2 个保持 `opened: false`。

### 7.3 `dropTable` 在「前端权威」这条路上被静默丢弃

地图配置的 `enemy_archetypes[].dropTable`（「这张图的怪掉什么」的权威配置）经
`localEnemiesPayload` → 后端 `applyLocalEnemies()` 重建实体，而 `applyLocalEnemies()`
**只复制了 `bounty`，没复制 `dropTable`** → 地图掉落表永远到不了掉落逻辑，
只能吃全局 `DEFAULT_DROP_TABLE`。

**修复**：`applyLocalEnemies()` 一起透传 `dropTable`；
`mapConfig.ts` 解析 Tiled 属性 `bounty` / `dropTable`（兼容 `drops`）；
`App.vue` mob 实体创建时转发。前端 `mockHost.ts` 补上同样的掉落/开箱逻辑（此前**完全没有**）。

### 7.4 附带修掉：同一具尸体被反复结算

`damage()` 的击杀分支条件是 `target.hp <= 0 && target.alive`，而 400ms 死亡淡出期
**故意保持 `alive === true`** → 淡出期内再打这具尸体，条件再次成立 → 击杀计数/经验/金钱/掉落宝箱
**被重复结算**（实测打 3 下 → `kills 1 → 4`）。

**修复**：加 `!(target as any).deathMs` 守卫。修复后 `kills 1 → 1`。

### 7.5 落地验证

- `.cache/test_kill_chest_chain.mjs`：全图清怪 → `chest_kill_*` 出现 → 走近 → `opened`。**PASS 5/0**
- `tmp/e2e_kill_chest.cjs`（真 dev-host）：`chests 3 → 6`（击杀掉落 3 个），走近 `opened = true`。**PASS**

### ⚠️ 需要做一次的事

修复后的 `PluginExecutor.ts`（影子加载）**必须重启后端一次**才会被加载；
此后 entry 改动即可热重载、不用再重启。已装好的 `entry.js` / `ui/game.html` 会随重启自动生效。
