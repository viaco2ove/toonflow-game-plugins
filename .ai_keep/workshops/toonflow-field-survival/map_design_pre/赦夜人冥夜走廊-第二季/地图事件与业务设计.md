## 1. 设计目标

把 chapter 85「黑夜」的 6 个 phase 全部**数据化**：

1. **零代码改 game**：剧情 / 战斗节奏 / 数值推进全靠 JSON + TS 脚本
2. **flag 唯一来源**：玩家卡（`t_plugin_session_data`），story.json 不存 flag
3. **AI 可写**：写 JSON / TS 经 `validate_events.mjs` 校验即可上线
4. **与通天传授同构**：events/ 目录结构、ctx API、白名单表完全复用
5. **AI 托管可读**：每个采集 zone 用 `trigger.ai.gather` 显式声明，供 `mapKnowledge` 派生

### 1.1 两条硬约束（实现时确认，写事件前必须知道）

1. **引擎只实现了 3 种 trigger**：`enter_map` / `interact` / `area_enter`。
   `kill_count` / `turn_count` / `step_on` / `flag_set` / `custom` 在 `eventEngine.ts` 里
   没有对应挂载点 → **写了也不会触发，是死事件**。所有节奏必须落到「进图 / 交互 / 进区域」上。
2. **运行时读的是 `plugins/.../vue/src/eventScripts/`**，不是 `workshops/.../events/scripts/`
   （`import.meta.glob("./eventScripts/*.ts")` 构建期内联）。两个故事共用这一个目录，
   所以本剧脚本统一加 **`SY_` 前缀**，避免与通天传授的 `E01_bind_system` 撞名。
   用 `.cache/sync_sheye_event_scripts.py` 同步（顺带把 `../shared/_ctx` 改写成 `./_ctx`）。

### 4.1 eventZones（写在地图 JSON 顶层）

坐标沿用 Tiled 瓦片坐标，`x/y` 为中心、`rx/ry` 为半径（App.vue 换算成米）。

```json
{
  "name": "桑镇",
  "theme": "城镇·深夜",
  "narration": "夜色压在桑镇的屋檐上，药铺的灯还亮着。",
  "eventZones": [
    { "name": "夜采药圃",   "x": 4,  "y": 27, "rx": 6, "ry": 8 },
    { "name": "药铺",       "x": 13, "y": 32, "rx": 3, "ry": 3 },
    { "name": "镇口",       "x": 20, "y": 30, "rx": 5, "ry": 5 },
    { "name": "暮光布道点", "x": 6,  "y": 15, "rx": 4, "ry": 4 },
    { "name": "木材堆",     "x": 16, "y": 52, "rx": 4, "ry": 2 }
  ]
}
```

> ⚠️ `夜采药圃` 是本剧 phase_1 的核心采集点，必须在 `events/maps/mulberryTown.events.json` 里用 `trigger.ai.gather = "herb"` 显式声明，否则 AI 大脑不知道本图能采药。

## 10. 与 AI 托管的接口（重要）

本剧必须满足 `vue/src/ai/mapKnowledge.ts` 的派生要求：

1. **采集点显式声明**：每个可采集 zone 的 `area_enter` 事件必须带 `trigger.ai.gather`（`herb`/`fish`/`wood`/`ore`/`other`）
