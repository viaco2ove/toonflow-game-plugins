## 点击地面寻路导致世界冻结（toonflow-field-survival）——根因已实证
- 现象（用户报告，localhost:3000 一直存在）：点击地面移动时整个画面有冻结感，野怪不动、技能特效不消失；停下后世界"突然变活"。方向键/摇杆移动无此问题。
- 根因：`input` 是 `ref({dx,dy,moveTo})`，`input.value.moveTo` 返回的是 **Vue 响应式 Proxy**；`window.parent.postMessage` 走结构化克隆，**Proxy 不可克隆 → DataCloneError**（已用工程自带 vue 在 node 里实证）。旧 `sendTick` 把 postMessage 包在 try/catch 里只 warn → 整条 tick 被静默丢弃。moveTo 是点击寻路期间**唯一**非空、方向键期间为 null 的载荷字段，故只有点击寻路触发。
- 宿主侧后果链（dev-host，vite.config.ts 里的 PAGE）：服务器 AI 循环每 100ms 消费 `window._devHostPending`（只有 tick 到达才会更新）。tick 全丢 → 宿主眼里的玩家位姿冻结 → 野怪追"幽灵坐标"并在 4m 内停住（看起来像全冻）；停下时 moveTo 归 null，tick 恢复 → 一切瞬间复活。
- 修复：
  - `App.vue` tick 载荷：`moveTo` 显式构造纯对象 `{x,y}`，不再传 Proxy。
  - `App.vue` localEnemiesPayload：`{...e}` 浅拷贝会把嵌套 bounty/_aiBag/buffs 留成 Proxy（同类 bug），改 `toCloneable()` 深拷贝。
  - `bridge.ts` 新增 `toCloneable()` + `postSafely()`：投递统一入口，clone 失败自动深拷贝重发一次，此类问题不会再静默吞 tick。
- 实证（浏览器 A/B，http://localhost:3000/ dev-host + agent-browser）：
  - 注入 bug：持续点击地面期间 tick 投递 131→132→134→137（15s 内 ≈0.3/s），hostTick 259→265，野怪 5s 只挪 0.3m。
  - 修复后：同期 tick 131→358（≈15/s），其中 221 条携带 moveTo，hostTick 259→486，野怪持续追玩家。
  - 结论：tick 投递差 ~40 倍，冻结现象与根因一一对应。
