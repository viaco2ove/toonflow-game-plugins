## 三条铁律（每次改代码前默念）

1. **entry.js 是编译产物，不上传 git，不许手改**
   只改 `entry.ts` → esbuild 编译 → 同步安装副本。
   （详见 [entry.js 关系说明](插件补充/entry.js和entry.ts%20的关系和说明(2026-10-07).md)）

2. **插件状态的权威是内存态，DB 只是快照**
   写操作走 `PluginStateExecutor.executePluginActionWithState()`，
   不要另写一套「读 DB → 调 entry → 写 DB」。
   （详见 [数据储存](插件补充/数据储存.t_plugin_session_data.md) §内存态）

3. **本地开发必须用 `npm run local`**
   `env/.env.local` 才是正确的 DB/上传目录；裸 `npx tsx src/app.ts` 会走 `env/.env.dev`（路径为空）导致插件加载失败。

## 快速上手（改一个插件后端逻辑）

```bash
# 1. 只改 entry.ts（唯一源码）
#    plugins/<plugin>/entry.ts

# 2. 编译 + 同步安装副本（后端按 mtime 自动热加载，无需重启）
cd plugins/<plugin>
npx esbuild entry.ts --bundle --format=esm --platform=node --target=node18 --outfile=entry.js
cp entry.js "D:/Users/viaco/tools/Toonflow-game/toonflow-app-run-db/plugins/1/<manifest.id>/entry.js"

# 3. 跑回归
PYTHONIOENCODING=utf-8 python -I .cache/immediate-interaction-tests/test_regression.py
```

> 安装副本路径里的 `<manifest.id>` 是 **manifest.json 的 id**（如 `com.toonflow.minigame-field-survival`），
> **不是文件夹名** —— 这是最常见的「改了不生效」原因。
