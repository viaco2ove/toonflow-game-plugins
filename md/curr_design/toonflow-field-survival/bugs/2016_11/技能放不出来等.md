## ① 切换技能组（下一页）——实测正常

技能共 8 格（6 真技能 + 2 占位），一页 4 格 → 共 2 页。

实测：UI 点「切换 2/2」，技能槽从「源之力/暗核共鸣/宿主/暗核瞬击」变为「暗核已归位/源脉/空技能格×2」；
后端 `skillPage` 250ms 内 0→1，前后端一致。

链路：前端 `pageSkill(d)` → `sendTick("page", {kind:"skill", delta:d})` → entry.ts `case "page"` 按
`skillPage = (skillPage + delta) % pages` 取模翻页 → `clampQuickbarPages` 夹紧。

**判定：功能正常。** 用户感知「有问题」多半是因为第 2 页有两个「空技能格」占位（置灰不可点），看起来像坏了。

## ② 释放技能——链路正常，「空放」是设计行为

实测证据（后端权威态 `/plugin/tick` 直探）：

- 施放后返回 `'源之力'`，事件写「施放 源之力，命中 2 个目标」；
- 命中的哥布林 hp **28 → 16**；
- 冷却 `cdLeft=24`（cd=24），按真实时间衰减（48→32→12→0 ≈ 4.8 秒），UI 按 `cdLeft/10` 显示秒。

「释放没反应」的原因：当时玩家在**桑镇**，附近没有任何敌人 → `case "skill"` 命中判定
（`inAttackRange`，近战 2m / 远程 4m）找不到目标 → 返回 `'源之力（空放）'`，只有特效没有伤害。
这是设计行为（空放：特效/CD 照常，只是无伤害结算）。

**判定：链路无 bug。** 必须在有怪的地图（桑林/乱葬岗/地牢）贴近怪（≤ 射程）才有命中。

## ③ 去打野怪——两层问题

### 3.1 城镇显示「无野怪」是正确的

故事地图 `map_design/赦夜人冥夜走廊-第二季/maps/mulberryTown.json`：敌怪 0、NPC 31，
与控制台 `npc=31 mobs=0` 完全吻合。野怪分布：桑林 22、乱葬岗 20、冥夜走廊各层 8~18。
HUD 的「🐾 无野怪」只数 `mapCfg.mobs` 里 `camp=hostile` 的，城镇没有 → 显示正确。

**所以「去打野怪」的前提是先离开城镇——而这正好踩中下面的传送 bug。**

### 3.2 真 bug：跨图传送前后端 desync（teleportTarget 竞态）

**现象**：地图面板点「传送→桑林」后，后端已切图（`levelName=mulberryForest`、事件写
「传送至 mulberryForest」、实体被 `handleLevelChange` 清空重建），**前端却仍停在桑镇**
（HUD「当前：桑镇」、🐾 无野怪）→ 玩家永远到不了有怪的地图。

**根因**：`teleportTarget` 是「一次性通道」，清除写在帧 tick 的第一行：

```ts
// entry.ts case "tick" 首行（修复前）
if ((s as any).teleportTarget) (s as any).teleportTarget = null;
```

而 `sys_travel` 走**慢锁**（withSlowLock）、帧 tick 走**快锁**（withSessionLock）——
两把锁互不排斥，却改**同一份 state 对象**。时序：

1. `sys_travel` 设 `s.teleportTarget = {...}`
2. 下一拍 10Hz driver tick（PluginRealtimeHub.driverTickOnce）插进来，**第一行**就把它清成 null
3. 该拍 WS push 给前端的 state 里已无 teleportTarget
4. 前端 `watch(() => state.value?.teleportTarget)`（App.vue）永远收不到 → 永不 switchLevel

实测：连续 4 次 `sys_travel`，`teleportTarget` 有 2 次直接是 null。

**修复**（entry.ts，提交 14cbd5d）：把「一拍即焚」改成「保活 3s 后才清」——

- 新增 `issueTeleport(s, tp)`：所有签发点（`sys_travel` / `sys_teleport` / `start`）统一走它，
  把签发时刻 `issuedAt` **存在目标对象内部**（不放 state 顶层独立字段——否则 tick 读 tp 与
  读 issuedAt 之间被并发换目标，会用旧时刻误判新目标）；
- 新增 `clearExpiredTeleport(s)`：帧 tick 只清除 `Date.now() - issuedAt >= TELEPORT_KEEP_MS(3000)`
  的目标；新签发的至少活 3 秒（十几拍），保证前端 watch 必然消费到；
- 不会「被绑住」：前端 watch 消费后自行置 null，且用 `rev` 去重（同一 rev 只传送一次）；
  3s 过期后由 tick 自动清掉（实测 2.4s 后变 null）。

**验证**：真机点「桑林 传送」→ 前端「当前：桑林」与后端 `mulberryForest` 一致，HUD「🐾 16只 Lv.1-10」；
连续 4 次 sys_travel `teleportTarget` 4/4 带 rev（修复前 2/4 为 null）。

## 附带发现的严重 bug：persistSys 空值覆盖，把玩家数据清空

排查上述问题时发现（2026-11-17）：UI 上「实体形象的 AI 生成图」变成「我的生成 (0)」、
技能的「属性特效绑定」配置全部丢失。

**现场证据**（sqlite-web 直查远端 `/data/toonflow/db.sqlite` 的 `t_plugin_session_data`）：
本会话 `sys_state` 里 `spriteGallery=[]`、`spriteBinds={}`、`skillMeta={}`、`itemMeta={}`，
连带 `player_card` 里每个物品的 `effects_type` 全是 `""`；而另一会话的存档里 spriteGallery
（292KB，2 张 AI 生成图）与 spriteBinds（123KB）完好。

**根因**：`persistSys` 是**全量覆盖写**（`api.set(SYS_DATA_KEY, {...})` 直接盖上去），而帧 tick
每 20 拍无条件调一次（`SYS_PERSIST_EVERY_TICKS = 20`）。只要某一拍内存态里某字段是空的
（开局重建、restoreSys 未跑到、状态被 start/select 重置等），那一拍就把 DB 里已存好的真数据
覆盖成空。宿主侧 `setPluginData` 是 `onConflict.merge({dataValue})` 整值覆盖，不做字段合并，
所以防线只能在插件侧。

**修复**（entry.ts，提交 2567d4a）：`persistSys` 改为**读-改-写**：

1. 写入前先 `api.get(SYS_DATA_KEY)` 读回 DB 旧值；
2. 对 `spriteGallery / spriteBinds / skillMeta / itemMeta / bagMeta / bagOrder / skillOrder / npcCards`
   八个字段：内存态为空 → **保留 DB 旧值**（`keepIfEmpty`）；内存态有值 → 用内存态；
3. 用户**主动删除**（删图库最后一张 `sys_sprite_gallery_del` / 解绑 `sys_sprite_unbind`）时，
   先置 `(s as any)._sysForceEmpty = ["spriteGallery","spriteBinds"]` 显式声明「本次允许写空」，
   否则删除会被旧值顶回来（解绑无效）。

**验证**：在真实帧 tick 环境（10Hz，3 秒 31 拍）往 DB 种入哨兵
（`skillMeta.源之力.effects_type="SENTINEL_FIRE"` + `spriteGallery[0].id="sp_sentinel"`，
后者内存态必空、只可能来自 DB），让 tick 跑 15 秒多次触发 persistSys → 两个哨兵均存活；
修复前同一场景必被写空。另验证 `sys_skill_edit` 正常路径写回的 skillMeta 含全部字段
（power/cost/cd/type/range/lv/buff_type/effects_type/attack_shape）→ 属性特效绑定机制本身是好的。

**注**：本会话已被覆盖清空的数据无法从库内恢复（备份会话属于另一个故事「黑塔」，角色对不上），
需要在插件面板重新生成实体形象、重配技能/物品属性特效绑定。修复保证以后不再丢。

## 排查手段备查（远端跨域 iframe 场景）

- iframe 跨域读不到 `__FS_DEBUG__` → 从 iframe src 提取 JWT，直探后端：
  `POST /plugin/tick {sessionId, pluginId, action, params}`（内存态权威）；
  读热态用 `action:"page", params:{kind:"skill",delta:0}`（delta=0 只读不改页码）；
  `POST /plugin/data op:"get"` 是 DB 快照（O2 2s 节流，会滞后）。
- 远端 `login` 返回的 token 无效（401），**能用的是 iframe src 里带的 token**。
- 插件部署走 `POST /plugin/install-raw`（原始 zip 流 + `X-Plugin-File-Name` 头），
  `POST /plugin/install`（base64）12MB 包会超时；打包要排除 `node_modules / test_data / test-host`。
- 改 `entry.ts` 后必须 `npx esbuild entry.ts --bundle --format=esm --platform=node --target=node18 --outfile=entry.js`，
  并重装插件（install-raw 会触发 esbuild 现编 + 清 entryModuleCache）。
- ⚠️ 不要用后端 API 直接 `tick start` 代替点 UI 开局——内存态残缺 + persistSys 覆盖写正是本次
  数据清空的触发方式（修复后已有 keepIfEmpty 防线，但仍建议走正常 UI 路径）。
