# 为何插件安装后野怪不攻击?

## 问题现象（2026-10-07 实测）

插件安装后（5175 宿主 → iframe 加载 60002 `/plugin/getAsset` 的 game.html），进入 mulberryForest 关卡后：

- 画面上 11 只野怪全部站立不动，玩家走到它们身边也不追击、不攻击
- 玩家 HP 永远满血，无伤害飘字
- UI 显示"当前关卡敌怪已接入宿主 AI（11 只）"（首次接入时有这条 event），但 AI 实际不推进
- 普攻/技能也无从谈起（目标都不会动）

## 排查过程（逐层定位）

野怪距离判断**在后端**（entry.js `step()`，entry.ts:1405-1454）：

- `dist(e, prey) <= MOB_DETECT_M(4m)` → `aiState="chase"` 追击
- `<= MOB_ATK_M(4m)` → `damage()` 攻击玩家
- `> MOB_DISENGAGE_M(4m)` → 脱战归位 / 巢点 8m 内游荡

前端只负责渲染后端回推的实体位置。因此"野怪不动"= 后端 step() 的 `enemies.forEach` 在空跑。

逐层验证手段与结果：

| 层 | 验证方法 | 结果 |
|---|---|---|
| 前端每帧 tick | 宿主页面 hook XMLHttpRequest 统计 `/plugin/tick` | ✅ 8 秒 81 次，body 带 `localEnemies(11只)+player+levelName` |
| 宿主转发 | 同上（axios 走 XHR） | ✅ |
| 后端 tick 推进 | 读 sqlite `toonflow-app-run-db/db.sqlite` → `t_plugin_session_data`（key=`plugin_state`）的 tick 字段 | ✅ tick 以 10Hz 自增 |
| **后端敌怪表** | 同上，数 `entities` 里 `side==='enemy'` | ❌ **恒为 0** |
| AI 距离判断 | 手动 POST `/plugin/tick` 带新 `localEnemies.epoch`+2 只测试怪 | ✅ 立刻建怪、进入 chase、正常移动——AI 代码本身没毛病 |

### 决定性证据

后端 state 里 `localMobsEpoch = 2`（与前端上报的 epoch 相同），但 `entities` 里 0 只敌人：

```json
{"tick": 4668, "localMobsEpoch": 2, "enemies": 0, "events": 2}
```

且前端每帧仍在发 `epoch=2, listLen=11` ——后端 `applyLocalEnemies` 的世代判断：

```ts
// entry.ts 修复前
if (epoch > 0 && num(s.localMobsEpoch, 0) === epoch) return 0;   // 该世代已接管，忽略回推
```

epoch 相同一律 `return 0` 不重建。敌怪表"标记在、实体无"，**死锁为空**。

## 根因

`localMobsEpoch` 标记与敌怪实体**生命周期不同步**：

1. 开局在 Town，前端发 epoch=1（Town 空清单）→ 后端记 epoch=1、建 0 只
2. 走路穿传送门切到 Forest，前端 epoch=2（11 只）→ 后端重建 11 只（events:"当前关卡敌怪已接入宿主 AI（11 只）"）
3. **某个路径把 entities 清空但保留了 localMobsEpoch 标记**（start 重跑 / restoreSys 从库恢复 epoch 字段 / handleLevelChange 等）。实测还观察到 state 整体回退（tick 变小、events 被重置）——说明 start/restore 链路确实重入过
4. 此后前端永远发同一 epoch=2 → 后端永远"已接管，忽略" → **敌人永远 0，AI 永远空跑**

一句话：**"已接管"判断只看 epoch 标记，不看敌怪实体是否真的存在**。

## 修复（entry.ts，fix⑦）

两处改动，双保险：

### 1. `applyLocalEnemies`：epoch 相同时校验实体是否还在

```ts
// entry.ts
if (epoch > 0 && num(s.localMobsEpoch, 0) === epoch) {
  // ★ fix⑦：该世代"已接管"的前提是本地怪实体还在。
  //   start 重建 / restoreSys 恢复 / handleLevelChange 等路径会清空 entities 却保留
  //   localMobsEpoch 标记 → 此后前端永远发同一 epoch，后端永远 return 0 →
  //   敌怪表死锁为空、AI 空跑。
  //   怪还在 → 正常忽略回推；怪丢了 → fallthrough 幂等重建（下面先清残留再建）。
  const alive = s.entities.filter((e) => e.side === "enemy" && isLocalEnemyId(e.id)).length;
  if (alive > 0) return 0;
}
```

### 2. `start` 分支：清空实体时同步清 epoch 标记

```ts
// entry.ts start case
s.entities = [];
// ★ fix⑦：新开局清空实体后必须同时清 localMobsEpoch——restoreSys 会把上局的
//   epoch 一并恢复，若不清，前端继续发同一 epoch 会被 applyLocalEnemies 当作
//   "已接管"忽略 → 敌怪表死锁为空（配合 fix⑦ 的丢失重建兜底，双保险）。
s.localMobsEpoch = 0;
```

### 部署步骤（缺一不可）

1. **重编译**：`npx esbuild entry.ts --outfile=entry.js`（vite/后端加载的是 entry.js 不是 entry.ts）
2. **部署到安装副本**：60002 后端跑的是 `toonflow-app-run-db/plugins/<userId>/com.toonflow.minigame-field-survival/` 下的 entry.js（不是插件仓库），把 entry.js + entry.ts 拷过去
3. **重启 60002 后端**：PluginExecutor 有 `entryModuleCache`（按 pluginDir 缓存模块），不重启拿不到新代码
4. 刷新 5175 页面重进游戏

### 修复后验证

- 新开局 DB 里 `entities` 敌人数：0 → **11** ✅
- 玩家点击地面走近野怪 → 野怪 `aiState: idle → chase`（4 米探测圈触发）✅
- chase 怪贴脸 0.4-1.0 米 → 玩家 HP 340 → 0，events 记录"陈彦 倒下了" ✅
- 玩家逃跑拉远 >4 米 → chase 怪脱战转 `return`/`idle` ✅

## 修复后遗留问题（本轮新发现，待办）

1. **复活血量观感异常**：events 记"你在原地复活（生命 340/340）"，但复活在怪堆里时瞬间又被打死，读到的 HP 常是 4-6。复活点=死亡点，周围有 chase 怪时会陷入"复活→秒死"循环。建议：复活时把周围 chase 怪推离（或给 2-3 秒无敌）。
2. **玩家自动普攻未验证**：atk=250、怪贴脸 0.9m，但 floaters 只有野怪打玩家的 -13，没有玩家打怪的伤害数字。待在安全环境（单只 idle 怪、满血状态）单独验证普攻与技能（castSkill）链路。
3. **3 只 chase 哥布林一度从 entities 消失**（epoch 未变、无重建日志）——另一条清怪路径，未定位。fix⑦ 的"丢失重建"兜底会在下一帧把它救回来，但源头值得查。

## 测试工具备忘（bsk 实测 5175）

- **只开一个 agent tab**：多 tab（3000 dev-host + 5175）会导致 evaluate/observe/截图落在不同 tab，数据全是错位的
- **读后端 state**：sqlite `toonflow-app-run-db/db.sqlite` → `t_plugin_session_data`（sessionId 见宿主会话，key=`plugin_state`），每 tick 都写，是**最可靠的判定日志**
- **控制玩家移动**：canvas 点击寻路。canvas 无 a11y ref，用"注入透明定位 div + click --selector"法：
  ```js
  // 宿主页面 evaluate 注入（pointer-events:none 不拦截事件，CDP click 按坐标命中 canvas）
  var d = document.createElement('div');
  d.id = '__ct';
  d.style.cssText = 'position:fixed;left:Xpx;top:Ypx;width:4px;height:4px;pointer-events:none;z-index:2147483647;';
  document.body.appendChild(d);
  ```
  然后 `bsk click --selector "#__ct"`。**注意坐标系**：screenshot PNG 是 DPR 缩放的（实测 1321×905 vs CSS 1056×724，系数 ≈0.8），点击坐标要按 CSS 像素换算，且 y 不得超出 iframe 实际高度（724），否则报 "element not visible"
- **WASD 键盘**：`bsk press --ref @eN --hold-ms 2000 w`（@eN 是 iframe 内 HUD 按钮，focus 后键盘路由进 iframe）。时灵时不灵（依赖 refs 新鲜度），鼠标点击更可靠
- **点怪身上**=走近+索敌；**点空地**=纯寻路
