| 需求（用户原话） | 设计落点 |

## 1. 数据模型（main-quests.json）

```jsonc
{
  "version": 1,
  "chains": [
    {
      "id": "MC1",                       // 链 id（MC=主线，MS=支线）
      "title": "消失的同桌",
      "chapter": "第一章",                // 显示用
      "desc": "……",                      // 一句话引入
      "giver": "任务板",
      "order": 1,                        // 「可选新主线」排序
      "lockedBy": [],                    // 需全部完成的链 id（空=开局可选）
      "nodes": [
        {
          "id": "MC1_1",
          "quest": { …完整 QuestDef… },  // id/title/type/objectives/reward/flags/timeLimitTicks/consume 与 quests.json 同构
          "onSuccess": ["MC1_2"],        // 成功后开放的节点（多个=分支抉择）
          "onFail": ["MC1_1F"],          // 失败后开放的节点；缺省=整链失败
          "failEndsChain": false          // true=失败即链终局（不可重试该节点）
        }
      ]
    }
  ]
}
```

- 节点 quest 会**注入委托系统**（复用 kill/gather/talk/arrive 全套进度钩子），但打上 `chain` 标记：**「可接」页签不显示主线任务**，只在主线页签显示。
- objectives 的目标全部指向已核实实体：
  - talk uid：妈妈=lichLair#10 · 苏晓=town#165 · 邻座同学=town#212 · 班主任=town#216 · 魏叔=town#225 · 小满=town#169 / forest#15 · 张晚意=graveyard#100 / taintedForest#600 · 老周=oldForest#600 / oldGraveyard#600 · 百晓生=lootGoblinLair#600 · 白子轩=town#311
  - kill target 写「伪人」——地图怪名 伪人·学生/精英/爪牙/宿主/教师 全部 includes 命中
  - arrive/explore 坐标沿用 quests.json 的既有口径（Q04 球场中央 26,10 已验证）

## 2. 节点状态机

```
locked ──(前驱 success/fail 且被选为下一步)→ selectable ──(玩家点「接受」)→ active
active ──(objectives 全达成 + 任务板提交)→ done
active ──(超时 / 玩家放弃)→ failed
done   ──后继节点全部入列──→ 链=awaiting_choice（onSuccess 多个）或下一节点 selectable（单个）
failed ──有 onFail──→ fail 节点 selectable；无 onFail──→ 链=failed（可「从头再来」重置整链）
暂停：active ⇄ paused（计时冻结；paused 显示 ⏸ 徽章，按钮只剩「继续」）
```

- **同一时刻每条链只有 1 个 active/paused 节点**——主线是「选择下一个」而不是「并行清单」。
- **放弃 = 失败**：主线页放弃按钮调 `sys_chain_abandon`（≠委托的 sys_quest_abandon），节点标 failed 并走 onFail。
- **重试**：链 failed 后提供「从头再来」，重置整链所有节点（已拿的奖励不回收——宽松设计，文档明示）。

### 2.1 分支语义（引擎硬规则，不可违反）

节点的 `onSuccess` 数量决定了走向，三种情况：

| onSuccess | 语义 | 引擎行为 |
|---|---|---|
| 1 个 | 线性推进 | 交付后该后继直接置 `selectable`，玩家回任务板点「接取」 |
| 多个 | **多分支抉择** | 交付后后继保持 `locked`，链状态置 `awaiting_choice`，主线页弹分支选择卡，玩家选一条（`sys_chain_choose`） |
| 空（0 个） | **终点** | 该节点是路径终点，交付后整链 `completed` |

**链完成判定 = 走完任意一条路径到终点**，而不是「done 节点数 == 全部节点数」。

> ⚠️ 这条是必须的：MC2 / MC4 / MC8 存在**二选一的平行分支**（MC2_2A 与 MC2_2B 是同层并列）。
> 若按「全部节点都完成」判链完成，玩家走完任一条分支后链永远卡在 `running`，MC3/MC5 也就永远不解锁。
> 同理，未走的那条平行分支保持 `locked`（在主线页显示为「未开启」），**不做任何惩罚**。

**失败分支（onFail）**同理：`onFail` 非空 → 失败后这些节点置 `selectable`（链继续，MC3/MC5/MC6 的失败线都汇回主线节点 MC*_2）；`onFail` 为空 → 整链 `failed`。

> ⚠️ 同样必须实现：不开启 onFail 分支的话，MC3_1 放弃后链就断了——玩家既不能重试也走不下去。

### 2.2 链状态取值

`locked`（前置未完成）→ `available`（已解锁未开始，任务板可接的新主线）→ `running`（有节点进行中）
→ `awaiting_choice`（待玩家选分支）→ `completed`（走完任一路径到终点）
分支：`failed`（终点失败且无 onFail）→ 「从头再来」重置回 `available`。

## 5. 引擎与故事包分工（铁律）

| 侧 | 职责 |
|---|---|
| 插件 entry.ts | 通用链引擎：StoryChain 类型、chainBoard/chainState、`sys_chain_pool/start/choose/turnin/pause/resume/abandon/retry`、buildChainView、链任务过滤出委托「可接」页 |
| 插件 QuestPanel.vue | 主线页签渲染 chainView（进度/轨迹/分支抉择/暂停继续/失败重试） |
| 故事包 main-quests.json | 全部黑塔业务：链、节点任务、分支、文案、奖励、flag |
| 故事包 events | 主线氛围演出不变（HT_E/HT_P 靠 phase flag），链任务的 flags.done 写同款 flag 与事件互通 |

主线节点 quest 的 `flags.done` 复用既有主线 flag（`phase_1_done` 等），**链完成即等于 phase 推进**，HT_E/HT_F 事件照常联动——两套系统共用一个 flag 源。

### 为什么要有生成器

不可能与数据脱节。改了 JSON 的分支（加一条 `onFail` / 改 `lockedBy`），重跑脚本图就跟着变。

### 图的约定

| 元素 | 含义 |
|---|---|
| 蓝框 | 链首节点（该章第一关） |
| 红框 | 失败分支节点（被别人的 `onFail` 指向：MC3_1F / MC5_1F / MC6_1F） |
| 绿框 | 终点节点（`onSuccess` 为空，走完即完成该章） |
| 黄框 | 支线（MS1/MS2，开局即可选，不推进 phase） |
| 实线 `-->` | 成功分支（`onSuccess`） |
| 虚线 `-.->` | 失败分支（`onFail`） |
| 粗线 `==>` | 章节间解锁（`lockedBy`，子图级） |
| 节点内 `🔓 解锁 X` | 该终点节点完成后解锁第 X 章 |

> **「任一路径都能解锁」怎么表达**：MC2 的两个终点 MC2_2A / MC2_2B 都能解锁 MC3。
> 解锁信息写在**终点节点的标签里**（两个节点都标 `🔓 解锁 三`），
> 章节间仍画子图级粗线。**不用节点级跨子图边** —— 那样 mermaid 会忽略子图的
> `direction`，图会退化成 9000+px 的竖条（见下方踩坑 3）。

### ⚠️ mermaid 踩坑记录（下次直接照抄）

1. **注释块必须放在 `flowchart` 声明之后，且 `%%` 注释行不能连续多行** ——
   mermaid 的注释剥离正则会把连续 `%%` 行连同换行一起吃掉，导致整份文件被当成一行，
   报 `Parse error on line 1: %%flowchart TD`。
2. **`end` 是保留字**，不能用作 `classDef` 名字（`classDef end` 会报语法错）——
   本图改用 `classDef finish`。
3. **子图内的 `direction` 在有跨子图边时会被忽略** ——
   想让「章节竖排、章节内横排」，不能靠节点级连线，得用 **子图到子图** 的边（`MC1 ==> MC2`）。
   否则会退化成 10000+px 的横条或竖条。
4. **支线区用 `~~~` 不可见边锚到主流程末尾**，否则它会飘到图的左上角。
5. **mermaid 里同一节点被多次 `class` 时后写的覆盖先写的** —— 保证每个节点只落一个类。
