# 地图集安装与加载

> 适用：`plugins/toonflow-field-survival/`
> 日期：2026-10-14
> 状态：✅ 已落地

## 1. 概念

**「地图集」** = 一个 Tiled 故事世界的**完整视觉包**，打成 .tbg 写到 `t_plugin_session_data`。包括：

| 类别 | 示例 | 作用 |
|---|---|---|
| 关卡 JSON | `maps/mulberryTown.json` / `maps/mulberryForest.json` ... | Tiled 导出的关卡（layers / tiles / portals / objects） |
| 起始声明 | `maps/first.map.json` | 声明开局起始图（`start_map.value` = `Mulberry Town`） |
| 故事元数据 | `story.json` / `entity_types.json` | 故事配置、地图 entity 类型表 |
| tileset 属性 | `compiled_dawnlike.json` | 碰撞/视线属性表（`blocked` / `blocks_vision`） |
| 资源 | `images/compiled_tileset_32x32.png` / `images/inventory_sprites/...` | sprite、装备、UI 图等 |
| 数据 | `data.xlsx` / `favicon.png` | 故事侧数据表、图标 |

**所有故事各自一套**，互不污染。**所有用户共用**（写 `sessionId="all"` 跨会话模板）。

## 2. 三层存储 / 加载通道

| 层级 | 位置 | 写入者 | 读取者 | 形态 |
|---|---|---|---|---|
| L1 源 | `workshops/toonflow-field-survival/map_design/<故事名>/` | 设计师（地图编辑） | CLI | 目录 |
| L2 模板 | `t_plugin_session_data.dataKey="map_visual:<故事名>"` (sessionId="all") | `cli.py plugin_session_data -u` | entry `ensureStoryVisualMap` → `getTemplate` | `{format:"tbg", encoding:"base64+zip", data:"<base64>", size, files:[...], source, tbg_path}` |
| L3 会话 | `t_plugin_session_data.dataKey="map_visual"` (per sessionId) | entry `ensureStoryVisualMap` | storyMap `loadStoryMapBundle` | 同 L2 原样复制（会话缓存，避免每帧都跨会话读 all） |
| L4 兜底 | 插件 `ui/maps/`（安装时烘焙的公共关卡） | 安装时 esbuild 进 dist | `loadMapConfig` / `loadLevelByName` 的 fetch 链末位 | 静态资源 |

**优先级**：L3（本会话缓存）→ L2（all 模板）→ L4（公共 ui/maps）→ 兜底 fallbackMapConfig。

## 3. 安装流程

### 3.1 设计师编辑（workshops）

```
workshops/toonflow-field-survival/map_design/<故事名>/
├── story.json
├── entity_types.json
├── compiled_dawnlike.json     ← tileset 属性表
├── data.xlsx
├── favicon.png
├── images/                     ← 全部 sprite / UI
│   ├── compiled_tileset_32x32.png
│   ├── inventory_sprites/
│   └── equipment_placeholders/
├── maps/                       ← Tiled 导出的关卡
│   ├── first.map.json
│   ├── mulberryTown.json
│   ├── mulberryForest.json
│   ├── ...
│   ├── bak/                    ← 旧版（自动排除）
│   ├── prefabs/                ← prefab 关卡（也当作关卡）
│   └── utils/                  ← 单物件关卡（NPC / Chest / Door 等）
└── test_data/                  ← 测试数据（自动排除）
```

`bak/` 和 `test_data/` 在解包时跳过，不进运行时视觉。

### 3.2 打包上传（CLI）

```bash
cd D:\Users\viaco\tools\Toonflow-game\toonflow-game-plugins

# -i 指向本地源目录，CLI 内部解析 manifest.json → 真 pluginId
# -u 传**整个故事目录**（不是 maps/ 子目录），自动 zip 成 .tbg 写 map_visual:<故事名> (sessionId=all)
python -m toon_plugins plugin_session_data \
  -i plugins\toonflow-field-survival \
  -u workshops\toonflow-field-survival\map_design\赦夜人冥夜走廊-第二季 \
  -story "赦夜人冥夜走廊-第二季"
```

**关键点**：
- -u 传**目录**（不是 .tbg）→ CLI 自动 zip 整个目录（保留 zip 内全量 entries：maps/* + tileset + images/* + story.json 等）
- 写入 `dataKey = "map_visual:" + story`，`sessionId="all"`
- 同步写旧 key `map_data:<故事名>`（历史兼容）
- 写入结构：`{format:"tbg", encoding:"base64+zip", data:"<base64>", size, files:[<entry 名数组>], source, tbg_path}`

### 3.3 删除旧数据

```bash
python -m toon_plugins plugin_session_data -i plugins\toonflow-field-survival \
  --remove -k "map_visual:赦夜人冥夜走廊-第二季" -story "赦夜人冥夜走廊-第二季"
```

## 5. 关键约定

### 5.1 故事名来源链（与角色列表同源）

`state.value?.worldName`（plugin_state 顶层）→ 与 `state.value?.roles` 同源，最稳。

补充：
- entry `emptyState` 把 `context.worldName/worldId` 写进 `state.worldName/worldId`
- App.vue onHostState 收到 state 时调 `setStoryContext(state.worldName, state.worldId)` 同步给 storyMap
- 宿主 ScenePlay 拼 iframe URL 时追加 `?story=&worldId=&sessionId=` 作第三道兜底
- dev-host 模式下 `window.__STORY__` 兜底

### 5.2 故事id / sessionId

`state.value?.worldId`（数字）/ `state.value?.sessionId`（字符串）。

宿主 URL 上追加 `?worldId=47&sessionId=gs_xxx`；前端从 `location.search` 取，作为 setStoryContext 之前的兜底。

### 5.3 map_visual 数据形态

| 形态 | shape | 来源 |
|---|---|---|
| 形态② | `{format:"tbg", encoding:"base64+zip", data:"<base64>", size, files:[...], source, tbg_path}` | CLI -u 上传 |
| 形态①-new | `{files: { "maps/mulberryTown.json": <Tiled JSON>, "compiled_dawnlike.json": {...}, "images/...": <bytes>, ... }, first, story, tileset, ...}` | 旧版本手动上传（已弃用） |
| 形态①-legacy | `{files: { "mulberryTown": <Tiled JSON>, ... }, first, ...}` | 极旧版本（已弃用） |

**前端兼容全部三种**：形态②走 v.data 重解 .tbg；形态①-new 按 zip 路径 key 索引（必须含 Tiled layers）；形态①-legacy 按裸文件名索引（必须含 Tiled layers）。**全无 Tiled layers 视为脏数据，拒绝**。

### 5.4 .tbg 解包

`vue/src/zipTbg.ts`：

- `readZipEntries` —— 最小 zip 解析器（0/store + 8/deflate）。**deflate-raw 必须 await**（漏 await 会得到空 bytes，2026-10-14 修）
- `b64ToUint8Array` —— base64 → Uint8Array
- `tbgToVisFiles` —— 解出**全量 entries**（maps/* + tileset + images/* + story.json + entity_types.json + 其它 .json/.png/.gif/.xlsx），按 zip 路径作为 key；附加便利字段（mapFiles / first / story / entityTypes / tileset）
- 跳过 `bak/` 和 `test_data/`

### 5.5 缓存策略

- **L2（all 模板）**：DB 内常驻，写一次多次读
- **L3（本会话）**：DB 内常驻（直到本会话 map_visual 被刷新）；前端 `bundle` 进程内缓存
- **L4（ui/maps）**：插件静态资源，安装时打包进 dist
- **不写** localStorage / sessionStorage / IndexedDB（**纯内存**）

## 7. 故障排查

| 现象 | 原因 | 修复 |
|---|---|---|
| console 显示 `maps/0.json, maps/1.json, ..., maps/1026.json` | DB 里 `v.files` 是数组，Object.keys 当数字 index 处理 | normalizeBundle 检测到数组形态 → 改走 v.data 重解 .tbg |
| `map_visual tbg 解包失败` | zip deflate-raw 漏 await，所有 entry bytes 都是空 | readZipEntries 强制 await |
| console 刷屏 1027 个 keys | bundle.files 全列 | 截断：>30 用 head/tail；>200 提示脏数据 |
| 关卡都加载了但碰撞失效 | tileset 没从 map_visual 包取，回退公共 assetUrl | collision.loadTileFlags 优先 getStoryTileset() |
| 故事名显示"未知" | URL 没带 ?story= 且 state 没 worldName | 修复任一来源链（setStoryContext / URL / window.__STORY__） |
| 故事id 显示"未知" | state.worldId 没设 / URL 没带 ?worldId= | entry emptyState 写入 ctx.worldId / URL 兜底 |
| `tilemapXxx.json` 找不到 | 关卡名映射错了 | `loadMapConfig` 用 `levelNameToFile(name)` 转文件名 |
