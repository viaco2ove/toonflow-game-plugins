## 1. 核心概念：地图集 = 故事文件夹

插件里一个「地图集（map collection）」就是一个**故事文件夹**，放在：

```
workshops/toonflow-field-survival/map_design/<故事名>/
```

| 现有地图集 | 用途 |
|------------|------|
| `base/` | 空白模板（新建地图集时从它复制 compiled_dawnlike.json / entity_types.json / images 等只读资源） |
| `通天传授-收徒系统/` | 收徒玩法故事（事件脚本用 `E01_`/`E50_`/`E70_` 前缀；含 data/ 货单、锻造炼丹面板、练习假人） |
| `赦夜人冥夜走廊-第二季/` | 主线剧情故事（事件脚本用 `SY_` 前缀，23 张地图） |
| `黑塔：从超忆症开始成神/` | 都市悬疑故事（事件脚本用 `HT_` 前缀） |

### 1.1 数据从地图集到玩家的三条链

```
① dev 调试链（vite）
   workshops/<故事>/  ──/story-data 中间件直读──▶  浏览器（改完刷新即生效，无需同步）
       ├─ maps/*.json、events/maps/*.json       → 地图 / 事件
       └─ data/*.json                           → ctx.story.readJson() 读的业务数据

② 正式链（真宿主）
   workshops/<故事>/  ──CLI -build──▶  <故事>.tbg（zip 包，含 maps/ events/ data/ images/ …）
                   ──CLI -u 上传──▶  t_plugin_session_data 的 map_visual:<故事>（sessionId=all）
                   ──开局 getTemplate 拉取──▶  zipTbg 解包 ──▶  运行时视觉世界 + data 数据

③ 兜底链
   plugins/toonflow-field-survival/ui/maps/（安装时烘焙的公共静态副本，不绑故事）
```

三条链的优先级与回退逻辑见 `vue/src/storyMap.ts` / `mapConfig.ts` 的多前缀尝试。
**改完地图只想本地看效果 → 走 ①；要让真机/宿主生效 → 必须走 ②。**

> ⚠️ `data/` 目录只在 ② 里跟着 `.tbg` 走。**改了 data/*.json 必须重建 .tbg**，
> 否则安装态读到的是旧包（dev 看不出来）。

## 2. 地图集目录结构

```
<故事名>/
├── compiled_dawnlike.json        # tileset 属性表（碰撞 blocked / 视线 vision），只读，从 base 复制
├── data.xlsx                     # 数值表：Enemies / Wall Textures / Floor Textures / Decor Textures
├── entity_types.json             # 实体类型档案（32 项：敌人/NPC/尸体/物品…），只读，从 base 复制
├── favicon.png                   # 图标（可选）
├── images/
│   ├── compiled_tileset_32x32.png  # 瓦片大图（Dawnlike 32×32，120 列 × 3488 高，id 0~13079）
│   ├── images.json                 # images 目录索引 + tile id 换算公式（维护说明用）
│   ├── player_sprites/             # 角色 sprite 备份（运行时实际用 tileset 切片）
│   ├── inventory_sprites/          # 物品栏 sprite（文件名 = tileset tile id）
│   ├── equipment_placeholders/     # 装备栏占位图
│   ├── death_icons/                # 死亡/墓碑图标
│   └── spells/                     # 法术动画帧（按学派分目录）
├── maps/
│   ├── first.map.json              # 起始地图声明（见 §5.4）
│   ├── <地图名>.json               # Tiled 地图 JSON（见 §5）
│   ├── prefabs/                    # 预制件（ruins-*.json 等）
│   ├── utils/                      # 模板对象（Chest/Goblin/Door/Mayor Leonard…）
│   └── bak/                        # 备份目录（打 .tbg 时自动排除）
├── events/
│   ├── maps/<地图名>.events.json   # 本图事件（声明式，与地图同名配对）
│   ├── scripts/<脚本名>.ts         # 复杂逻辑脚本（default export）
│   ├── shared/_ctx.ts              # ctx API 类型契约（三个故事共用一份，md5 必须一致）
│   └── 任务事件/quests.json         # 任务定义（任务板数据）
├── data/                          # ★ 地图集自带业务数据（脚本用 ctx.story.readJson 读）
│   ├── shop.forge.json            # 锻造大师货单（149 件）
│   └── shop.alchemy.json          # 炼丹炉货单（163 件）
├── story.json                     # 故事元数据 { storyName, sessionId, worldId }
└── test_data/                     # 测试状态（打 .tbg 时自动排除）
```

要点：

- **`bak/` 与 `test_data/` 会被 .tbg 打包自动跳过**（zipTbg.ts 按 `bak/`、`test_data/` 过滤），可以安全地放备份和测试数据。
- **`compiled_dawnlike.json` / `entity_types.json` / `images/` 属于只读公共资源**，新故事从 `base/` 复制，不要单独改。
- 地图 JSON 的 `tilesets[].source` 字段运行时**不被读取**（reader 只用地图集根目录的 `compiled_dawnlike.json`），写错不影响运行，但建议保持一致。
- **`data/` 是「地图集业务数据」的标准落点**：货单、按钮文案表、NPC 台词表、关卡配置……
  只要不是地图/事件本身的数据，都放这里，用 `ctx.story.readJson("data/xxx.json")` 读。
  **绝对不要写进插件源码**（插件是全故事共用的，写进去就是违规 + 改数据要重编插件）。
- `data/` 下的货单由生成器产出（`vue/scripts/gen-shop-goods.mjs` 读设计文档 md 表格），不要手改生成物。

# WIN2 编辑器前端

cd plugins/toonflow-field-survival/vue
npm run debug -- --story 赦夜人冥夜走廊-第二季 --conn
```

编辑器能力：打开/新建地图集（自动生成完整目录）、地图列表切换、瓦片绘制与擦除、
对象放置与属性编辑、Undo/Redo、碰撞遮罩预览、保存直写文件系统（File System Access API）。
**必须用 Chrome/Edge**（该 API 仅 Chromium 支持）。

手动新建地图集时，从 `base/` 复制：`compiled_dawnlike.json`、`entity_types.json`、`favicon.png`、
整个 `images/`，再建 `maps/first.map.json` 和 `story.json`。

### 3.2 校验器（写完事件必跑）

```
node .cache/validate_events.mjs <故事目录名>
# 例如：node .cache/validate_events.mjs 赦夜人冥夜走廊-第二季
```

检查 7 项：事件 JSON schema 白名单、interact/proximity uid 在 Actors 层真实存在、teleport 目标可解析、
run_script 脚本存在、flag 类型一致性、TS 脚本 ctx API 白名单 + 死循环粗查，
外加 workshops ↔ 插件三份副本的一致性。exit 1 = 有错误。详见 [API文档.md](API文档.md) §5。

### 3.3 CLI（上传/构建/安装）

```

## 4. Tiled 地图 JSON 格式

地图是**标准 Tiled 1.1.3 导出格式**（`orientation: orthogonal`、`renderorder: right-down`、
`tilewidth/tileheight: 32`、瓦片层 `compression: zlib` + `encoding: base64`），
外加 5 个顶层自定义字段。模板见 `workshops/.../map_design/赦夜人冥夜走廊-第二季/maps/mulberryTown.json`。

### 4.1 顶层字段

| 字段 | 值 | 说明 |
|------|----|------|
| `width` / `height` | 整数 | 地图尺寸（格）。桑镇 43×56，森林 60×40，走廊一层 31×23 |
| `tilewidth` / `tileheight` | 32 | 固定 32，1 格 = 1 米 |
| `orientation` / `renderorder` | orthogonal / right-down | 固定 |
| `infinite` | false | 固定 |
| `layers` | 数组 | 见 §4.2 |
| `tilesets` | `[{firstgid:1, source:...}]` | 只认地图集根目录 compiled_dawnlike.json |
| `name` | 中文显示名 | **自定义字段**，如 "桑镇"；地图面板/头顶显示，缺省回退文件名 |
| `theme` | 中文主题 | **自定义字段**，如 "城镇·深夜" |
| `narration` | 旁白文本 | **自定义字段**，进图/主题面板展示 |
| `notes` | 备注 | **自定义字段**，分区说明等 |
| `eventZones` | 数组 | **自定义字段**，事件区域，见 §4.4 |

### 4.2 图层规范

- **瓦片层**：命名 `Tile Layer 1` ~ `Tile Layer N`（现有地图 1~5 层：地面/装饰/物件/顶层…）。
  数据 zlib+base64 压缩。层数越多绘制越慢，控制在 5 层以内。
- **对象层**：必须有一个 `type: "objectgroup"` 的层（现有地图都叫 `Actors`），
  所有实体（出生点、NPC、野怪、出口、机关）都以对象形式放这里。
  读取时取**第一个 objectgroup**，别开两个对象层。
- 编辑器「新建地图」会生成 20×15 空白图（草地 tile + 基础层 + PLAYER 出生点）。

### 4.3 对象属性速查表

所有属性写在 Tiled 对象的 `properties` 数组里（`name`/`type`/`value`）。

> ★ **外观 ≠ entity_type**：实体长什么样由对象的 **`gid`**（指向 tileset 的瓦片）决定，
> `entity_type` 只决定**行为类**（出生点/出口/NPC/怪/容器…）。
> `gid` 是 Tiled 对象的**顶层字段**（`tileId + firstgid`），**不在 properties 里**——
> 想换形象就换 `gid`；`gid` 缺省(0) 时回退「按 entity_type 的默认贴图」。
> 人物是动画瓦片，第一帧就是 `gid` 指向的那格，第二帧读图集的 `animated_id`（不是 id+8）。

**entity_type 总表**（解析规则见 `mapConfig.ts` `normalizeTiledMap`）：

| entity_type | 行为 | 专用属性 |
|-------------|------|----------|
| `PLAYER` / `SPAWN_POINT` | 玩家出生点（**每张图且仅一个**，多个取最后一个） | 无。注意 Tiled 的 y 是 1-indexed，内部会减 1 |
| `NPC` | 可对话中立 NPC（走近弹「💬 聊天」） | `full_name`（中文名，头顶显示）、`name`、`dialog`（对话 key）、`wanders`（bool 游走）、`pickup_item`（可拾取物名，如 "斧头"） |
| `LEVEL_TRANSITION` / `LADDER` | 出口/传送点（走近出「出去」箭头，点击切图） | `portalID`（**目标关卡英文名**，如 "Mulberry Forest"）、`full_name`（出口显示文字，如 "镇口·往桑林"） |
| `DOOR` / `LOCKED_DOOR` | 门（装饰/碰撞） | 无 |
| `CHEST` | 宝箱 / **可交互设施**（见下） | 有 `full_name`/`name`/`dialog` 任一 → 生成可走近交互的实体；都没有 → 只是掉落宝箱占位 |
| `KEY` / `GOLD` / `ITEM` | 掉落物 | 无 |
| `TREE` / `ROCK` / `WALL` | 场景物件 | 无 |
| `ZOMBIE_CORPSE` / `SKELETON_CORPSE` / `CORPSE` | 尸体 | 无 |
| 野怪类型（见 §7 表） | 敌对实体 | 见下 |
| 任意类型 + `camp=hostile` | 也能成怪（走兜底档案） | 同上 |
| 任意类型 + `training_dummy=true` | **练习假人**（见下） | 同上 |

**★ CHEST 也可以是设施**：`entity_type=CHEST` 且带 `full_name`（如「炼丹炉」）时，
它会被当作**可交互实体**注入（而不是只画一张贴图），可以挂 `proximity` 事件。
通天传授的炼丹炉就是这么做的（uid=257，`entity_type=CHEST`、`full_name=炼丹炉`、`gid=9002`）。

**野怪对象属性**（`entity_type` 在白名单内，或 `camp=hostile` 即可成为野怪）：

| 属性 | 类型 | 说明 |
|------|------|------|
| `camp` | string | `hostile` / `neutral` / `friendly`。缺省按 entity_type 推断；`hostile` 可让白名单外类型也成怪 |
| `level` | int | 野怪等级，缺省用 archetype 默认；**练习假人写 0 = 自动「玩家等级+5」**（每次进图重算） |
| `full_name` | string | 姓名，头顶显示「哥布林(低阶湮物)」 |
| `bounty` | JSON 字符串 | 击杀赏金，如 `{"exp":60,"money":40}` |
| `dropTable` | JSON 字符串 | 掉落表，如 `[{"name":"暗核","w":100}]`；缺省回退全局默认表 |
| `training_dummy` | bool | ★ 练习假人标记：`camp=neutral` 但**必须能被打**（有 hp、有血条、可被近战命中）。只写 `camp=neutral` 会变成「打不到的装饰」 |
| `dummy_mode` | string | 假人初始模式：`stand`（站桩）/ `duel`（模拟实战）。脚本运行时会改实体上的 `dummyMode` |

> 击杀奖励（bounty/dropTable）是「地图集参与击杀奖励」的唯一入口——事件引擎没有
> kill_count 挂载点（见 [规范.md](规范.md) §4）。

### 4.4 eventZones（事件区域）

地图顶层自定义字段，`area_enter` 触发器按**区域名**匹配（见 [API文档.md](API文档.md) §2.2）：

```json
"eventZones": [
  { "name": "夜采药圃", "x": 4,  "y": 27, "rx": 6, "ry": 8 },
  { "name": "药铺",     "x": 8,  "y": 11, "rx": 3, "ry": 2 },
  { "name": "篝火",     "x": 20, "y": 30, "r": 5 }
]
```

- `x`/`y` 是 **Tiled 瓦片坐标**（不是像素）；`rx`/`ry` 矩形半长宽、`r` 圆形半径，
  单位同样是**瓦片**（1 格 = 1 米，所以等于米）。三者都给时 rect 优先。
- 运行时换算：`世界坐标 = 瓦片坐标 - 地图半宽/半高`（App.vue `afterMapSwitchForEvents`）。
- **区域名必须与事件 JSON 的 `trigger.zone` 完全一致**（questGatherMap 的采集寻路也认这个名）。

### 4.5 交互设施：走近自动弹按钮（proximity）

功能设施（锻造大师、炼丹炉、练习假人）用 `proximity` 触发器，**不需要**玩家先点「💬 聊天」：

```
地图 Actors 层放一个对象（NPC 或带 full_name 的 CHEST）
        + gid（外观）
        ↓
events/maps/<map>.events.json 里加一条 proximity 事件
        { trigger: {type:"proximity", uid:"<对象id>", radius:2.8},
          proximity: {label:"锻造", icon:"🔨", hint:"走近锻造大师"},
          repeat: true, actions:[{type:"run_script", script:"E50_forge_master"}] }
        ↓
玩家走进 radius 米 → HUD 弹「🔨 锻造」按钮 → 点击 → 跑脚本 → 脚本开面板/弹选择框
```

| 规则 | 说明 |
|------|------|
| 按钮文案 | 事件**顶层** `proximity.label/icon/hint`，不是写在 trigger 里 |
| 半径 | `trigger.radius` 米，默认 2.8，最小 0.8；只取**最近的一个**点位 |
| 冷却 | 面板类必须 `repeat: true`（否则同一次进图只能开一次） |
| 与聊天互斥 | 该 uid 挂了 proximity 事件后，**不再弹「💬 聊天」**（避免两个入口打架） |
| 实体存活 | 实体 `alive=false` 时不再弹按钮 |
| 拿不到 uid | 脚本里 `ctx.npc.byUid(uid)` 自己找（同一个脚本可被多个 uid 复用，如 4 个假人） |

完整可照抄的案例：[触发性事件.靠近目标.地图集制作案例.md](地图集事件案例/触发性事件.靠近目标.地图集制作案例.md)

## 5. 三个辅助文件

### 5.1 first.map.json（起始地图声明）

```json
{ "start_map": { "name": "portalID", "type": "string", "value": "Mulberry Town" } }
```

- `value` = 开局进哪张图（**关卡英文名**，经 levelNameToFile 找 `maps/<小写驼峰>.json`）。
- 缺失/读不到 → 回退 `DEFAULT_START_LEVEL`（"Mulberry Town"）。
- 开局之后的切图只由场景内 `LEVEL_TRANSITION` 出口触发，first.map.json 只管开局。

### 5.2 story.json（故事元数据）

```json
{ "storyName": "赦夜人冥夜走廊-第二季", "sessionId": "gs_1789458006016_e0d4ebf114", "worldId": 47 }
```

- **只存元数据，不存任何 flag/进度**（flag 唯一来源是玩家卡 `t_plugin_session_data`）。
- `worldId` 是宿主世界观 id；`sessionId` 由宿主会话生成。

### 5.3 images/images.json（维护说明）

记录 tileset 的 id 换算与子目录用途，改图片资源时同步更新。tile id → 像素：

```
src_x = id % 120 * 32        # 120 列
src_y = id // 120 * 32       # 每行 120 格，全图 3488 高
```

id 分段：0-99 基础物品小图标 / 100-999 UI 图标 / 1000-1999 地表植物装饰 / 2000+ 角色与物件。

## 6. 坐标系统（1 米/格，图心为原点）

这是出错最多的地方，务必读懂：

| 坐标系 | 原点 | 用途 |
|--------|------|------|
| Tiled 瓦片 | 左上角 | 地图编辑、eventZones |
| Tiled 像素 | 左上角 | Tiled 对象 x/y（32px/格） |
| 世界（米） | **图心** | 实体坐标、teleport 落点、任务目标 |

换算公式（mapConfig.ts / App.vue）：

```
世界x = 对象像素x / 32 - 图宽 / 2
世界y = 对象像素y / 32 - 1 - 图高 / 2      # Tiled 对象 y 是 1-indexed，减 1
eventZones: 世界x = 瓦片x - 图宽/2，世界y = 瓦片y - 图高/2
```

现有地图坐标范围（写 teleport / 任务目标时先卡一遍）：

| 地图 | 尺寸 | x 范围 | y 范围 |
|------|------|--------|--------|
| mulberryTown（桑镇） | 43×56 | [-21.5, 21.5] | [-28, 28] |
| mulberryForest（桑林） | 60×40 | [-30, 30] | [-20, 20] |
| mulberryGraveyard（乱葬岗） | — | 见图内 name 尺寸 | — |
| mulberryDungeon1（走廊一层） | 31×23 | [-15.5, 15.5] | [-11.5, 11.5] |
| kingdom | 40×40 | [-20, 20] | [-20, 20] |

> **坐标写超不报错，只会「寻路后原地不动」/ 落点被 freeEnemySpot 夹回边界**——
> 排查任务/传送问题时先按上表核对。

## 7. 地图命名：三套写法，切图只认第三列

| 用途 | 示例 | 说明 |
|------|------|------|
| ① 地图文件名（关卡 key） | `mulberryDungeon1` | 小写驼峰，= `maps/mulberryDungeon1.json`、.tbg 内 mapFiles 的 key，**唯一能喂 switchLevel/teleport 的标识** |
| ② 关卡英文名 | `Mulberry Dungeon` | 带空格的 Pascal 写法，first.map.json / portalID / THEME_BY_MAPNAME 用它；层号在归一化时可能丢 |
| ③ 中文显示名 | `冥夜走廊·一层` | 地图 JSON 顶层 `name` 字段，只用于展示 |

换算规则 `levelNameToFile`（mapConfig.ts）：

```
"Mulberry Forest" → 去掉非字母数字后按驼峰拼接 → mulberryForest
"Mulberry Dungeon 2" → mulberryDungeon2      （层号在尾部才保得住）
```

**两个禁忌**（血泪教训）：

1. **纯中文名不能当 key**：`toLowerCase().replace(/[^0-9a-z]/g,"")` 对「桑镇」返回空串——
   用它做前缀匹配会恒真、做相等比较会把「桑镇」「桑林」判成同图。跨图寻路一律先过
   `levelKeyOf()`（前端）/ `rawQuestMapKey()`（后端）转换。
2. 出口 `portalID`、teleport 目标、first.map.json 的 value 全部写**英文名 ②**，
   不要写中文名 ③，也不要写文件名 ①（①只在地图 JSON 内部和 mapFiles 索引用）。

野怪类型白名单（MOB_ARCHETYPES，`camp=hostile` 可突破白名单）：

| entity_type | 中文名 | HP/ATK/Lv |
|-------------|--------|-----------|
| RAT / BAT / SNAKE | 老鼠 / 蝙蝠 / 毒蛇 | 12/4/1、20/5/1、25/8/2 |
| GOBLIN / LOOT_GOBLIN | 哥布林 / 拾荒哥布林 | 30/6/1、40/8/2 |
| ORC / ORC_BOSS | 半兽人 / 兽人首领 | 80/12/3、200/18/8 |
| SKELETON / ZOMBIE / GHOST / IMP | 骷髅兵 / 僵尸 / 幽灵 / 小恶魔 | 50/12/2、60/10/1、35/9/3、30/7/2 |
| LICH | 巫妖 | 160/20/7 |
| WOLF / BOAR / WILD_GOAT | 巨狼 / 野猪 / 山羊 | 60/10/2、50/8/1、45/9/2 |

## 8. 野怪刷新与安全区

| 规则 | 说明 |
|------|------|
| 城镇不刷怪 | 关卡名在 `THEME_BY_MAPNAME` 里映射为 null 的（Mulberry Town / Kingdom 等）无兜底刷怪；关按键名含 town/overworld 自动判定为城镇 |
| 野外/地牢按主题刷 | RUINS（≤5 层）/ CATACOMBS / MINE / ICE 四主题决定兜底怪池；关盆栽名含 graveyard/lich/crypt → CATACOMBS，mine/cave → MINE，ice/frost/snow → ICE，未登记回退 RUINS |
| 城镇安全区 | 城镇类地图自动生成中心 safe 区（rx/ry 截断到 15/17），野外/地牢 zones 为空——**别指望森林中央有安全区** |
| 手动野怪 | Actors 层放的野怪对象最可靠（等级/camp/赏金/掉落都可定制），兜底刷怪只是补底 |
| 练习假人 | 手动放对象 + `training_dummy=true` + `camp=neutral`（进 mobs 分支才有 hp/血条）+ `level`（0=玩家等级+5）。它不主动攻击，由脚本改 `side=enemy` 才开打 |
| 地图面板等级标签 | `MAP_MOB_LEVEL_RANGE`（mapConfig.ts）按文件名登记 Lv 区间；改地图野怪等级后两边同步（脚本 `.cache/set_map_mob_levels.py` 改 JSON，这张表管显示） |

> 森林/墓地中心格可能是墙：进图落点有 `settleSpawn` 自动纠化（主连通域 + 离 portal ≥3 米），
> 但 teleport 写坐标时仍要避开墙。

## 9. 新地图制作全流程（checklist）

```
[ ] 1. 编辑器打开目标地图集（或从 base/ 复制只读资源新建）
[ ] 2. 铺地形：瓦片层命名 Tile Layer 1..N，≤5 层；瓦片只用 compiled_dawnlike 图集
[ ] 3. 放 Actors：PLAYER/SPAWN_POINT 出生点唯一；NPC 带 full_name + gid（外观）；出口 LEVEL_TRANSITION
[ ]    带 portalID（英文名）；野怪带 entity_type + camp + level；练习假人带 training_dummy=true
[ ] 4. 写顶层自定义字段：name（中文显示名）/ theme / narration / notes
[ ] 5. 按需画 eventZones（区域名=事件 trigger.zone=采集寻路 zone 名，三处一致）
[ ] 6. 写 events/maps/<地图名>.events.json（文件名与地图 JSON 主名一致！）
       功能设施用 proximity（顶层写 proximity.label/icon/hint，事件 repeat:true）
[ ] 7. 复杂逻辑写 events/scripts/<名>.ts（本故事前缀：赦夜人 SY_，通天传授 E01_/E50_/E70_）
[ ] 8. 需要自带数据（货单/文案表）→ 放 data/*.json，脚本用 ctx.story.readJson 读
[ ] 9. 跑校验：node .cache/validate_events.mjs <故事目录名>  直到 0 error
[ ]10. 同步副本：events/maps → vue/public/events/maps + ui/events/maps；
       scripts → vue/src/eventScripts（import 改 ./_ctx）；四份 _ctx.ts md5 一致
[ ]11. dev 验证：npm run debug -- --story <故事名> --conn，进图逐条过事件
[ ]12. 发布：CLI -build 打 .tbg（含 data/）→ -u 上传 → 真宿主进游戏验证
```

## 10. FAQ / 排查表

| 现象 | 先查哪里 |
|------|----------|
| 进图提示「关卡加载失败（地图文件缺失）」 | ① 文件名与 `levelNameToFile(portalID/first.map.json)` 是否对得上；② .tbg 是否重新上传；③ mapConfig 控制台的 fetch 前缀链日志 |
| 野怪不出现/不追人 | ① entity_type 在白名单或有 camp=hostile；② 地图是不是城镇（theme null + 中心 safe 区抑制兜底刷怪）；③ 落点是否正好在 safe 区内 |
| 出口点了没反应 | ① portalID 写的是英文名 ②（不是中文名/文件名）；② 目标地图 JSON 存在；③ App.vue 日志「关卡不存在」 |
| 事件不触发 | ① 引擎只实现 enter_map/interact/proximity/area_enter/interval 五种（见 规范.md §4）；② 事件文件名必须与地图主名一致；③ dev 直读 workshops，真宿主读 .tbg 副本——改了 workshops 没同步/上传等于没改；④ interact/proximity 的 uid 是 Tiled 对象 id（数字），且真实存在于 Actors 层；⑤ `repeat` 缺失 → 同一次进图只 fire 一次 |
| 走近设施不弹按钮 | ① 事件 `trigger.type` 是不是写成了 `interact`（那是「💬 聊天」通道）；② `proximity.label` 写在**事件顶层**了吗（写进 trigger 里不生效）；③ uid 对不上实体（看实体 id `mapnpc_<uid>` / `mapmob_<uid>_<ts>`）；④ 实体 `alive=false` 不弹；⑤ 半径够不够（默认 2.8 米） |
| 点了按钮没反应/面板不开 | ① 脚本里 `ctx.ui.openShopPanel` 前面是否提前 return（AI 执行者会跳过开面板）；② 事件没配 `repeat:true` → 第二次进图才恢复；③ 脚本异常被吞：看 console 的 `[eventEngine] 事件执行异常` |
| 锻造/炼丹面板能开但货架是空的 | ① `data/shop.forge.json` / `shop.alchemy.json` 是否存在；② 事件脚本是否真的把 `goods` 传给了 `openShopPanel`；③ 安装态是否忘了重建 `.tbg`（dev 能读、真机读不到就是这个原因）；④ 分类页空但「全部」有货 = 商品缺 `cat` 字段 |
| 买了东西没进背包/扣钱不对 | 面板购买走 `sys_shop_buy` + `params.good`；先看后端回执（弹窗文案）：`商品不存在` = good 没带上来或 price≤0 |
| 假人打不到 / 打不死 / 没血条 | ① `training_dummy=true` 漏了 → 走了装饰物分支（只有贴图没有 hp）；② `camp` 写成 hostile 会主动打人（假人应 neutral）；③ `level` 0 = 玩家等级+5，别写 0 又期待固定等级 |
| 改了脚本不生效 | 运行时读 `vue/src/eventScripts/`（构建期内联），不是 workshops；同步后**刷新页面**；改了 `entry.ts` 要跑 `python -m toon_plugins plugins -i`（自动重编 entry.js 并安装，别手编手拷） |
| 改了 data/*.json 不生效 | dev：刷新页面（有缓存，按 path 缓存一局）；真宿主：**必须重建 .tbg**（`-build`）后重新 `-u` |
| 任务寻路原地不动 | 任务目标坐标超出该图范围（§6 表）；或目标图 station 名是纯中文（key 归一化空串） |
| 地图串故事（进 A 故事看到 B 的地图） | dev 前缀必须与 `?story=` 同源（STORY_EVENT_BASE_DEV / STORY_MAP_BASE_DEV 用同一个故事名）；CLI 上传的 dataKey 是 `map_visual:<故事名>`，故事名写错就会串 |
| 进图卡顿 | 瓦片层 ≤5；对象层对象数别上千（NPC/野怪都进实体）；装饰逐格生成已废弃，走烘焙 |
| Tiled 手工编辑后自定义字段丢了 | 顶层 name/theme/narration/notes/eventZones 要手改回 JSON，或用本编辑器 |
