# 假人交互事件 · 地图集制作案例

> **一句话**：走近练习假人 → 弹「⚔ 对打」按钮 → 选择 **站桩模式**（不还手、自动回血、无经验）
> 或 **模拟实战**（会反击、血条不回、击碎给经验）→ 引擎按你选的模式改假人状态。
>
> 前置：[触发性事件.靠近目标](触发性事件.靠近目标.地图集制作案例.md)。
> 接口：[../API文档.md](../API文档.md) §2.2（`ctx.npc.setField`）；硬约束：[../规范.md](../规范.md) §4 第 18 条。

---

## 0. 两种模式的区别

| | 站桩模式 `stand` | 模拟实战 `duel` |
|---|---|---|
| 假人还手 | ❌ 站着不动 | ✅ 会反击（阵营变敌对，走引擎敌人 AI） |
| 血条 | 每秒自动回 5%，打空也原地立起来 | 不回复，打空即散架 |
| 奖励 | 无经验 | 击碎得经验 `10 + 等级×6` |
| 结束条件 | 玩家离开 4 米 / 假人被打空 | 击碎，或玩家离开 6 米（未击碎则复位） |
| 下次还能用 | 是 | 是（重进地图后假人重新立起） |

---

## 1. 要准备的东西

```
① 地图 Actors 层  对象属性：training_dummy=true + camp=neutral + level(+dummy_mode)
② 事件 JSON      每条假人一个 proximity(uid) → 全部指向同一个脚本
③ TS 脚本        选模式 → ctx.npc.setField 改 side/dummyMode → 回血/轮询击碎 → 发经验
```

**不用改插件**。假人之所以能被打、能有血条、能被击碎，靠的是地图属性 + 已有引擎能力；
插件侧只多了一条「`training_dummy` 也算合法攻击目标」的通用判定。

---

## 2. 第一步：地图对象属性

练习假人**不是 NPC**，它是「能被攻击的中立单位」，靠 `training_dummy=true` 走特殊分支：

| 属性 | 必填 | 说明 |
|------|------|------|
| `training_dummy` | ✅ | `true`。漏了 → 走「NPC 装饰物」分支，只有一张贴图，**打不到、没血条** |
| `camp` | ✅ | **必须 `neutral`**。写 `hostile` → 假人会主动追打玩家，站桩模式直接失效 |
| `level` | ✅ | 假人等级。`0` = **永远比玩家高 5 级**（每次进图重算） |
| `entity_type` | ✅ | 决定 hp/atk 档案，`SKELETON` = 骷髅兵（hp 50 / atk 12 / Lv2 基准），按等级 ×(1+(Lv-1)×0.3) 缩放 |
| `name` | | 实体名（脚本 toast 里用它） |
| `full_name` | | 头顶显示：`<类型中文名>(<full_name>)`，例如「骷髅兵(练习假人)」 |
| `dummy_mode` | | **初始**模式 `stand` / `duel`。玩家一旦通过菜单选过，就会被脚本覆盖；只影响「没选模式直接打」时后端是否记击碎 |
| `gid` | | 外观。`gid=0` 就用 `entity_type` 的默认贴图（假人就是骷髅） |

实物（`通天传授-收徒系统/maps/mulberryTown.json`，Actors 层）：

```json
// 假人 1（uid=251，站桩型，Lv10）
{ "id": 251, "x": 512, "y": 64, "width": 32, "height": 32,
  "properties": [
    { "name": "entity_type",   "value": "SKELETON", "type": "string" },
    { "name": "camp",          "value": "neutral",  "type": "string" },
    { "name": "level",         "value": 10,         "type": "int" },
    { "name": "name",          "value": "练习假人", "type": "string" },
    { "name": "training_dummy","value": true,       "type": "bool" },
    { "name": "dummy_mode",    "value": "stand",    "type": "string" }
  ] }

// 假人 4（uid=254，level=0 → 永远玩家+5 级）
{ "id": 254, "properties": [ /* ... "level": 0, "dummy_mode": "duel" ... */ ] }
```

四台假人的推荐梯度：`level` 10 / 20 / 30 / 0（0 = 跟随玩家）。

## 3. 第二步：事件（4 条，共用一个脚本）

```json
{ "id": "E70_dummy_1", "comment": "走近练习假人1：走进即弹「对打」按钮",
  "trigger": { "type": "proximity", "uid": "251", "radius": 2.8 },
  "proximity": { "label": "对打", "icon": "⚔", "hint": "走近练习假人1" },
  "repeat": true, "actions": [{ "type": "run_script", "script": "E70_training_dummy" }] }

{ "id": "E70_dummy_2", "trigger": { "type": "proximity", "uid": "252", "radius": 2.8 },
  "proximity": { "label": "对打", "icon": "⚔", "hint": "走近练习假人2" },
  "repeat": true, "actions": [{ "type": "run_script", "script": "E70_training_dummy" }] }
```

要点：
- **`repeat: true` 必须有**——打完一次还要能再打（repeat 有 3 秒冷却）。
- 4 条事件指向**同一个脚本**；脚本靠「玩家附近最近的假人」自己判断是谁。

## 4. 第三步：脚本（骨架 + 三个关键点）

完整实现见 `events/scripts/E70_training_dummy.ts`，这里只列你必须理解的三个关键点。

### 4.1 找目标：引擎不传 uid 给脚本

`run_script` 的动作参数 `args` **不透传**，脚本拿不到「是哪个 uid 触发的」。当前实现是自己找最近的：

```ts
/** 找玩家 3m 内最近的练习假人 */
const uids = ["251", "252", "253", "254"];   // ★ 换成你自己地图的对象 id
const me = ctx.player as any;
let best = null, bestDist = 3.0;
for (const uid of uids) {
  const ent: any = ctx.npc.byUid(uid);
  if (!ent || ent.alive === false) continue;
  const d = Math.hypot((ent.x ?? 0) - me.x, (ent.y ?? 0) - me.y);
  if (d < bestDist) { bestDist = d; best = { uid, ent }; }
}
```

> ⚠️ **这是复制脚本时必须改的一行**：`uids` 数组写死的是通天传授的四台假人。
> 换地图集要换成自己的对象 id（引擎没有「列出附近实体」的 API，只能按 uid 探测）。

### 4.2 改状态：必须用 `ctx.npc.setField`，不能改快照

```ts
// ❌ 错：byUid 返回的是快照，改了不会生效
const e = ctx.npc.byUid(uid); if (e) e.side = "enemy";

// ✅ 对：setField 走 state 里的可变引用（entityRef）
ctx.npc.setField(uid, { side: "enemy", dummyMode: "duel" });
```

可改字段：`side`（`enemy` 才会被当敌对目标、血条变红）、`dummyMode`、`hp`、`alive`、`maxHp`。

`ctx.npc.setLabel / move / faceTo` 是**空实现**（调用不报错、什么都不发生），别指望它们。

### 4.3 站桩：自己起定时器回血，离开就复位

```ts
ctx.npc.setField(uid, { side: "enemy", dummyMode: "stand" });

const heal = setInterval(() => {
  const ent: any = ctx.npc.byUid(uid);
  if (!ent) { clearInterval(heal); return; }
  if (ent.alive === false || (ent.hp ?? 0) <= 0) {          // 被打空 → 原地立起
    ctx.npc.setField(uid, { hp: ent.maxHp ?? 100, alive: true });
    return;
  }
  const hp = Number(ent.hp) || 0, maxHp = Number(ent.maxHp) || hp || 100;
  if (hp < maxHp) ctx.npc.setField(uid, { hp: Math.min(maxHp, hp + Math.max(1, Math.round(maxHp * 0.05))) });
}, 1000);

const watch = setInterval(() => {                            // 离开 4m → 结束站桩
  const ent: any = ctx.npc.byUid(uid), me = ctx.player as any;
  if (!ent || !me) { clearInterval(watch); clearInterval(heal); return; }
  if (Math.hypot(ent.x - me.x, ent.y - me.y) > 4) {
    clearInterval(watch); clearInterval(heal);
    ctx.npc.setField(uid, { side: "neutral", hp: ent.maxHp ?? 100 });
    ctx.ui.toast("站桩结束，假人恢复了平静。", "white");
  }
}, 1500);
```

### 4.4 实战：击碎由**后端**记账，脚本只负责发经验

玩家砍死假人这件事发生在 `entry.ts` 的 `damage()` 里，脚本收不到回调。所以链路是：

```
玩家把假人打到 0 血
  → entry.ts damage() 检测 trainingDummy && dummyMode !== "stand"
  → 写 flag：dummy_destroyed_<实体id>
  → 脚本每 1.2s 轮询该 flag，发现为 true → ctx.cmd("sys_dummy_reward", {exp, name})
  → 后端 gainPlayerExp + 飘字 + 事件日志
```

```ts
const expGain = 10 + dummy.level * 6;
const timer = setInterval(async () => {
  if (await ctx.save.getFlag(`dummy_destroyed_${dummy.id}`)) {
    clearInterval(timer);
    await ctx.cmd("sys_dummy_reward", { exp: expGain, name: dummy.name });
    ctx.ui.subtitle(`${dummy.name} 击碎！+${expGain} 经验`, 2000);
  }
}, 1200);
```

> 为什么经验不直接由后端 `damage()` 发：假人是 `camp=neutral`，不是野怪，
> 走野怪赏金链会连带 `kills++`、掉落、宝箱逻辑。所以后端只「记倒下」，
> 奖励数值留给地图集自己决定（不同故事想要不同经验曲线就改这一行）。

### 4.5 重进地图自动重置

假人实体 id 形如 `mapmob_<uid>_<世代时间戳>`，每次进图 `currentMapMobTs` 都变 →
`dummy_destroyed_<旧实体id>` 自然不再命中 → 假人满血复活。
（旧 flag 会留在 `player_flags` 里不再使用，属已知无害残留。）

---

## 5. 为什么状态不会被「每 tick 回滚」

客户端对 `mapmob_*` 的假人是**本地权威**：`onHostState` 合并时用客户端版本覆盖宿主/模拟后端
传回的同 id 实体。否则脚本刚把 `side` 改成 `enemy`，下一 tick 宿主快照就把它打回 `neutral`（实测 1 秒内回滚）。

这条规则写在 `App.vue` 的状态合并里，**你不需要做任何事**，但要知道：
假人这类「脚本会改状态的实体」必须走 `mapmob_*` 前缀注入（由 `training_dummy` 自动保证）。

## 6. 坑表

| 现象 | 原因 / 解法 |
|------|-------------|
| 假人打不到、没血条 | 漏了 `training_dummy=true` → 走了 NPC 装饰物分支（只有贴图） |
| 假人主动追着打人 | `camp` 写了 `hostile`。必须 `neutral` |
| 走近不弹「对打」 | ① 事件 `trigger.type` 不是 `proximity`；② uid 与对象 id 不符；③ 漏 `repeat: true` |
| 点了「对打」没反应 | 脚本 `uids` 数组没改成自己的对象 id → 找不到假人，只弹「附近没有练习假人」 |
| 改了 side 但血条不变红 | 没用 `ctx.npc.setField`（改了快照）；或没写 `side: "enemy"` |
| 站桩打空后假人消失 | 回血定时器没处理 `alive=false` → 补「原地立起」分支 |
| 实战打死了没经验 | ① 轮询 flag 的 key 用错（必须是 `dummy_destroyed_<实体id>`，含世代 ts）；② 后端 `sys_dummy_reward` 没被调用 |
| 假人被打死后永远不复活 | 说明直接写了固定 key 的 flag（不含实体 id）；用实体 id 才能随世代失效 |
| 假人等级不跟随玩家 | `level` 写了固定值。想要「玩家+5」必须写 `level: 0` |
| dev 里行为诡异（残留弹窗/重复菜单） | 多次 HMR 留下的脏实例；刷新页面重进图 |

## 7. 检查清单

```
[ ] 地图对象：training_dummy=true、camp=neutral、level（0=玩家+5）、entity_type、gid
[ ] 每条假人一个 proximity 事件，uid 与对象 id 一致，repeat: true
[ ] 脚本里 uids 数组 = 本图的假人对象 id
[ ] 改状态全部走 ctx.npc.setField（没有直接改 byUid 返回值）
[ ] 站桩：每秒回血 + 打空立起 + 离开 4m 复位 neutral
[ ] 实战：轮询 dummy_destroyed_<实体id> → sys_dummy_reward 发经验 + 离开 6m 未击碎复位
[ ] node .cache/validate_events.mjs <故事名> → 0 error
[ ] dev 实测：站桩能打能回血；实战会反击、击碎有经验；重进图假人复活
[ ] 事件/脚本已同步插件副本（否则真机跑的是旧脚本）
```
