# 「已复制-改」方式制作地图集

> 用现成地图集（`base/` 空白模板、`赦夜人冥夜走廊-第二季`、`通天传授-收徒系统`、`黑塔：从超忆症开始成神`）
> 复制一份，改成新故事集的完整流程。本文档是**操作手册**，讲「一步步做什么」；
> 格式细节看 [地图制作指南.md](地图制作指南.md)，硬规则看 [规范.md](规范.md)，接口看 [API文档.md](API文档.md)。
>
> **实例**：本文按「把桑镇奇幻地图集复制改造成《黑塔：从超忆症开始成神》」的真实过程写成
> （2026-10-23 实施完毕），所有坑都是踩过验证的。

---

## 0. 前置认知：什么能改，什么不能改

一个地图集目录里，文件分三类：

| 类别 | 文件 | 改不改 |
|------|------|--------|
| **只读公共资源** | `compiled_dawnlike.json`、`entity_types.json`（结构）、`images/` 整目录、`data.xlsx` | 从 `base/` 原样复制，**运行时引擎只认这四个的格式，别按故事魔改结构** |
| **故事数据** | `maps/*.json`、`maps/first.map.json`、`events/`、`story.json` | **本次改造的主战场**，全部可以改 |
| **半共享** | `entity_types.json` 的**内容**（enemies/dungeon_themes/item_types）、`story.json` 的 `storyName` | 内容按故事重写，**但 schema 结构保持不变** |

⚠️ **头号铁律**：`plugins/toonflow-field-survival/vue/src/` 下的代码表（`mapConfig.ts`/`mockHost.ts`/`entry.ts`）是**所有故事全局共享**的。改地图集时对这些文件**能不动就不动**，要动也只增不删、先查重（见 §5）。

## 1. 复制

```bash
cd workshops/toonflow-field-survival/map_design
# 目录名 = 新故事名（定好后别中途改名）
cp -r <来源集> <新故事名>
# 例： cp -r 赦夜人冥夜走廊-第二季 我的新故事
```

- **从哪个集复制**：看瓦片/地形风格与新故事的接近程度。黑塔（校园）实际复制的是桑镇奇幻系地图集——只改数据层，瓦片美术完全复用。拿不准就复制 `base/`（空白模板）。

- 目录名 = 故事名，会写进 `story.json` 的 `storyName`，也是 `-story` 参数、`map_visual:<故事名>` key、dev-host `--story` 参数——**定好后别中途改名**。
- 复制完先清垃圾：删掉原集的 `bak/`、`test_data/`、`maps/bak/`（避免旧备份被当成新故事内容）。
- 顺手做一份**改造前备份**（或者放到集外 `workshops/toonflow-field-survival/bak/`）：

```bash
# 备份放集外 bak/ 目录（不要放地图集目录内，会被打 .tbg 包）
cp -r <新故事名> ../../bak/<新故事名>.pre-retheme-<日期>
# 例： cp -r 黑塔：从超忆症开始成神 ../../bak/黑塔：从超忆症开始成神.pre-retheme-20261023
```

## 2. 改 story.json + first.map.json

```bash
# story.json 只改 storyName（sessionId/worldId 是运行时数据，保留原值即可）
# first.map.json 的 value = 开局那张图的关卡英文名
cat > maps/first.map.json << 'EOF'
{
  "start_map": { "name": "portalID", "type": "string", "value": "Lich Lair" }
}
```

- `value` 写**关卡英文名**（带空格 Pascal），不是文件名也不是中文显示名。
- 开局图建议选**小而安全**的（无野怪、有明确出口），玩家第一眼看到的就是它。

## 3. 地图批量改造（改 name/theme/narration/notes/eventZones）

每张 Tiled JSON 顶层有 5 个故事字段，这是「换皮」的主阵地：

| 字段 | 作用 |
|------|------|
| `name` | **中文显示名**。只用于展示；切图/任务 map 归一/传送门都**不认它** |
| `theme` | 地图集内部说明（引擎不消费，写给编辑器/AI 看） |
| `narration` | 旁白（进图氛围文字） |
| `notes` | 编辑备注（区域说明，写给维护者） |
| `eventZones` | 事件区域数组 `[{name,x,y,rx,ry}]`，**瓦片坐标** |

批量改造推荐**写 Python 脚本**（比 20 多张图逐个手改快一个量级，且可重跑）：

```python
# .cache/<你的脚本>.py 的核心结构（幂等，可重复跑）
import json, os, io
M = {}  # slug → 新元数据
M["lichLair"] = dict(name="陈曦的卧室", theme="室内·清晨",
    narration="...", notes="...", zones=[dict(name="书桌", x=6, y=6, rx=4, ry=3)])
for slug, cfg in M.items():
    p = f"maps/{slug}.json"
    d = json.load(open(p, encoding="utf-8"))
    d["name"] = cfg["name"]; d["theme"] = cfg["theme"]
    d["narration"] = cfg["narration"]; d["notes"] = cfg["notes"]
    d["eventZones"] = cfg["zones"]
    with io.open(p, "w", encoding="utf-8") as f:
        json.dump(d, f, ensure_ascii=False, indent=2); f.write("\n")
```

改造要点：

- **显示名自由改，key 全部不动**：文件名 `mulberryTown.json`、`portalID`、事件 `teleport` 目标里的英文关卡名，一律保持原样。运行时切图走 `levelNameToFile()` 把英文名转文件名，改了就断。
- 事件区域（`eventZones`）的 `x/y/rx/ry` 是**瓦片坐标**，改了场景语义（比如药圃变书桌）就按新场景重新画。
- 每张图的 `narration`/`notes` 别偷懒，写新故事的氛围文字——这两块是「复制-改」最出效果的地方。

## 4. 地图对象改造（NPC / 野怪 / 出口）

### 4.1 先盘点再动手

```python
# 把所有图的 objectgroup 全 dump 出来，列出每张图有什么
# 关注三个东西：entity_type、full_name、portalID/full_name
```

### 4.2 NPC 改造 —— 复用 uid

每个 NPC 对象的 `uid` 被事件 `interact` 引用。**优先改属性而不是删了重建**：

```json
// 改前（桑镇酒馆老板）
{"id": 165, "name": "NPC", "properties": [
  {"name": "entity_type", "type": "string", "value": "NPC"},
  {"name": "dialog", "type": "string", "value": "BARTENDER"},
  ...]}
// 改后（黑塔的苏晓）——只动三个属性：name / full_name / dialog
{"id": 165, "name": "苏晓", "properties": [
  {"name": "entity_type", "type": "string", "value": "NPC"},           // 保留
  {"name": "wanders", "type": "bool", "value": false},                 // 保留
  {"name": "full_name", "type": "string", "value": "苏晓"},            // ← 改：头顶显示名
  {"name": "dialog", "type": "string", "value": "SU_XIAO_CLASS_PRESIDENT"}  // ← 改：新对话 key
]}
```

- **新增 NPC**：`nextobjectid` 递增 uid，放进唯一 objectgroup 层，属性同上。
- `dialog` key 想换就换，但要让前端 `NPC_DIALOG_ZH`（mapConfig.ts）认识——不认识就**头顶不显示中文名**（fallback 是原名）。
- `wanders`、`bubbleData`、`dialogBubbleEnabled` 可保留原值。

### 4.3 野怪改造 —— entity_type 换成新体系

野怪类型必须**三处一致**：地图对象 `entity_type` ↔ `entity_types.json` `enemies[].entity_type` ↔ `MOB_ARCHETYPES`（mapConfig.ts，除非对象带 `camp=hostile` 走兜底档案）。

- `full_name` 换成新故事的称号（如「值日生」「体育课代表」）——击杀任务按双向 includes 匹配，**目标名要能在头顶名里命中**。
- `level` 可按新故事的等级曲线重排。
- `bounty`/`dropTable`（JSON 字符串）按需重写。
- **不要删旧类型条目**——另一套故事集还在用。

### 4.4 出口改造 —— 只改 `full_name` 标签，portalID 不动

```json
{"name": "Level Transition", "properties": [
  {"name": "entity_type", "type": "string", "value": "LEVEL_TRANSITION"},
  {"name": "portalID", "type": "string", "value": "Mulberry Forest"},   ← 保持
  {"name": "full_name", "type": "string", "value": "往网球场"}          ← 改这个
]}
```

出口显示文字（`full_name`）改成新地名，`portalID` **绝对不动**——它经 `levelNameToFile()` 转文件名，改了切图就静默失败。

## 5. entity_types.json 内容重写

schema 保持不变，内容按新故事重写：

- `enemies[]`：换成新怪。字段照抄原结构（`entity_type/name/description/description_zh/hp/mana/str/def/range/morale/wanders/ai/textures/spawn/playable_now`）。
- `dungeon_themes`：**四个槽位名 `RUINS`/`CATACOMBS`/`MINE`/`ICE` 是引擎按名查权重的 key，不能改**。只改每个槽位的 `name`/`note`/`mob_distribution`。
- `item_types`：掉落物按新故事换。
- `meta`：说明文字按新故事改。

**前端代码表同步（只增不删 + 查重）**：

| 表 | 位置 | 加什么 |
|----|------|--------|
| `MOB_ARCHETYPES` | mapConfig.ts | 新野怪类型（白名单） |
| `ENTITY_TYPE_ZH` | mapConfig.ts | 新野怪中文名 |
| `ENTITY_SPRITE_KEY` | mapConfig.ts | 新野怪 → sprite key |
| `SPRITE_ANIM` | assets.ts | 新野怪动画帧对（从 `assets/tilesetAnim.ts` 的 `TILE_ANIM_ID` 挑，**逐帧目视确认**） |
| `NPC_DIALOG_ZH` | mapConfig.ts | 新 NPC dialog key → 中文名 |
| `THEME_BY_MAPNAME` | mapConfig.ts | 新图 theme（**按关卡 slug 登记**，中文名可加可不加） |
| `MAP_MOB_LEVEL_RANGE` | mapConfig.ts | 新图等级区间——**旧表已有同 slug 就改值，别加第二行** |
| `QUEST_MAP_SLUGS` | entry.ts + mockHost.ts | **别动！** slug 是跨故事共享的，加中文显示名会跟旧 key 撞（TS 重复 key 后者覆盖前者，会打坏别的地图集）。显示名只写在地图 JSON 的 `name` 字段 |

> `THEME_BY_MAPNAME`/`currentTheme()` 的查表 key 是**关卡 key（slug，来自 `currentLevelName`）**，不是中文显示名。按 slug 登记，中文显示名可作为兜底双写。

## 6. quests.json 重写

schema 见 [API文档.md](API文档.md)。换故事时的换法：

- **任务结构保留**（id/title/type/objectives/reward/flags），文案与数值全换。
- `objectives.kind` 只用引擎支持的五种：`kill`/`gather`/`arrive`/`talk`/`explore`。
- `map` 字段写**地图文件名小写驼峰**（`mulberryTown`）。
- `kill.target` 写的字符串要能在野怪头顶名中 includes 命中（如 `target:"伪人"` 能命中 `伪人·学生(值日生)`）。
- `talk` 的 `target`+`uid` 用 §4.2 复用过的 NPC uid。
- `arrive`/`explore` 的 x/y 是**世界米坐标（图心原点）**，写完按地图尺寸范围表卡边界。
- `flags.done` 若沿用旧 key（`q01_done`），意味着老玩家的进度会延续——新故事**建议换前缀**（如 `ht_q01_done`）避免旧进度污染。

## 7. 事件重写

- 事件文件 `events/maps/<地图名>.events.json`，文件名与地图主名严格一致。
- 触发器只用引擎实现的三种：`enter_map`/`interact`/`area_enter`；条件只用 `flag_check`（其余是死事件）。
- 脚本 `events/scripts/*.ts` **必须带故事前缀**（赦夜人 `SY_`、黑塔 `HT_`），因为全插件共用一个 `eventScripts/` 目录，不带前缀会撞名。`import ... from "../shared/_ctx"` 在同步时会被改写成 `./_ctx`。
- 复杂剧情节奏放 `run_script` 指向的 TS 脚本里；纯 toast/subtitle/set_flag 用声明式动作即可。
- 写完先跑校验器（见 §9）。

## 8. 三份副本同步

改了 `workshops/<故事>/events/` 后：

| 源 | 副本 | 方式 |
|----|------|------|
| `events/scripts/*.ts` | `vue/src/eventScripts/` | 复制过去（把 `../shared/_ctx` 改成 `./_ctx`）；可参考 `.cache/sync_sheye_event_scripts.py` 写个自己的同步脚本 |
| `events/maps/*.events.json` | `vue/public/events/maps/` + `ui/events/maps/` | 手动复制 |

- dev-server 的 `/story-data` 中间件直读 workshops 源文件，纯前端调试不强制同步；但 **`.tbg` 打包、`npm run build` 产物、真宿主都读副本——发布前必须同步**。
- `import.meta.glob("./eventScripts/*.ts")` 是构建期内联，同步后刷新页面即可生效。

## 踩坑实录（2026-10-23 黑塔改造）

1. **slug 表污染**：往 `entry.ts`/`mockHost.ts` 的 `QUEST_MAP_SLUGS` 加中文显示名映射（`lichLair: "陈曦的卧室"`），与旧表 key 全撞 → TS 对象重复 key 后者覆盖前者，会打坏另两套地图集。**回滚**：显示名只写地图 JSON `name` 字段。
2. **`forestDungeon.json` 不存在**：地图集只有 1~5 层，旧图靠 `createDungeon:true` 动态生成；事件 teleport 指向无层号名会**静默切图失败** → 指到 `Forest Dungeon 1`。
3. **`MAP_MOB_LEVEL_RANGE` 追加块与旧条目重复** → esbuild 报 Duplicate key。只增不删也要**先查重**。
4. **脚本中文引号**：`toast("小满："你记得他…"", "gold")` ——引号里再嵌裸 `"` 直接破坏 TS 字符串语法。对话引号一律用全角 `‘’` 或 `“”`。
5. **Python 关键字**：改造脚本里 `def`/`class` 是保留字，做 dict key 要写 `**{"def": v}`，做参数名要换名（`dfn`/`klass`）。
6. **theme 表 key**：`THEME_BY_MAPNAME`/`currentTheme()` 查表 key 是**关卡 slug**，不是中文显示名；旧表用显示名、靠 `getThemeForMapName` 的正则兜底。新故事按 slug 登记（可加中文名双写兜底）。
7. **`entity_types.json` 的 `meta`**：复制来的说明文字会残留旧故事痕迹（「地精/巫妖」），记得改。
8. **通用拾荒物件**：原集遗留的 `斧头`（`pickup_item`）这类通用物件容易漏改——**按 full_name 全量 grep 一遍**。
