# 地图集规范（toonflow-field-survival）

> 动地图/事件/脚本前必读。规范分两类：**引擎硬约束**（现状限制，违反=不生效）和
> **工程规范**（一致性要求，违反=难排查/难维护）。
> 配套：[地图制作指南.md](地图制作指南.md)（怎么做）、[API文档.md](API文档.md)（接口细节）。

---

## 严重违规事项
- 把地图集独有的业务写到插件里（地图集自己的ai 和触发器和事件和ui 设计应该在地图集里面编写）
- 在编辑地图集时，插件尽量不改，改也得按着通用函数和接口的方向修改


## 1. 总则

1. **正本唯一**：`workshops/toonflow-field-survival/map_design/<故事名>/` 是唯一正本。
   插件内的一切副本（public/events、ui/events、src/eventScripts、ui/maps）都是派生物，
   **可以整个删掉重建，不允许手改后不同步**。
2. **零代码改 game**：剧情/节奏/数值推进只用 JSON + TS 脚本，不改引擎源码。
3. **flag 唯一来源是玩家卡**（`t_plugin_session_data`）：story.json、地图 JSON、事件文件
   都不存任何运行时进度状态。
4. **AI 可写可校验**：所有内容必须过 `validate_events.mjs`，不靠人肉 review 语法。

---

## 2. 目录规范

| 路径 | 规范 |
|------|------|
| `compiled_dawnlike.json` / `entity_types.json` / `images/` | 只读公共资源，从 `base/` 复制，**不要按故事单独改** |
| `maps/*.json` | 一个文件一张图；主名 = 小写驼峰关卡 key；备份进 `maps/bak/` |
| `maps/first.map.json` | 每集一份，声明起始图 |
| `maps/prefabs/` `maps/utils/` | 预制件/模板对象，编辑器用，运行时不解析 |
| `events/maps/<map>.events.json` | **文件名与地图 JSON 主名严格一致** |
| `events/scripts/*.ts` | 加故事前缀（赦夜人 `SY_`，通天传授 `E01_`），全插件共用一个运行目录 |
| `events/shared/_ctx.ts` | 三故事共用同一份，改动需评估全线影响 |
| `story.json` | 只存 `{storyName, sessionId, worldId}` |
| `bak/` `test_data/` | 随便放——打 .tbg 时自动排除；但别把要上线的内容放这里 |

## 3. 命名规范

| 对象 | 规则 | 正例 | 反例 |
|------|------|------|------|
| 地图文件名 | 小写驼峰 | `mulberryDungeon1.json` | `MulberryDungeon1.json`、`冥夜走廊一层.json` |
| 关卡英文名（portalID/teleport/first.map.json 的 value） | 带空格 Pascal | `Mulberry Forest`、`Mulberry Dungeon 2` | `mulberryForest`、`桑林` |
| 中文显示名 | 地图 JSON 顶层 `name` | `桑镇`、`冥夜走廊·一层` | （拿中文名当 key） |
| 事件 id | `E<序号>_<语义>`，同文件唯一 | `E07_to_forest` | 重复 id、无序号 |
| 脚本文件 | 故事前缀 + 事件号 | `SY_E08_wood_at.ts` | `wood.ts`（会撞名） |
| flag key | 小蛇形 + 语义前缀，见 §6 | `phase_1_done`、`q01_done` | `flag1`、中英混拼 |
| eventZones/zone | 与事件 trigger.zone、questGatherMap 三处一致 | `夜采药圃` | 同义不同名（「药圃」vs「夜采药圃」） |

## 4. 引擎硬约束（写事件前必读）

以下按 `eventEngine.ts` / `mapConfig.ts` 当前实现列出，**踩了不会报错，只会静默不生效**：

| # | 约束 | 后果 |
|---|------|------|
| 1 | 只实现 3 种 trigger：`enter_map` / `interact` / `area_enter` | 白名单里另外 5 种（step_on/flag_set/kill_count/turn_count/custom）写了是**死事件** |
| 2 | 只实现 1 种 condition：`flag_check` | phase_done/level_gte/random 不判定（恒真通过），别依赖 |
| 3 | `call_action` / `registerAction` 未实现 | 自定义动作链路整个是 v0.2 占位 |
| 4 | `llm_speak` / `ctx.llm.speak` 是占位 | 返回空串——NPC 对话别走它，用 toast/subtitle |
| 5 | `ctx.npc.setLabel/move/faceTo` 是空实现 | 脚本里调用不报错但什么都不发生 |
| 6 | `run_script` 的 `args` 不透传 | 需要参数请写死在脚本里或读 flag |
| 7 | 非 repeat 事件**条件不满足也消耗一次机会**（ firedIds 先记入后判定） | 「条件不满足下次再判」的写法无效；切图/重载才重置 |
| 8 | repeat 事件 3 秒冷却，且条件不满足也进冷却 | 采集类不要叠 condition |
| 9 | teleport/portal 目标吃**关卡英文名** | 写中文名或文件名 → 静默失败/回退 |
| 10 | 击杀进度没有 trigger 挂载点 | 击杀奖励/掉落一律走野怪对象属性 `bounty`/`dropTable`，击杀任务走后端任务系统 |
| 11 | 上报关卡列表只能报真实存在的关 | 后端 `reportLevels` 兜底只报当前关，**绝不能拼 sysMapNodes**（后端回显→回声环→地图面板一排同名关卡） |
| 12 | 事件引擎与后端共用同一份 t_plugin_session_data | 后端写 flag 后前端缓存陈旧 → 切图时 invalidateFlagCache；脚本外不要直写 pluginData |

## 5. 地图内容规范

| 项 | 规范 |
|----|------|
| 瓦片层 | 命名 `Tile Layer 1..N`，**≤5 层**；超出请合并。层走烘焙渲染，不要手工逐格 decoration |
| 对象层 | 有且只有一个 objectgroup（`Actors`）；读取只取第一个 |
| 出生点 | 每图**恰好一个** `PLAYER`/`SPAWN_POINT`（多个取最后一个，意外双生点=玩家位置飘） |
| 出口 | `LEVEL_TRANSITION`/`LADDER` 必带 `portalID`（英文名）；成对出现（A→B 就有 B→A），否则玩家回不去 |
| eventZones | 区域名三处一致（地图/事件/questGatherMap）；坐标用瓦片；矩形优先圆形 |
| 顶层自定义字段 | `name`/`theme`/`narration`/`notes`/`eventZones` 必须随地图一起维护；Tiled  round-trip 后检查没被抹掉 |
| 地图尺寸 | 新增图建议 ≤80×80（进图卡顿与面积正相关）；大图先评估 |
| 对象数量 | Actors 层对象别过千（每个 NPC/野怪都是一个实体） |
| story.json | 只三个字段，不加业务数据 |

## 6. flag 规范

1. **单一存储**：事件引擎的 flag 全在 `t_plugin_session_data` 的 `player_flags`（一个对象）里；
   后端任务/系统面板写的是同库其它 key。**任何脚本不得绕过 `ctx.save` 直写 pluginData。**
2. **命名**：小写蛇形 `phase_<n>_done` / `phase_<n>_active` / `q<n>_done` / `met_<npc>` /
   `rumor_<topic>` / `map_locked_<mapFile>`。禁止 `flag1`、中英混拼、临时语义命名。
3. **类型一致**：同一个 key 全站只写一种类型（校验器会 warn 多类型写入）。
   boolean 用 true/false，不要用 "true" 字符串或 1/0。
4. **先删后传**：改了 `flags.done` 语义或清空旧进度 → CLI `--remove -k "map_visual:<故事名>" -story "<故事名>"` 再重传，避免新旧数据混。
5. 完成态一律落到 flag（如 `phase_1_done`），不要在脚本里闭包计数。

---

## 7. 坐标规范

1. 所有跨系统坐标（teleport 落点、任务 arrive 目标、实体位置）都是**世界米、图心原点**。
2. Tiled 里放对象用像素/瓦片没问题，但写 teleport/arrive 时必须先换算（公式见
   [地图制作指南.md](地图制作指南.md) §6），并按各图范围表卡边界。
3. eventZones 在地图 JSON 里写**瓦片坐标**（不带 32 倍），运行时统一减半图宽/高。
4. 落点避开墙与地图边缘：森林/墓地的中心格可能是墙，传送坐标宁可靠墙内侧 1~2 米。

## 8. 同步与发布规范

### 8.1 事件数据的三份副本

改了 `workshops/<故事>/events/` 后，必须同步到插件副本，否则 dev/真机行为不一致：

| 源（正本） | 副本 | 同步方式 |
|------------|------|----------|
| `events/scripts/*.ts` | `plugins/toonflow-field-survival/vue/src/eventScripts/` | `python .cache/sync_sheye_event_scripts.py`（赦夜人；自动把 `../shared/_ctx` 改写为 `./_ctx`）；通天传授手动同步 |
| `events/maps/*.events.json` | `vue/public/events/maps/` + `ui/events/maps/` | 手动复制（校验器第 7 项会比对，不一致会 warn） |

> dev-server 的 `/story-data` 中间件直读 workshops 源文件，所以**只调前端时同步不是强制的**；
> 但 `.tbg` 打包、`npm run build` 产物、真宿主都读副本——**发布前必须同步**。
> `import.meta.glob("./eventScripts/*.ts")` 是构建期内联：同步后刷新页面即可；
> 若同时改了 vite.config.ts 要重启 dev-server。

### 8.2 改后端（entry.ts）的三步收尾

1. `plugins/toonflow-field-survival/vue` 下 `npm run build` → 产出 `../ui/game.html`
2. `entry.ts` 用 esbuild 编成 `entry.js`（ESM 单文件，无 import / `import.meta`）
3. `entry.js` 与 `ui/game.html` 同步到两份 installed 副本，`md5sum` 三方一致：
   - `toonflow-app-run-db/plugins/1/com.toonflow.minigame-field-survival/`
   - `toonflow-game-app/Toonflow-game/plugins/1/com.toonflow.minigame-field-survival/`

**缓存坑（务必知道）**：

- 真宿主后端影子模块按 `<pluginKey>.<mtime>.mjs` 热重载 → 编完 entry.js 即生效，不用重启。
- **dev-host（`npm run debug -- --conn`）例外**：`loadEntryModule()` 里 `if (entryMod) return entryMod;`
  进程内永久缓存 → **改了 entry.ts 必须重启 dev-server**，否则你测的还是旧后端。

### 8.3 发布链路（地图/事件上线）

```
1. 改 workshops 正本
2. node .cache/validate_events.mjs <故事名>        # 0 error
3. 同步三份副本（§8.1）
4. （改了后端才做）§8.2 三步收尾
5. dev 全量过一遍：npm run debug -- --story <故事名> --conn
6. python -m toon_plugins plugin_session_data -i plugins/toonflow-field-survival \
     -u workshops/toonflow-field-survival/map_design/<故事名> -story "<故事名>"   # 打 .tbg + 上传
7. 结构性变更（删图/改 storyName/改 flag 语义）先 --remove 再 -u
8. 真宿主进游戏验证；需要分发时装插件：python -m toon_plugins plugins -i toonflow-field-survival
```

## 9. 禁止事项（反模式清单）

| 禁止 | 原因 |
|------|------|
| 用中文名做关卡 key / 前缀匹配 | 归一化后空串 → 恒真匹配、「桑镇」「桑林」判同图 |
| 写白名单外 trigger/condition/action | 静默不生效，且校验器直接 error |
| `while(true)` / `for(;;)` / 脚本内直写 pluginData | 校验器 error；直写破坏 flag 缓存一致性 |
| 在 story.json / 地图 JSON 里存进度 flag | 违反「flag 唯一来源=玩家卡」 |
| 后端 reportLevels 拼 `sysMapNodes` 上报关卡 | 后端回显→回声环→地图面板一排同名关卡 |
| 手改插件内副本当正本 | 下次同步/打包即被覆盖，且两份副本漂移 |
| 改 `events/shared/_ctx.ts` 只改一个故事 | 三故事共用，白名单/类型漂移会连锁翻车 |
| 把要上线内容放 `bak/` `test_data/` | 打 .tbg 自动排除，上线即缺失 |
| 新增 `.tbg` 之外的静态资源类型不改 vite 中间件 | `/story-data` 中间件有文本/二进制分支（二进制 octet-stream 原样回），新类型不同步会损坏字节 |
| teleport/任务目标坐标不卡范围 | 不报错，只表现为寻路原地不动/落点被夹 |
