# 技能特效设计 V2 —— 战斗状态可视化（仇恨 / 流血 / Buff 图标 / 攻击范围）

> **本文档角色**：V2 的**设计说明**——回答「做什么、为什么这样做、数据怎么走、改哪几处、怎么验收」。
> **前置文档**：`../V1/游戏特效.md`（现有特效体系全貌）、`../V1/技能属性特效.md`（effects_type 与法术图标）。
> **落地清单**在同目录 `实施与验收清单.md`（逐条 task + 测试用例）。
>
> 状态：**设计完成，尚未实施**（2026-11-13）。
>
> **范围**：R1~R4 = 头顶状态徽章层（跟随实体）；**R5 = 地面攻击范围指示层**（一次性、挂在施放点）。
> 两层互相独立，不共用数据模型。

---

## 0. 一句话结论

**在实体头顶加一层「状态徽章层」**：宿主导威生成徽章数据（血滴 / 环标图标 / 仇恨感叹号），前端只读渲染；
所有颜色、图标、兜底文案由宿主按统一规则产出，**前端不做任何业务判断**。

## 1. 需求 → 设计目标 → 验收

| # | 原始需求 | 设计目标 | 验收口径 |
|---|---|---|---|
| R1 | 野怪感知到用户产生仇恨时要有标识（头上红色感叹号） | 敌怪进入 `aiState === "chase"` 时，头顶出现**红色感叹号**，脱战即消失 | 怪进入 4m 探测半径 → 感叹号出现；玩家退出 4m → 消失 |
| R2 | 用户被攻击要有流血效果：头上血滴符号 + **粉红色**扣血值；**粉红色圆圈**圈住「被攻击技能最新图样」，兜底显示「伤」 | 玩家受击 → 头顶粉色血滴 + 粉色圆圈（圈内=最近一次致伤技能的图标，无图标则显示「伤」）+ 粉色 `-N` 飘字 | 玩家掉血时三者同时出现且颜色为粉红；无技能来源时圈内为「伤」 |
| R3 | 野怪被攻击要有流血效果：头上血滴符号 + **红色**扣血值；**红色圆圈**圈住「被攻击技能最新图样」，兜底显示「伤」 | 同 R2，受击方为敌怪时颜色取红 | 敌怪掉血 → 红色血滴 + 红色圆圈 + 红色 `-N` |
| R4 | buff 生效期间头顶出现**绿色血滴**，**绿色圆圈**圈住 buff 技能最新图样，兜底显示「buff」 | buff 施加 → 头顶绿色血滴 + 绿色圆圈（圈内=buff 技能的 effects_type 图标，无则「buff」），持续到 buff 失效 | 施放 buff 技能 → 徽章出现；buff 到期 → 徽章消失 |
| **R5** | **攻击范围可视化**：V1 全是圆形范围攻击；V2 增加**朝向攻击类型**（只攻击面前的敌人），施放时出现与攻击范围**同样大小**的**粉红色半透明扇形**；圆形范围攻击也要每次出现**粉红色圆形区域**（透明度高一点、隐约可见） | 每个技能可配置 `attack_shape`（`circle` / `cone`）。施放瞬间在施放者位置画出**范围指示区**：cone → 朝向扇形；circle → 圆形。均为粉红色半透明 | 放 cone 技能 → 面前出现粉红扇形，**只命中扇形内的敌人**；放 circle 技能 → 出现粉红圆形；两者形状与实际命中范围**完全一致**（指示区 = 判定区） |

**R1~R4 的共同骨架**：头顶一条横向徽章行，每枚徽章 = `[血滴符号] + [圆圈(内含图标/文字)]`。
R1 的感叹号是**独立徽章**（无血滴、无圆圈），因为它是「状态」而不是「事件」。

**R5 与 R1~R4 是两套独立机制**：R1~R4 是**头顶状态层**（挂实体、跟随实体、随实体消失）；
R5 是**地面范围指示层**（挂施放点、按 tick 衰减、是一次性效果）。两者不共用数据模型。

### 2.2 缺口（本设计要补的）

| 缺口 | 证据 | 影响 |
|---|---|---|
| **宿主的飘字没有颜色** | `entry.ts:1188` `s.floaters.push({ id, text, x, y, life })` —— **不带 color** | 玩家/野怪受伤都是**白字**，R2/R3 的「粉红/红色扣血值」根本不存在（V1 文档里写的「红色 #ff5a5a」只存在于 mockHost 桩，宿主路径从没生效过） |

| **敌怪仇恨没有可视化** | `entry.ts:2345` `ex.aiState = "chase"` 只是一个字符串，前端无人读 | R1 无载体 |

| **技能没有「攻击形状」配置项** | `SkillSlot`（`entry.ts:394`）只有 `type`/`range`/`lv`/`buff_type`/`effects_type`；`skillMeta`（`entry.ts:460`）同样 | 需要新增 `attack_shape` 字段，并打通「技能面板配置 → skillMeta 持久化 → buildSkills 读回 → 施放时生效」全链路（见 §5.7） |
| **施放时玩家朝向不一定是「面向敌人」** | 玩家朝向由移动方向决定（`App.vue:4519`：`me.facing = dx>0?0:dx<0?180:dy>0?90:270`），**不因瞄准而变** | 施放 cone 技能时必须**先算朝向再判定**：朝向取「玩家→目标」方向，或取玩家当前 facing（见 §5.6 决策点 D7） |

## 3. 总体方案

```
                      ┌──────────────────────── entry.ts（宿主权威）────────────────────────┐
   伤害结算 damage()  │  ① 判定受击方阵营（player / 敌怪）                                        │
   ────────────────▶ │  ② 写飘字颜色（粉红 / 红）                                              │
                      │  ③ 更新受击方的 hurt 徽章（图标 = 致伤来源技能的 effects_type 图标）      │
                      │  ④ 技能/物品施放 → 写施放者的 buff 徽章（图标 = 该 buff 的 effects_type） │
   敌人 AI            │  ⑤ aiState === "chase"（已有字段，前端只读）                             │
                      └───────────────────────────────┬────────────────────────────────────────┘
                                                      │ state.entities[].headBadges
                                                      │ state.entities[].aiState
                                                      │ state.floaters[].color
                                                      ▼
                      ┌──────────────────────── App.vue（只读渲染）────────────────────────┐
                      │  drawEntity / drawMonster → recordHeadBadge(e, x, y)（只记锚点）        │
                      │  drawHeadStatusLayer(ctx)（在 VFX 层 + 血条层之后统一补画）              │
                      └─────────────────────────────────────────────────────────────────────┘
```

**铁律**：徽章的**内容**（有没有、什么颜色、什么图标、兜底什么字）**全部由宿主决定**；
前端只做「把宿主给的东西画出来」。这与 v3 网络通信的「状态必须是同一份」是同一条纪律。

## 4. 数据模型

### 4.1 宿主侧（`entry.ts`）

```ts
/** ★ V2 头顶状态徽章（宿主权威，前端只读渲染） */
export interface HeadBadge {
  /** hurt=被打（血滴）/ buff=增益生效中（绿血滴） */
  kind: "hurt" | "buff";
  /** 徽章主色：玩家受击=粉红 / 敌怪受击=红 / buff=绿 */
  color: string;
  /** 法术图标相对路径（相对 ui/，如 images/spells/fire/fireball.png）；缺省=用 label 兜底 */
  icon?: string;
  /** 图标兜底文字：hurt 缺省 "伤"、buff 缺省 "buff" */
  label?: string;
  /** 产生时刻（tick） */
  bornTick: number;
  /** 到期时刻（tick）；缺省=不自动过期（仅 hurt 会出现这种情况的兜底） */
  expireTick?: number;
}
```

挂载位置：`Entity.headBadges?: HeadBadge[]`（`entry.ts` 的 `interface Entity` 追加字段）。

### 4.4 R5 攻击范围指示（宿主侧）

```ts
/** ★ V2 攻击形状：circle=圆形范围（V1 行为）/ cone=朝向扇形（V2 新增，只打面前） */
export type AttackShape = "circle" | "cone";

/** ★ V2 攻击范围指示区（一次性，挂在施放点，不跟随实体） */
export interface RangeIndicator {
  id: string;
  /** circle | cone */
  shape: AttackShape;
  /** 世界坐标：施放者位置（米） */
  x: number;
  y: number;
  /** 半径（米）—— circle 用作半径，cone 用作扇形半径 */
  radius: number;
  /** 朝向（角度制，0=右 90=下 180=左 270=上）——cone 用；circle 忽略 */
  facing: number;
  /** 扇形半角（度）——cone 用；circle 忽略 */
  halfAngleDeg: number;
  /** 剩余生命（tick） */
  life: number;
  total: number;
}
```

挂载：`FieldSurvivalState.rangeIndicators?: RangeIndicator[]`（新增顶层字段）。

### 5.1 `floater()` 支持 kind / color（`entry.ts:1187`）

```ts
function floater(s: FieldSurvivalState, text: string, x: number, y: number,
                 opts?: { kind?: string; color?: string }) {
  s.floaters.push({
    id: `f_${s.tick}_${Math.random().toString(36).slice(2, 6)}`,
    text, x, y, life: 24,
    kind: opts?.kind,
    color: opts?.color,

  if (s.floaters.length > 30) s.floaters = s.floaters.slice(-30);

```

**为什么必须改**：前端 `App.vue:6350` 已经是 `const fill = f.color || "#fff"` —— 前端早就支持按 color 上色，
只是宿主从没给过 color。**这是 R2/R3 的颜色需求能成立的前提**，且是纯增量（不传 opts 的老调用点行为不变）。

### 5.2 `damage()` 产出飘字颜色 + hurt 徽章（`entry.ts:1404`）

签名扩展（**只加可选参数，不破坏 8 个既有调用点**）：

```ts

                attacker?: Entity,
                src?: { icon?: string; label?: string }) { ... }
```

`amount > 0` 分支里新增：

```ts
const isPlayerHit = target.side === "player";
```

### 5.4 buff 徽章 + buff 生命周期

新增 helper：

```ts
/** 施加 buff：写 ent.buffs（已有语义）+ 写头顶 buff 徽章 + 设置到期 tick */
function applyBuff(s: FieldSurvivalState, ent: Entity,
                   opts: { name: string; icon?: string; durationTicks?: number }) {
  const dur = Math.max(1, Math.round(opts.durationTicks ?? BUFF_DURATION_TICKS));
  ent.buffs = Array.isArray(ent.buffs) ? ent.buffs : [];
  if (!ent.buffs.includes(opts.name)) ent.buffs.push(opts.name);
  (ent as any).buffUntilTick = s.tick + dur;
  setHeadBadge(s, ent, {
    kind: "buff", color: BUFF_COLOR,
    icon: opts.icon, label: BUFF_LABEL,
    expireTick: s.tick + dur,
  });
}
```

- 调用点：`entry.ts:7494`（AI 角色放 buff 技能）、`entry.ts:6225`（玩家技能 fx=buff）、
  `entry.ts:7167`（系统面板技能 fx=buff）、`entry.ts:4757`（物品 type=buff）。
- **玩家 buff 技能此前根本不入 `ent.buffs`**（只有 AI 分支 push 了）→ 顺手补齐，AI 的 `sensor.ts:66` 也能读到玩家 buff。

**到期清理**（放在 `step()` 的实体循环附近，`entry.ts:2378` 一带）：

```ts
// ★ V2：buff 到期 → 移除 buffs 列表项 + 移除头顶 buff 徽章
if ((e as any).buffUntilTick != null && s.tick >= (e as any).buffUntilTick) {
  (e as any).buffUntilTick = undefined;
  const list = Array.isArray((e as any).buffs) ? (e as any).buffs : [];

}
```

### 5.6 【R5】攻击命中判定：支持朝向扇形

这是 R5 的**核心**——指示区必须与判定区**完全一致**，否则玩家看到扇形却打到了扇形外的怪，
比没有指示更糟。

新增两个纯函数（放在 `entry.ts` 靠近 `dist()` 的位置）：

```ts
/** ★ V2 角度差（度）：把两个角度归一到 [-180, 180] */
function angleDiffDeg(a: number, b: number): number {
  let d = ((a - b) % 360 + 540) % 360 - 180;
  return d;
}

/**
 * ★ V2 攻击形状命中判定（唯一真源，指示区与判定共用）
 *   circle → 半径内全部命中（V1 行为，向下兼容）
 *   cone   → 半径内 **且** 在朝向 ±halfAngleDeg 内命中
 * @param shape 攻击形状
 * @param fx,fy 施放者坐标（米）
 * @param facing 施放者朝向（角度制，0=右 90=下 180=左 270=上）
 * @param halfAngleDeg 扇形半角（度）
 * @param tx,ty 目标坐标（米）
 * @param radius 作用半径（米）
 */
function inAttackRange(
  shape: "circle" | "cone", fx: number, fy: number, facing: number,
  halfAngleDeg: number, tx: number, ty: number, radius: number,
): boolean {
  const dx = tx - fx, dy = ty - fy;
  const d = Math.hypot(dx, dy);
  if (d > radius) return false;
  if (shape !== "cone") return true;
  // 目标与施放者几乎重合 → 距离判定已通过，方向无意义 → 命中
  if (d < 0.0001) return true;
  // 施放者朝向（角度制：0=右 90=下）→ 目标方位角
  const targetAngle = (Math.atan2(dy, dx) * 180) / Math.PI;
  return Math.abs(angleDiffDeg(targetAngle, facing)) <= halfAngleDeg;
}
```

**施放朝向怎么定**（决策点 D7，见 §9）：

```ts
/**
 * 计算 cone 技能的实际朝向与判定基准点。
 * ★ 朝向来源优先级：
 *   1) 玩家当前 facing（客户端上报的实时位姿 params.player.facing）
 *   2) 若有明确目标（params.targets[0] / params.targetId）且玩家几乎没动过
 *      → 用「玩家→目标」方向（保证「只攻击面前的敌人」符合直觉）
 */
function resolveCastFacing(
  params: any, castRef: { x: number; y: number }, fallbackFacing: number,
  target?: { x: number; y: number } | null,
): number {
  const poseFacing = num(params?.player?.facing, NaN);
  if (Number.isFinite(poseFacing)) return poseFacing;
  if (target) {
    const dx = target.x - castRef.x, dy = target.y - castRef.y;
    if (Math.hypot(dx, dy) > 0.01) return (Math.atan2(dy, dx) * 180) / Math.PI;
  }
  return fallbackFacing;
}
```

**改造 3 个施放点**（把 `dist(...) < SKILL_RANGE_M` 换成 `inAttackRange(...)`）：

| 施放点 | 现状 | 改后 |
|---|---|---|
| `case "skill"`（`entry.ts:6216`） | `s.entities.filter(e => e.side==="enemy" && e.alive && !e.deathMs && dist(castRef, e) < SKILL_RANGE_M)` | 先算 `shape` / `facing` / `halfAngle`，再 `inAttackRange(shape, castRef.x, castRef.y, facing, half, e.x, e.y, SKILL_RANGE_M)` |
| `case "sys_use_skill"`（`entry.ts:7162`） | 同上（用 `meSk` 作基准） | 同上 |
| `case "ai_command.useSkill"`（`entry.ts:7481`） | `dist(ent, e) <= SKILL_RANGE_M` | 同上（`ent` 的 facing 来自 `(ent as any).facing`） |

**普攻（`case "attack"`，`entry.ts:6271`）默认仍为 circle** —— 普攻是「点谁打谁」，
不该被朝向限制。若用户希望普攻也能配 cone，走 §5.7 的同一套配置。

**绘制规格**（严格按需求：「透明度可以高一点，隐约看见就行」）：

| 项 | 规格 |

**2.5D 压缩注意**：`wz2py` 带 `DEPTH` 压缩（`App.vue:5999`），而半径是各向同性的。
处理方式：绘制时用 `ctx.save(); ctx.translate(px, py); ctx.scale(1, DEPTH); ctx.arc(0, 0, r, ...)` ——
先平移到施放点，再纵向压 DEPTH，再画正圆 → 屏幕上呈现为**贴合地面的椭圆**（正确透视）。

**绘制顺序**（`App.vue` 的 `render()`）：

```

```

理由：指示区画在**实体之下**（不能盖住怪和玩家），但在 **VFX 之上**（要压在地面装饰物之上才看得清）。

**为什么指示区要在实体层之前**：它是「地面投影」，盖在角色身上会让人误以为角色被染色。

### 6.8 【R5】渲染层的坐标一致性检查（关键）

扇形指示区用 `facing`（角度制 0=右 90=下），而 `wz2py` 有 DEPTH 压缩 —— 二者组合后，
**扇形角度在屏幕上不再是几何角**。处理方式：`ctx.scale(1, DEPTH)` 压缩后，
Canvas 的 `arc()` 仍在压缩后的坐标系里画，此时角度参数是**压缩前世界坐标系的角**，
绘制结果会被自动纵向压缩 → 与地面上的世界坐标一致。**这是正确做法，不要改成"手动算屏幕角"。**

> 自检方法：站在怪正右侧放 cone 技能 → 扇形应水平指向右侧（不歪）；
> 站在怪正下方放 cone 技能 → 扇形应指向下方（纵向被压缩变短，符合 2.5D 透视）。

| **D1** | 「被攻击技能最新图样」是否包含**普攻**（用武器 effects_type 图标） | **包含**（普攻有武器图标时用图标，无则兜底「伤」） | 不包含的话普攻永远显示「伤」，R2/R3 的「技能图样」在普攻占比高的战斗里几乎看不到 |
| **D2** | 圆圈内是**图标**还是**技能名文字** | **图标**（需求原文是「图样」），文字只做兜底 | 用文字会占位大、可读性差，且系统图标不统一 |
| **D3** | buff 到期时间 | **默认 30s（300 tick）**，可被技能参数覆盖 | ⚠️ **行为变更**：现状 buff 永不过期（`entry.ts:7495` 只 push 不删）。加到期 = buff 真的会被移除。需确认；若不改，则 buff 徽章常驻（观感差但不破坏逻辑） |
| **D4** | 敌怪是否也显示「被自己人打」的粉红 | 否：敌怪一律红、玩家一律粉红 | 敌我分色是需求原文 |
| **D5** | 队友（ally）受击的颜色 | 按「非玩家 = 红」处理 | 需求未提 ally，取红最省事 |
| **D6** | 徽章是否需要随 zoom 缩放 | **跟随缩放**（与实体同缩放，用 `sx` 换算尺寸），否则 zoom=40 时徽章相对过小 | 视觉一致性 |
| **D7** | 【R5】cone 技能的朝向以谁为准 | **玩家当前 facing**（客户端上报的实时位姿），无 facing 时退化为「玩家→最近目标」方向 | 玩家站着不动时 facing 是上一次移动方向 → 面朝哪就打哪。若改成「永远对准最近目标」，则「只攻击面前的敌人」会退化成「自动选最近的」，失去手动控制的意义 |
| **D8** | 【R5】指示区与判定区的一致性保障 | **共用常量 + 共用函数**：半径统一 `SKILL_RANGE_M`，半角统一 `CONE_HALF_ANGLE_DEG`，判定与指示都读同一组值 | 若将来允许「每技能单独配半径」，必须让 `pushRangeIndicator` 与 `inAttackRange` 读**同一个** `radius` 变量，不能各写一份 |
| **D9** | 【R5】物品（背包）是否也支持 `attack_shape` | **支持**（与技能同一套字段，物品也能是「扇形刀」） | 若不支持，物品的 `atk` 类永远是圆形，与技能行为不一致 |
| **D10** | 【R5】普攻（右键）是否受朝向限制 | **否**（普攻是「点谁打谁」，保持现状） | 若改成 cone，普攻会经常打空（玩家点了身后的怪，但朝向朝前）——体验倒退 |
| **D11** | 【R5】指示区是否也要给敌方（野怪）显示 | **否**（本期只做玩家侧） | 野怪 AI 走 `MOB_DETECT_M` 圆形感知，给它加扇形会牵动整条 AI 逻辑，收益低风险高 |

### 已识别的技术风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 前端从 `state.entities` 读 `aiState` 可能拿到**客户端权威怪**的旧值 | 感叹号延迟 1 tick 或不出现 | 宿主是权威且合并时宿主胜出（`App.vue:8554 hostAdopted` 分支）；最坏延迟 1 tick（100ms），可接受 |
| `state.floaters` 上限 30 条，战斗高峰挤掉 | 飘字丢失 | 现状问题，本设计不扩大；徽章不受影响（挂在实体上） |
| `entry.js` 与 `entry.ts` 不同步 | 部署后行为与设计不符 | 遵守「只改 entry.ts → esbuild → 拷安装副本」铁律 |
| **【R5】指示区画歪**（2.5D DEPTH 压缩导致角度失真） | 扇形指向错误 → 玩家按指示打却打不中 | `ctx.scale(1, DEPTH)` 后再画弧（§6.8）；自检「正右侧放技能 → 扇形水平朝右」「正下方放 → 扇形朝下且变短」 |
| **【R5】真机与 dev-host 行为分叉** | 桩是圆形、真机是扇形 → 调试时结论相反 | 桩必须同步引入 `inAttackRange`（§7 已强调） |
| **【R5】cone 技能在「玩家不动」时朝向是历史值** | 玩家以为面朝怪、实际朝别处 → 打空 | 面板提示「cone 技能按当前朝向判定」；或改为「施放瞬间自动转向最近目标」（属 D7 变体） |
