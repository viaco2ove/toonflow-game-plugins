插件通信方案选型总览
结论：实时动作保留 tick + 增量优化；回合制用指令-结算；挂机/AI短信用事件推送。优化顺序：语义 → 持久化 → 传输。
三层方案空间（可自由组合）
① 传输通道层（字节怎么送）
T1 HTTP 短轮询 ✅ 保留（现状通道）
T2 HTTP 长轮询 ❌ 不推荐（收益被 O1 覆盖）
T3 WebSocket 🟡 中期可选（断线体验）
T4 SSE ✅ 短信/通知推荐（单向推送）
② 协议语义层（装什么、何时发）
S1 高频全量镜像 ⚠️ 唯一通道=错
S2 增量/脏检查镜像 ✅ 第一优先（48KB→0）
S3 指令-结算(RPC) ✅ 回合制标准（tick 归零）
S4 事件推送+低频拉取 ✅ 通知/AI短信标准
S5 本地优先+权威同步 ❌ 红线（丢防作弊）
③ 传输格式层（字节怎么编码）
F1 JSON 明文 ✅ 现状（增量后体积非问题）
F2 二进制+压缩 🟡 远期（破坏宿主零理解）
组合示例：短信 = T4 SSE + S4 事件推送 + F1
动作游戏 = T1 + S2 增量 + O2/O3 + F1
