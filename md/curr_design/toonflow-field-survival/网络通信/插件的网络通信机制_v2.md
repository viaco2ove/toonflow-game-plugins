## 0. 一句话结论

- **实时动作游戏**（野外生存/假人对打）：保留 10Hz tick，叠加**增量回传 + 写库降频 + 动态降频 + 快慢锁**，成本可降 90%+（O1-O4 全部落地实测）；
- **回合/指令型**插件：用**指令-结算协议**（S3/P2），tick 归零（manifest `interaction:"turn-based"` + 模板，已落地实测）；
- **挂机/通知/AI 主动消息**：用**事件推送协议**（S4/P3，后端队列 + 插件 30s 轮询）——AI 主动短信已端到端实测（不再依赖 tick 心跳）；T4 SSE 作为延迟升级项保留设计；
- 优化顺序铁律：**先语义层 → 再持久化 → 最后传输层**（语义层拿走 90% 成本）。

## 1. 架构现状（保留部分，勿动）

```
插件前端 (iframe, 60002 game.html)
  │  rAF 60fps 渲染（移动端 30）；逻辑 10Hz（TICK_MS=100）
  │  SEND_MS：桌面 100ms / 移动 200ms；document.hidden 停发
  ▼  postMessage({type:'tf_plugin_tick', action, params})
宿主 (5175 ScenePlay.vue) —— 哑管道，只透传
  ▼  POST /plugin/tick
后端 (60002 tick.ts)
  │  ① 会话串行锁 tickLocks
  │  ② 读 session.stateJson + plugin_state（~48KB）
  │  ③ entry.js handle_action —— 权威游戏逻辑
  │  ④ writeback 写回故事动态数据（仅变化帧）
  │  ⑤ plugin_state 落盘【v2：节流+脏跳过，见 §3.1】
  ▼  返回 resultState（~48KB）
宿主 ──postMessage({type:'tf_plugin_state'})──► 插件渲染
```

**保留的既有优点**（这些是资产，任何优化不得破坏）：
- 权威状态在后端（防作弊 / 多端一致 / 换端不丢）；
- 宿主哑管道（插件生态零集成成本）；
- 前端本地预推进 + 宿主镜像位姿（消除坐标双写）；
- localEnemies epoch 增量上报 / walkGrid 仅切图上报；
- document.hidden 停发 / 409 failStreak 自愈 / 会话串行锁 / plugin_state 独立表（根治 clobber）。

## 3. 优化实施记录

### 3.1 O2 写库降频 —— ✅ 已实施（2026-11-01）

**位置**：`toonflow-game-app/src/routes/plugin/tick.ts`

**机制**：
```
PLUGIN_STATE_FLUSH_MS = 2000
pluginStateLastJson / pluginStateFlushAt（按 userId:sessionId:pluginId 记账）

forceSync（立即落盘）= 非 tick 命令 ∨ phase 变化 ∨ phase==over ∨ state.forceSync
否则：state 与上次落盘版本相同（挂机空转）→ 不写；
     有变化但距上次落盘 < 2s → 跳过本轮（下轮再判）。
```

**效果**：挂机写库 10 次/秒 → **≤0.5 次/秒**；无变化时 **0**。
**代价**：崩溃最多丢 2 秒进度（动作游戏可接受，退出/结算时 forceSync 兜底）。
**生效条件**：后端进程重启（tsx 直跑无热载，改动后首次重启生效）。

### 3.2 O1 增量回传（304 语义）—— ✅ 本文件实施（2026-11-01）

**机制**（同样在 tick.ts，与 O2 共享 serializedNow 快照）：

```
response.state = 无变化 && !forceSync ? null : resultState
```

- 前端收到 `state === null` → **跳过本帧渲染状态合并**（本地继续预推进，零开销）；
- 有变化 → 仍回**全量 state**（不做字段级 patch——合并语义二选一，全量替换最稳；
  48KB 只在有变化时才发，O1 的收益已拿走大半；字段级 patch 留给未来有需要时再升级）。

**为什么不做字段级 patch**：宿主是哑管道、前端合并语义必须全链路一致；patch 引入
"半新半旧 state" 风险，而"全量 or 空"的二值语义零歧义、实现一行。挂机场景两者收益相同（都归零）。

**兼容性**：`state:null` 只出现在 `action === "tick"` 且无变化的响应里；
sys_* 命令 / phase 变化 / 首帧永远带全量 state —— 前端所有既有消费路径不受影响。

### 3.3 O3 动态降频 —— ✅ 已实施（2026-11-01）

活跃（有输入/战斗）100ms → 挂机（3s 无输入无敌怪）500ms-1s → 后台 0。
放插件侧（App.vue 判定活跃度后动态拉长上报间隔）。

实现（`App.vue` `currentSendMs(ts)`）：
- 活跃判据：`phase==="playing" && (dx!==0 || dy!==0 || moveTo)`；
- 进入挂机档需持续 3s 无输入（避免停手瞬间掉帧感）；
- 回活跃档时 `lastSendAt=0`，**本帧立刻补发**（不丢一帧）。

实测（真实 5175 宿主 + 60002 后端）：
| 场景 | 时长 | tick 数 | 折算频率 |
|---|---|---|---|
| 挂机 | 30s | 28 | **≈0.93 req/s** |
| 按住方向键 | 3s | 30 | **10 Hz** |

### 3.4 O4 快慢锁拆分 —— ✅ 已实施（2026-11-01）

sys_brain/sys_chat（LLM 1-5s）与帧 tick 共用 tickLocks → AI 决策期间帧被堵。
拆 `fastLock`（帧 tick）与 `slowLock`（sys_* 慢命令）；两锁对 plugin_state 的最终
写库仍互斥（经 O2 的节流记账天然弱化）。

实现（`tick.ts`）：
```
const isSlowCmd = action.startsWith("sys_");
const lockFn = isSlowCmd ? withSlowLock : withSessionLock;
```

实测（短信端到端，真实链路）：
- `sys_chat`（含 LLM）耗时 **1927.663ms**；
- 同一时段帧 tick 响应耗时 **12~15ms**，全部正常返回；
- AI 回复正常：「第五次测试已收到，陈南璇确认回应正常。」

## 4. 分流协议（新插件选型）

| 插件形态 | 协议 | tick 频率 | 关键改动 |
|---|---|---|---|
| 实时动作（野外生存/假人） | S1+S2+O2+O3 | 10Hz 活跃 / 挂机 0.5-1s / 后台 0 | ✅ 已具备 |
| 回合/指令（卡牌/经营/RPG） | S3 指令-结算 | 0 | ✅ **P2 已实施**（manifest `interaction:"turn-based"` + 模板 `plugins/templates/turn-based/`，见 §7） |
| 挂机/通知（宠物/离线/**AI 主动短信**） | S4 事件推送 | 0（拉取 30s+ 或 SSE 即时） | 后端事件定时器 + T4 SSE 下行 |

**S4 的 AI 决策归属（重要）**：AI 上下文（性格/记忆/感知）在前端 `aiStates`，后端拿不到——
后端定时器只发「唤醒事件」，LLM 决策仍由插件前端跑（方案 A，AI 状态不迁移）。

**T4 SSE 的跨域中继（成败关键）**：插件 iframe（60002）嵌在 5175 里且无 JWT，iframe
开不了 SSE。正确链路：`后端 ──SSE──► 宿主(5175, 持 JWT) ──postMessage(tf_plugin_event)──► iframe`。

## 5. 红线（不要做）

- ❌ 游戏逻辑搬回前端（S5）——丢权威状态/防作弊/多端一致；
- ❌ WebSocket 全量重写链路——O1/O2 拿走 90% 成本，ws 只剩断线体验的边际收益；
- ❌ 字段级 patch 强上——合并语义歧义风险 > 收益（全量 or 空已覆盖主场景）；
- ❌ AI 主动消息挂 tick 心跳——实时语义做异步场景，成本全付体验差；
- ❌ 插件生态强推二进制格式——破坏宿主"零理解"优势。

## 8. P3 事件推送 + AI 主动短信 —— ✅ 已实施 + 实测（2026-11-01）

### 8.1 架构（S4 方案 A + T1 低频拉取）

```
后端编排器/定时器（未来接）            插件前端（AI 状态所在地，不迁移）
  │ POST /plugin/events op=push          │ 每 30s（页面隐藏 5min）：
  │ {type:"wake_sms",payload:{roleId,hint}}   │ POST /plugin/data get __plugin_events__
  ▼                                      ▼
  t_plugin_session_data  ◄────拉取并清空────┘
  (__plugin_events__ 队列，上限 64 条)      │ 有 wake_sms：
                                           ▼
                              wakeAiForProactiveSms(roleId, state, hint)
                              → 幽灵实体 + callBrainDetailed({proactiveSms:true})
                              → dispatchSmsDecision → 短信落库
```

**为什么不用 SSE（T4）**：插件 iframe 无 JWT 开不了 SSE，宿主中继要改 ScenePlay +
后端 wsHub，而 30s 轮询的成本是 30s 一次 ~120B 的 get——已接近零。SSE 的唯一收益是
把延迟从 ≤30s 降到即时，等有真实时效需求再升级（v2 §4 T4 跨域中继设计保留）。

### 8.2 实现清单

| 端 | 文件 | 内容 |
|---|---|---|
| 后端 | `src/routes/plugin/events.ts`（新增） | push/pop 队列 + `pushPluginEvent()` 导出（编排器未来直接调）；`/plugin/events` 路由 |
| 后端 | `src/router.ts` | 挂载 `/plugin/events` |
| 插件 | `sms/proactivePoller.ts`（新增） | 30s 轮询器（setTimeout 链，页面隐藏降 5min）；**state 未就绪不清队列**（防事件丢失） |
| 插件 | `ai/index.ts` | `wakeAiForProactiveSms()`：幽灵实体 + 主动语境记忆 + `proactiveSms` opt；`registerProactiveWake` 接线 |
| 插件 | `ai/brain.ts` | `BrainCallOptions.proactiveSms`：userPrompt 注入「主动短信任务」专项块——把 message 从可选项提升为主要产出 |
| 插件 | `App.vue` | onMounted 启动 / onBeforeUnmount 停止轮询器 |

### 8.3 实测（真实 5175 + 60002）

| 验证项 | 结果 |
|---|---|
| 队列 push/pop | push 回 `{"pushed":1}`；pop 取回完整事件结构 ✅ |
| 插件拉取消费 | push 后 ≤30s 队列被插件拉空 ✅ |
| 防丢事件 | state 未就绪（选人页）时轮询器**不清队列**，进入 playing 后正常消费 ✅ |
| LLM 决策 | `brain_diag` 全阶段可见：`p3_proactive_start → p3_proactive_sent/silent`（带 reasoning）✅ |
| **AI 主动短信** | push hint「荒野出现狼群提醒玩家」→ 38s 内陈南璇主动发出「我这边暂时安全，先待命。」（玩家未发任何消息）✅ |
| 无 hint 语境 | 无提示时 LLM 判断"保持待命"不发——silent 是正确产品行为（宁缺毋滥）✅ |

**★ 踩坑（LLM 3 连 silent 的根因）**：输出格式契约里 `message` 是"可选，不需要发就省略"，
叠加 keepAction（保持现状）+ ghost（动作一律 wait）双重保守语境 → LLM 倾向省略 message。
解法：`proactiveSms` opt 在 userPrompt 注入专项块，**显式声明"message 是本次决策的主要产出，
不要省略"**，同时保留"确实无话可说可省略"的出口（避免硬逼 AI 硬编）。

## 7. P2 回合/指令型分流 —— ✅ 已实施 + 实测（2026-11-01）

### 7.1 实现（三处改动，全部向后兼容）

1. **manifest 声明**（`contributes.minigame.interaction`）：
   - `"turn-based"`：回合/指令型，插件端**不发 tick**；
   - 缺省/`"realtime"`：实时动作型，行为与既有插件完全一致。

2. **宿主**（`Toonflow-game-web`）：
   - `usePluginRuntime.ts`：`ResolvedPluginMinigame.interaction` 字段（默认 realtime）；
   - `ScenePlay.vue appendInteraction()`：把 `interaction` 拼进 iframe src query
     （realtime 也显式拼，便于观察；插件端对缺省同样按 realtime 处理）。

3. **插件端**：
   - `bridge.ts`：`interactionMode()` / `isTurnBased()`（读 `location.search`，缓存）；
   - `App.vue` tick 循环：`if (ts - lastSendAt >= currentSendMs(ts) && !isTurnBased())`。

4. **后端 tick.ts 自愈守卫放宽**（配合回合制）：
   - 旧：仅 `phase==="playing" || phase===""` 放行指针自愈；
   - 新：`phase!=="over"` 即放行——回合制有 select/config 等合法中间态；
   - `over` 仍拒绝：结束的局必须走编排器正常重开，防僵尸指针复活已结算对局。
