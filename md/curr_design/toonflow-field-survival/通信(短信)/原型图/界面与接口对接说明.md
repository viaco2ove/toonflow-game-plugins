# 通信(短信) 界面与接口对接说明

> 版本：v2（2026-10-30）—— 与 `通信(短信).design.md` v2 同步
> 原型：`通信面板原型.html`（v2 为「系统面板内嵌 tab」形态）

## 1. 页面定位

- **菜单路径**：系统面板 → 通信 tab（★ tab 排在**第一位**）
- **落地形态**：`SystemPanel.vue` 的 `.sp-body` 内嵌子面板，**不是独立浮窗**
- **核心用途**：玩家与 AI 托管角色的单聊/群聊，类似微信的短信系统

### 1.1 与既有「角色对话」的关系（并存，不合并）

| | 既有角色对话 | 通信(短信) |
|---|---|---|
| 触发 | 走到角色身边点「聊天」 | 通信面板，随时随地 |
| 存储 | 前端内存态，关闭即丢 | `t_plugin_session_data` 持久化 |
| AI 来源 | 独立「发言器 agent」 | AI 托管大脑的同一次决策 |
| `#ai` 指令 | ✅ 支持 | ❌ 不支持（轻量通道） |

## 2. 界面字段说明

### 2.1 左侧会话列表

**顶部是「通讯录选择器」**（`SmsContactPicker.vue`）—— 搜索框 + 下拉，不是纯过滤框：

| 字段 | 类型 | 说明 |
|---|---|---|
| 搜索框 | 文本输入 | 点它展开下拉；输入按角色名 / 群名过滤下拉内容 |
| 下拉 · 群聊段 | 列表项 | **已创建**的群聊（带未读角标），点一下切换过去 |
| 下拉 · 角色段 | 列表项 | 通讯录里**还没建过单聊**的角色；带「托管」标签；点一下**主动建单聊并打开** |
| 下拉 · ＋新建群聊 | 按钮 | 打开建群弹窗 |
| 下拉空态 | 居中文本 | 「没有匹配的角色」 |
| 头像 | 图标 | 单聊显示角色头像，群聊显示群图标 |
| 会话名称 | 文本 | 单聊=角色名；群聊=群名 + 蓝系 `[群聊]` 标签 |
| 最后消息预览 | 文本 | 最后一条消息内容截断；**群聊带发送者前缀**（`陈南璇: 前面有哥布林`） |
| 时间 | 文本 | 最后一条消息时间（今天显示时分，昨天显示"昨天"，更早显示日期） |
| 未读角标 | 数字角标 | 该会话未读消息数，>99 显示 `99+`；为 0 时不渲染 |

> ★ 会话列表**只放已有会话**；找新的人走顶部下拉。
> ★ 下拉项的点击用 **`pointerdown`** 触发（不是 `click`）—— 面板可拖拽，
> `setPointerCapture` 会让浏览器不再在选项上合成 click，导致「点了没反应」。
> ★ 已建过单聊的角色**不在下拉「角色」段里重复出现**。

## 3. 数据存储（t_plugin_session_data）

### 3.1 存储位置

| 项 | 取值 |
|---|---|
| 表 | `t_plugin_session_data` |
| `sessionId` | `"all"`（跨会话共享） |
| `dataKey` | `sms_conversations:<story>`（★ **按故事隔离**） |

> `story` 取自 `state.worldName`（entry.ts 在 init 时注入顶层）。
> **禁止**用裸 key `sms_conversations` + `sessionId="all"` —— 那是跨故事覆盖。
> 兼容：带后缀的 key 不存在时，回退读裸 key 并迁移。

### 3.2 数据结构

```typescript
export type ConversationType = "private" | "group";
export type MessageType = "text" | "system";

export interface Conversation {
  id: string;                    // 会话ID（string）
  type: ConversationType;
  name: string;
  avatar?: string;
  members: string[];            // 参与角色ID（玩家固定在其中）
  messages: Message[];          // 按时间升序，最多 100 条
  lastReadMsgId: string | null; // 玩家最后读到的消息ID
  createdAt: number;
  updatedAt: number;            // 用于会话列表排序
  awaitingReply?: boolean;
}

export interface Message {
  id: string;                    // 消息ID（string）
  conversationId: string;       // 所属会话ID（冗余）
  from: string;                  // "player" 或 角色ID
  fromName: string;              // 发送者显示名（冗余）
  text: string;                  // ≤500 字符
  timestamp: number;
  type: MessageType;             // "text" / "system"
}

export interface SmsStoreShape {
  conversations: Conversation[];
  version: number;
}
```

### 3.3 ID 生成

```typescript
export function genId(prefix: "c" | "m"): string {
  return `${prefix}_${Date.now().toString(36)}_${Math.random().toString(36).slice(2, 8)}`;
}
```

### 3.4 容量上限

| 约束 | 值 |
|---|---|
| 单会话消息数 | ≤ 100（超出丢最旧） |
| 单条消息文本 | ≤ 500 字符 |
| 总会话数 | ≤ 50（超出丢最久未活跃） |
| 落库体积 | ≤ 256 KB |

> 裁剪若丢掉了 `lastReadMsgId` 指向的消息 → 把 `lastReadMsgId` 重置为 `null`。

## 4. 未读数计算

### 4.1 单会话未读

```typescript
export function getConvUnread(conv: Conversation): number {
  const startIdx = conv.lastReadMsgId
    ? conv.messages.findIndex((m) => m.id === conv.lastReadMsgId) + 1
    : 0;
  return conv.messages
    .slice(startIdx)
    .filter((m) => m.from !== "player" && m.type !== "system")
    .length;
}
```

**关键点**：排除 `from === "player"`（玩家自己发的**不算**未读）和 `type === "system"`。

### 4.2 总未读

```typescript
export function getTotalUnread(conversations: Conversation[]): number {
  return conversations.reduce((sum, c) => sum + getConvUnread(c), 0);
}
```

### 4.3 清零规则

| 操作 | 效果 |
|---|---|
| 点进会话 | `lastReadMsgId` 更新为最后一条消息ID → 该会话未读清零 |
| 玩家正在看这个会话时 AI 发消息 | 不标未读（实时已读） |
| 玩家主动发消息 | `lastReadMsgId` 推到该条 → 当前会话自动清零 |
| `system` 类型消息 | 永远不计入未读 |

### 4.4 实时已读判断

```typescript
export function shouldMarkUnread(
  convId: string,
  activeTab: string,
  activeConvId: string,
): boolean {
  return !(activeTab === "sms" && activeConvId === convId);
}
```

> `activeTab` / `activeConvId` 放在 `sms/store.ts` 的模块级 reactive 对象里，
> App.vue（系统按钮角标）与 SystemPanel.vue（tab 角标）都从 store 读，**不各维护一份**。

## 5. AI 消息触发

### 5.1 AI 主动发消息（心跳 / 事件触发）

AI 大脑决策时（`callBrain()`），LLM 返回的 JSON 里带可选 `message` 字段：

```json
{
  "reasoning": "在采药，想跟玩家说一声",
  "goal": "采集",
  "action": { "type": "gather", "...": "..." },
  "message": {
    "text": "我去东边药圃采药了，有事喊我。",
    "to": "player"
  }
}
```

`to` 取值：

| 值 | 含义 |
|---|---|
| `"player"` | 发到与该角色的**单聊**会话（不存在则自动创建） |
| `"group:<groupId>"` | 发到指定群聊会话 |

**规则**：拿不到 LLM（闸门被挡 / 超时 / 解析失败）→ **不发短信**（宁缺毋滥）。

### 5.2 ★ 玩家→AI 回复（必须实现）

玩家发消息时：

```
玩家发送
  → smsStore.sendPlayerMessage(convId, text)      // 落库 + 清未读
  → 对 conv.members 里每个 AI 角色：
       notifyAIEvent(entityId, "dialog", `收到玩家短信：${text}`)
       aiState.pendingTriggerPriority = "P0"        // 立即决策，不等 20s 心跳
```

AI 侧 prompt 必须能看到玩家消息（**单聊和群聊都要**）：

```
### 短信往来（最近 5 条，★ 表示还没回复你）
- [单聊·萧肿] 玩家 14:22: 药圃在哪
- [单聊·萧肿] 萧肿 14:23: 往东走第三个田埂
- [群聊·林家护卫团] 玩家 14:30: 大家小心
```

回复契约：

```
如果你在上面的「短信往来」里看到了 ★ 标记的玩家消息，
你必须在本次回复里给出 message.text 来回应它。
如果你已经回复过该消息（没有 ★ 标记），则不要再发重复的 message。
message 字段是可选的，不需要发短信时省略它。
```

## 6. 写入链路（全前端，方案 A）

```
callBrain() 返回 LLMDecision（含 message）
  → App.vue 消费 decision.message          ← ★ 唯一接线点
  → smsStore.receiveFromAI(from, to, text)
  → smsStore 内部防抖 1s → pluginData.set(dataKey, shape)
```

**为什么不用后端落库**：`t_plugin_session_data` 每次 set 都会触发宿主回包刷新，
前端还要再拉一次；未读清零靠前端回写会出现写-读竞态（存储文档已知坑 #1）。

### 写入策略

| 时机 | 动作 | 延迟 |
|---|---|---|
| 新消息到达 | 防抖写 | 1s |
| 玩家阅读更新 `lastReadMsgId` | 防抖写 | 500ms |
| 玩家发消息 | 防抖写 | 500ms |
| 退出游戏 / 切换地图 | **强制同步写** | 立即 |
| 落库失败 | `console.warn` 兜底 | 不阻断玩法 |

### 加载时机

```
App.vue 收到 init 状态 → worldName 就绪
  → smsStore.load(worldName)
      → pluginData.get(`sms_conversations:${story}`, "all")
      → 不存在则回退读 `sms_conversations`（兼容老存档）并迁移
      → 解析失败 / 非 JSON → 丢弃并用空结构（不阻断游戏）
```
