## 2. 关键设计决策（实施时确认）

### 2.1 默认关闭，且关闭时零开销
- 开关落 `localStorage`（`fs_sound_on`），**不进 `sys_state` 存档** —— 音效是「这台设备的听感偏好」，不该跟着角色跨设备串味。
- 关闭状态下 **连 AudioContext 都不创建**（`ensureCtx()` 只在 `enabled === true` 时被调用）→ 零 CPU / 零内存。

### 2.2 手势解锁必须挂在 iframe 文档自身
插件 UI 跑在宿主 iframe 里，**宿主外层的 pointerdown 不会传递进来**。
所以 `bindUnlockGesture()` 挂在插件文档自身的 `pointerdown / keydown / touchstart`（capture 阶段），解锁后自我摘除。

### 2.3 音量持久化踩坑（已修）
`localStorage.getItem(key)` 未存过时返回 `null`，而 `Number(null) === 0`
→ 原实现会把**所有音量默默变成 0**，表现为「开了音效但完全没声」。
修复：`readNum()` 先判空再转数字。

### 2.4 并发上限不依赖 onended 回调
原设计用 `osc.onended` 递减并发计数，一旦浏览器丢回调就会**永久卡在上限，之后所有音效哑掉**。
改为「记录到期时间戳 + 播放前剪枝过期项」，自愈、无回调依赖。

### 2.5 伤害音用 hp 差分，不依赖宿主事件字段
宿主 `damage()` 里没有推「谁被打了」的事件字段。
所以前端在 10Hz tick 里比对前后两帧的 `hp` 差分：
- 敌人掉血 → `hit`
- 玩家掉血 → `player_hurt`
- 敌人 hp 归零 → 追加 `enemy_die`
- 玩家 hp 归零 → `player_die`（只播一次，靠 `playerDeathPlayed` 标志位）

### 2.6 脚步按位移阈值触发
不是每帧触发，而是**累计位移 1.6 米**才播一步（`STEP_DIST_M`）。
停止移动时清空基准，重新起步先建基准再累计。

## 4. 业务专属音效的注入方式（遵守插件边界）

插件**不写**任何地图集特有的音效配方。地图集/事件脚本通过 ctx 注入：

```ts
// 地图集的事件脚本里
ctx.audio.register("blacktower_gate_open", {
  group: "system",
  wave: "sawtooth",
  freq: 180,
  toFreq: 60,
  dur: 600,
  gain: 0.25,
});

ctx.audio.play("blacktower_gate_open");
```

- `ctx.audio.register(name, recipe)` —— 注册业务专属配方
- `ctx.audio.play(name, { gain?, rate? })` —— 播放
- `ctx.audio.enabled()` —— 当前是否开启

`.cache/validate_events.mjs` 的 `CTX_API` 白名单已同步补上这三个名字。

## 7. 音量调节「卡顿」的修复（2026-11-12 二修）

### 7.1 症状
用户反馈：主音量能调但很卡；分组音量看起来调不动。

### 7.2 根因（三层叠加）

**① 架构问题：音量没有作用到「正在响」的声音上（主因）**
旧实现把音量在 `schedule()` 时乘进包络：

```ts
const total = gain * masterVolume * groupGain;   // ← 每次播放时才算
env.gain.exponentialRampToValueAtTime(total, ...);
```

→ 改音量只影响**下次播放**，正在响的声音纹丝不动。
用户拖滑块时**听不出任何变化**，只能靠再点一次试听来验证 —— 反馈延迟 = 一次完整往返，
主观上就是「卡」「不跟手」。

**② 响应式开销：每次滑动整体替换 `groups` 对象**
```ts
groups.value = { ...groups.value, [g.id]: v };   // ← 整个对象换了
```
Vue 认为 `groups` 的依赖全变了 → 6 个滑块 + 6 个百分比文本**全部**重渲染。
`input` 事件每秒触发 60+ 次 → 明显卡手。

**③ 同步落盘：每次滑动都写 localStorage**
`setItem` 是同步 IO，拖动时每秒 60+ 次 → 主线程阻塞。

### 7.3 修复方案

**① 改成 GainNode 增益图（架构级修复）**

```
masterGain ─┬─ groupGain(ui) ─┬─ [每次播放的临时包络] ─┐
            ├─ groupGain(move)┤                         ├→ destination
            └─ ...            ┘                         ┘
```

- `masterGain` 与 6 个 `groupGain` 在 `AudioContext` 创建时建一次
- 滑块直接改 `GainNode.gain` → **正在响的声音立刻变轻/变响**
- `schedule()` 里的包络峰值只保留「配方自身增益」，不再乘主/分组音量（避免二次衰减）
- 用 `setTargetAtTime(τ=0.02s)` 而非直接赋值 —— 直接赋值会在音频块边界产生突变（爆音/咔哒），
  `setTargetAtTime` 做平滑过渡，既跟手又不炸

**② 响应式改为逐 key 赋值**
```ts
const groups = reactive<Record<string, number>>({...});
groups[g] = v;      // ← 只有该滑块和它的百分比文本重渲染
```

**③ 落盘防抖 300ms**
```ts
function persist(key, value) {   // 滑动时只写最后一次
  clearTimeout(persistTimer);
  persistTimer = setTimeout(() => write(key, value), 300);
}
```

**④ 滑块松手自动试听**
`<input type=range>` 加 `@change="preview(g.id)"` —— 拖完松手立刻听到该分组的样例音，
不用手动点 ▶。配合 `playSound(..., { force: true })` 绕开 80ms 去重窗口，保证「点了必有声」。

### 7.4 验证
- 增益图结构：7 个 GainNode（1 主 + 6 分组）✅
- `setMasterVolume` / `setGroupVolume` 直接写入对应节点 ✅
- 平滑时间常数 0.02s（跟手）✅
- 包络峰值不含主/分组音量（无二次衰减）✅
- 连续滑动 3 次 → 落盘 1 次，值正确 ✅
- `force:true` 绕过去重 ✅
- 回归：gameSounds 12 项全通过 ✅
- 共 **38 项断言全通过**

### 7.5 浏览器内实测（补记）
后续用 BrowserSkill 实际进入 `http://localhost:3000/` 的游戏，打开系统 → 设置 → 音效做了验证：
7 个滑块的 GainNode 增益图结构正确、`setTargetAtTime(v, τ=0.02)` 实时生效、拖动时不重建音频图、
300ms 落盘防抖生效、`@change` 自动试听确实调度了音源；连续 60 次 `input` 总耗时约 4ms（单次约 0.067ms）。
主观拖动手感已由用户确认顺畅。

## 8. 脚步声「完全没有声音」的修复（2026-11-12 三修）

### 8.1 症状
用户打开音效试听后反馈：其他音效有，**脚步声完全没有声音**，要求「换一种明显的声音」。

### 8.2 根因：用了一个永远是 0 的速度字段
旧实现把「玩家是否在移动」当作入参传进来：

```ts
// App.vue（旧）
const moving = Math.abs(me.vx) + Math.abs(me.vy) > 0.01;
updateFootstep(me.x, me.y, moving);
```

但 `localTick()` 里移动是**直接改 `me.x / me.y`**，末尾还有一句 `me.vx = 0; me.vy = 0;`
—— 速度字段从来没有被赋过真实值。

→ `moving` 恒为 `false` → `updateFootstep()` 每帧都走「静止」分支并重置基准
→ 位移永远攒不起来 → **`play("footstep")` 一次都不会被调用**。

所以这不是音量小、也不是配方不好听，而是**根本没触发**；只调配方治不了这个病。

### 8.3 修复（三层）

**① 改成纯位置差分，删掉速度依赖**

`updateFootstep(x, y)` 只比较本次采样与上次采样的坐标：
- 首次采样只建基准（`stepPrimed`）
- 单帧位移 `< 0.01m` 视为静止，但**保留已攒距离和基准**，不清零
- 否则累加 `Math.hypot(dx, dy)`，达到 `1.6m` 播一次
- 触发后 `stepAccum -= STEP_DIST_M`，**保留余数**
  （旧写法直接清零会丢掉超出阈值的距离，12m 实际只走 6 步且节奏不均）

`App.vue` 的 `observeGameAudio()` 同步改为只传 `x/y`。

**② 换成明显得多的「低频砰 + 高频沙沙」双层声音**

旧配方是纯噪声 + 低增益，在普通音箱上几乎听不见。新配方：

| 配方 | 波形 | 频率 | 时长 | 增益 | 噪声 | detune |
|---|---|---|---|---|---|---|
| `footstep` | square | 180→90 Hz | 90ms | 0.34 | 0.7 | 0.04 |
| `footstep_stone` | square | 260→140 Hz | 70ms | 0.30 | 0.85 | 0.05 |
| `footstep_wood` | triangle | 220→110 Hz | 130ms | 0.32 | 0.55 | 0.03 |
| `footstep_water` | sine | 150→80 Hz | 200ms | 0.30 | 1.0 | 0.06 |

低频给出「踏地」实感，噪声层给出摩擦质感，`detune` 让每次落脚略有差异、避免机械重复。

**③ `move` 分组默认音量 0.4 → 0.75**

只在 `localStorage` 没有存档时生效；已经手动调过音量的用户仍保留自己的设置。

### 8.4 验证
临时测试 `.cache/audio-test/footstep.test.ts` **15 项全通过**：
- 不传 `moving` 也能触发（针对旧 bug 的回归）
- 12m 直线走 → 恰好 7 步；静止 / 微小抖动不触发；停下再走仍能触发
- 每次落脚同时调度振荡器与噪声层
- 配方波形 / 频率 / 增益 / 时长 / detune 参数正确
- `move` 默认音量不低于 0.6
- 端到端合成调度链路通过

> 测试中踩到两个坑，一并记下：同步循环连播会被 80ms 去重吞掉（要 `await sleep(100)`）；
> mock 的 `AudioContext.currentTime` 若不随时间前进，`voiceEnds` 并发上限永远不释放
> （`FakeCtx.currentTime` 改成跟随真实时间）。

### 8.5 边界
自动化只能证明「脚步被调度、音源被创建」，**不能证明主观上好不好听**。
浏览器内实际走动听感仍需人工确认一次。
