# 音效设计方案

> 状态：**已实现**（2026-11-12，WebAudio 实时合成方案落地）
> 实施细节与测试结果见：[音效实施记录.md](./音效实施记录.md)
> 编写时间：2026-11-12
> 适用范围：插件 `toonflow-field-survival`（Vue 3 + Canvas 2D 前端，`ui/game.html` 单文件产物）
> 目标：**默认关闭**，用户在「系统 → 设置 → 音效」里自行打开；打开后游戏关键行为有明确的听觉反馈。

## 二、路线对比与选型（性价比分析）

### 方案 A：程序化合成音效（WebAudio 实时合成）

用 `AudioContext` + `OscillatorNode` / `BufferSource(白噪声)` + `GainNode` 包络**实时合成**音效，代码里只存「配方」不存音频文件。

- ✅ **零素材成本**：不用找/录/切音频，不用引入版权风险
- ✅ **零加载成本**：没有网络请求、没有 base64 体积膨胀（单文件 `game.html` 尤其敏感）
- ✅ **参数可调**：同一配方可随机微调音高/时长，重复触发不腻
- ✅ **可被地图集覆盖**：配方只是数据，地图集可自定义
- ❌ 音色偏「电子/合成器」，不够「有质感」
- ❌ 复杂音色（脚步、刀剑拟音）实现成本高于直接用素材

### 方案 B：预渲染音频文件 + base64 内联

离线用工具生成 `.wav/.mp3`，转 base64 内联进 `game.html`。

- ✅ 音质好、可录制人声/拟音
- ❌ **体积**：base64 膨胀 ~33%，单个 0.5s mp3 ≈ 8KB → base64 ≈ 11KB；20 个音效 ≈ 220KB，且**每个地图集都带这一份**
- ❌ 需要素材来源与授权链路
- ❌ 与「插件通用能力、素材归地图集」的边界冲突（见第五节）

### 方案 C：运行时加载独立音频文件（`assetUrl` 通道）

把 `.mp3` 放 `ui/audio/`，运行时 `new Audio(assetUrl("audio/xxx.mp3"))`。

- ✅ 音质好、体积不占 `game.html`
- ❌ **宿主 getAsset 通道对查询串敏感**：必须确认宿主 `/plugin/getAsset` 支持 `Content-Type: audio/mpeg` 与 `Range` 请求，否则移动端/安卓 WebView 可能整片静默（已知该通道对查询串敏感，`assets.ts` 里已有大量注释踩坑）
- ❌ 离线/宿主未安装态（本地 `ui/game.html` 直开）拿不到文件 → 需要双通道兜底，复杂度上升
- ❌ 首次播放有加载延迟

### ✅ 选型结论：**A 为主，C 为可选扩展**

**性价比最高的路线是方案 A**：音效本质是短促的功能性提示音（1–3 kHz 区间、可 60–250ms），合成音完全够用，且能零成本覆盖全部事件点。

- **第一阶段只做 A**：`audio/synth.ts` 里放 ~16 条配方 + 一个统一播放入口，不引入任何素材文件
- **第二阶段按需混入 C**：若个别音效（刀剑拟音、脚步、环境氛围）合成出来确实难听，再单独为**那几条**走 `assetUrl` 通道加载，配方表里标 `source: "file" | "synth"`，引擎按字段分发。**不为了个别音效把整个系统改成文件制**。

理由汇总：
1. 素材是最大成本项（找/录/切/授权/上传），方案 A 直接消除这一项
2. 单文件产物体积敏感（`game.html` 已被图片撑到 MB 级），方案 A 增量为 **0 KB**
3. 合成音天然可程序化生成「随机化变体」，比固定素材更耐听
4. 复用已有的 `ctx.audio.play(name)` 协议，事件脚本侧**零改动**即可发声

## 三、系统架构

```
        ┌──────────────── 事件脚本（地图集） ────────────────┐
        │  ctx.audio.play("pickup") / ctx.audio.play("hit")   │
        └──────────────────────┬─────────────────────────────┘
                               │  （协议已存在，实现从 no-op 改为真实播放）
        ┌──────────────────────▼─────────────────────────────┐
        │            audio/audioEngine.ts                    │
        │  · ensureUnlocked()   首次用户手势恢复 AudioContext │
        │  · play(name, opts)   查配方表 → 合成/加载 → 播放  │
        │  · 节流 / 并发上限 / 同音效去重                      │
        │  · 主音量 × 分组音量                                  │
        └──────────────────────┬─────────────────────────────┘
                               │
        ┌──────────────────────▼─────────────────────────────┐
        │         audio/recipes.ts（配方表，纯数据）           │
        │  name → { wave, freq, dur, gain, sweep, noiseMix }  │
        └────────────────────────────────────────────────────┘
```

### 3.1 关键约束

1. **浏览器自动播放策略**：`AudioContext` 创建后是 `suspended` 状态，必须等一次用户手势（`pointerdown` / `keydown`）才能 `resume()`。
   → 在 `App.vue` 顶层挂一次性手势监听，resume 后再 `play()`。**在用户点任何东西之前产生的音效本来就不该有**，所以「手势解锁」与「默认关闭」不冲突。

2. **默认关闭**：音效总开关默认 `false`，落 `localStorage`（键 `fs_sound_on`），与现有 `fs_pixel_mode` / `fs_fog` 同一套做法。
   - 关闭时**完全不创建 AudioContext**（连对象都不 new），零 CPU、零内存
   - 开关状态**不随游戏存档走**（`sys_state`），避免跨设备串味

3. **单文件产物兼容**：方案 A 不引用任何外部音频文件 → 不受 `getAsset` 查询串敏感问题影响，也不需要把素材打包进 `.tbg`。

4. **iframe 内运行**：插件 UI 跑在宿主 iframe 里，`AudioContext` 在 iframe 中完全可用，不受同源策略限制；但**宿主页面的手势不会传给 iframe**，所以解锁必须挂在 iframe 文档自身的监听上（插件自己的 `pointerdown`），宿主外层点击不触发。

### 3.2 配方表结构

```ts
export interface SoundRecipe {
  /** 分组，用于分组音量调节 */
  group: "ui" | "move" | "combat" | "item" | "skill" | "system";
  /** 合成方式 */
  wave?: "sine" | "square" | "sawtooth" | "triangle" | "noise";
  /** 起始频率 Hz */
  freq?: number;
  /** 结束频率 Hz（做滑音） */
  toFreq?: number;
  /** 时长 ms */
  dur?: number;
  /** 峰值增益（再乘主音量/分组音量） */
  gain?: number;
  /** 噪声占比 0~1（与 wave 混合） */
  noise?: number;
  /** 延迟 ms（用于做「先后两声」的复合音） */
  delay?: number;
  /** 音高随机化 ±比例，避免重复触发听觉疲劳 */
  detune?: number;
}
```

### 3.3 播放入口 API

```ts
// vue/src/audio/audioEngine.ts
export function isSoundEnabled(): boolean;
export function setSoundEnabled(on: boolean): void;      // 落 localStorage
export function play(name: string, opts?: { gain?: number; rate?: number }): void;
export function setMasterVolume(v: number): void;          // 0~1
export function setGroupVolume(group: SoundGroup, v: number): void;
export function unlockAudio(): void;                        // 手势解锁
```

- `play()` 内部：`if (!enabled) return;` → 查配方 → 未命中则 `console.debug` 提示（便于排查，不刷屏）
- **节流**：同一配方名在 `80ms` 内重复触发只播一次（防止多帧多实体同时命中）
- **并发上限**：同时最多 `6` 个发声节点，超出丢弃最旧的
- 配方未命中、AudioContext 不可用、合成出错 → 全部 `try/catch` 吞掉，**音效永远不能影响游戏逻辑**

### 4.1 入口位置

当前「系统」面板的页签结构是：`通信 / 背包 / 纳戒 / 商城 / 技能 / 地图 / 角色 / 事件 / 任务 / 设置`。

`设置` 页签现在只放 AI 托管（`AIPanel.vue`）。两种放法：

| 方案 | 做法 | 评价 |
|---|---|---|
| **① 设置页内分区**（推荐） | `设置` 页签内部分成「AI 托管」「音效」两个区块，上下排列 | 不改页签结构、不占页签位；用户说的「系统-设置-音效」路径最短 |
| ② 新增独立页签 | 加一个 `🔊 音效` 页签 | 页签已经有 10 个，再加会更挤 |

**推荐 ①**：`SystemPanel.vue` 的 `activeTab === "config"` 分支改成渲染两个子区块 —— 上半部分 `<AIPanel>`，下半部分新增 `<SoundPanel>`（新建 `vue/src/panels/SoundPanel.vue`），中间一条分隔线 + 小标题「音效」。

### 4.2 SoundPanel 内容

```
🔊 音效                                     [ 关 / 开 ]   ← 总开关，默认关

┌ 音效总音量 ────────────────●───── 70%

   界面音 (ui)              ──●──  60%
```

在「音效」区块底部加一行调试信息：`已合成 N 条配方 / 上下文状态：suspended|running`，方便开发期确认解锁是否成功。

## 五、边界：插件 vs 地图集（沿用既有架构约定）

> 既定原则：**插件只提供通用能力，地图集自行管理业务数据。** 音效设计必须遵守。

| 内容 | 归属 | 说明 |
|---|---|---|
| `AudioContext` 管理、播放引擎、节流、音量分组 | **插件** | 通用能力，地图集不该也不需要重复实现 |
| 基础配方表（UI 点击、拾取、命中等**全局通用**提示音） | **插件** | 每个插件都要用，不算业务 |
| **具体地图集专属音效**（如「黑塔」机关声、任务专属BGM线索） | **地图集** | 通过事件脚本 `ctx.audio.play("自定义名")` 触发，配方由地图集提供/覆盖 |
| 自定义配方扩展点 | **插件** | 提供 `ctx.audio.register(name, recipe)` 或从事件包加载覆盖表 |

**边界控制手段**：插件配方表只保留「跨地图通用」的功能性音效；任何带具体剧情/地图语义的音效一律不写进插件，由地图集在事件脚本里注册。

**事件脚本侧已有通道**（无需新增动作类型）：

```js
// 地图集 events.json 的 run_script
ctx.audio.play("pickup")
ctx.audio.play("chest_open", { gain: 0.9 })
```

`ctx.audio.play` 已存在于 `_ctx.ts` 协议中，事件引擎侧只需把 no-op 换成真实调用。

## 六、音效事件清单（按性价比排序）

优先级说明：**P0 = 打开开关后必须能感知到游戏在响应**；P1 = 显著提升手感；P2 = 锦上添花。

### P0 —— 骨架（先做这 8 条，收益最大）

| 事件 key | 触发点（现有代码位置） | 建议音色 | 理由 |
|---|---|---|---|
| `ui_click` | 面板按钮点击（`SystemPanel` / 各 Panel 的 `@click`） | 短促方波 ~1200Hz, 40ms | 所有交互都有反馈，成本最低 |
| `ui_open` | 系统面板 / 商城 / 背包打开 | 上行滑音 400→900Hz, 120ms | 空间感 |
| `ui_close` | 面板关闭 | 下行滑音 900→400Hz, 120ms | 与 open 成对 |
| `pickup` | `App.vue` `onPickupConfirm()` L7019 | 双音上行 700→1100Hz, 180ms | 刚做完的功能，高频 |
| `hit` | 玩家/怪物受击（伤害落地处） | 噪声爆 + 低频砰, 120ms | 战斗核心反馈 |
| `player_hurt` | 玩家血量下降 | 噪声 + 下滑方波, 200ms | 与 hit 区分（更低沉） |
| `skill_cast` | `App.vue` `castSkill()` L7844 | 三角波扫频 300→1400Hz, 300ms | 技能释放 |
| `error` | 非法操作 / 冷却中 / 资源不足 | 两声低沉方波, 150ms | 否定反馈，避免玩家困惑 |

### P1 —— 手感（第二轮）

| 事件 key | 触发点 | 建议音色 |
|---|---|---|
| `enemy_die` | 敌人死亡（`deathMs` 淡出起点） | 下行噪声 + 低频 |
| `crit` | 暴击 | 高频金属感短音 + hit 叠加 |
| `footstep` | 玩家移动（按地面材质变音色：草/石/木/水） | 极短噪声，40–60ms，低音量 |
| `item_use` | 消耗品（`sys_use_item`） | 咕噜式双音 |
| `quest_accept` / `quest_done` | 任务接取 / 完成 | 三音上行小旋律 / 五音上行 |
| `level_up` | 升级 | 上行琶音 |
| `panel_tab` | 系统面板切页签 | 极短点击音（与 ui_click 区分） |
| `message` | 短信/消息提示 | 双音「叮-咚」 |
| `shop_buy` | 购买成功 | 硬币声（两段高频噪声） |
| `craft_success` / `craft_fail` | 锻造/炼丹成功失败 | 成功清亮琶音 / 失败闷响 |

### P2 —— 氛围（第三轮，视资源余量）

| 事件 key | 触发点 | 说明 |
|---|---|---|
| `teleport` | 传送 / 切图 | 空间穿越感 |
| `cooldown_ready` | 技能冷却结束 | 轻提示音，注意别频繁 |
| `footstep_water` / `footstep_wood` | 分材质脚步 | 需地形材质查询 |
| `ambient_wind` | 环境底噪（循环） | **性价比最低**：循环音最耗性能与注意力，最后做 |

## 八、风险与注意事项

| 风险 | 应对 |
|---|---|
| 用户没点过任何东西 → AudioContext 一直 suspended | 首次手势解锁；面板按钮本身点击就是手势，自动解锁 |
| 音效「吵」 | 默认关闭 + 分组音量 + 节流；战斗组可单独调低 |
| 移动端/宿主 WebView 禁音 | `play()` 全 try/catch；失败静默降级，绝不影响游戏 |
| 帧循环里误触发大量音效 | 脚步按**位移阈值**触发；同 key 80ms 去重；并发上限 6 |
| 地图集塞业务音效进插件 | 配方表只放通用音；业务音走 `ctx.audio.register()` 由地图集注入 |
| 单文件产物体积 | 方案 A 增量为 0；若将来引文件，只给个别音效开 `source: "file"` 通道 |
| 未受控的自动播放 | 总开关默认关；即便打开，也只有用户主动操作后的行为才发声 |
