## 野外生存 HUD 快捷栏（技能/物品）翻页修复

用户反馈：「有些物品没有切换出来。不是 4 个一页、最后一页又换回去吗？」
截图：物品行 `银鲤×29 | 干粮×1 | 镇痛注射剂×2 | 湮气过滤滤芯×1`，技能行 `源之力 | 暗核共鸣 | 夜采直觉 | 暗核共鸣2`。

### 现状机制（修复后仍是这套）
- 前端 `App.vue` 两个 HUD 行：`.slots--item` / `.slots--skill`，每页 4 格，末位一个「切换」按钮。
- 点「切换」→ `sendTick("page", { kind: "item"|"skill", delta: 1 })` → 后端 `entry.ts case "page"`
  更新 `s.itemPage` / `s.skillPage`（`(page+delta) mod pages`，最后一页再点回到第一页）。
- 前端 `itemPage`/`skillPage` computed 用 `state.itemPage*4` 切片；点击格子发 `item`/`skill` + `index`，
  后端用 `s.itemPage*4 + index` 反查真正的槽位。

### 三个真实 bug
1. **硬上限 8 格**：`buildItems(card, 8)` / `buildSkills(card, 8, …)` 只生成 8 个槽位，
   一页 4 格 → 永远最多 2 页。背包第 9 件、技能第 9 个**永远翻不出来**。这是「有些物品没有切换出来」的主因。
2. **技能同名被改名占格**：`buildSkills` 里 `names.push(c === 1 ? nm : nm + c)`，
   参数卡里重复出现的技能变成 `暗核共鸣2 / 暗核共鸣3 / 源之力2 / 源之力3` 这种**假技能**，
   把真技能（基础功法）挤到后面。用户截图里的「暗核共鸣2」就是它。
3. **空格子写成假物品**：不足 8 格时填 `物品4 / 备用物1..4`，能点、点了返回「不在背包中」，
   还占着页数让人以为翻到了没内容的一页。
   附带：`counts[counts.length-1] += p.count` 只对**连续**同名正确，`A,B,A` 时 A 的数量会加到 B 上。

### 修复
- `entry.ts` 新增 `QUICKBAR_PAGE_SIZE = 4`、`padQuickbar()`（补到 4 的整数倍）、`clampQuickbarPages()`。
- `buildItems(card, padTo=4)`：**不设上限**；空格子 `{name:"", count:0, empty:true}`；同名按名下标累加。
- `buildSkills(card, padTo=4, meta)`：同名只留一格、`lv` 取 `max`，不再生成 `name2`；空格子 `empty:true`。
- `patchCard` / `syncCardFromContext` / `start` / `sys_skill_pool` 全部改调新签名 + `clampQuickbarPages`。
- `case "page"` 用双模 `((p+d)%pages+pages)%pages` 并夹紧；`case "item"`/`case "skill"` 跳过 `empty` 槽。
- **旧存档迁移** `normalizeQuickbarLegacy(s)`：在 `handle_action` 里每次进 action 前跑一次，
  按「`物品N`/`备用物N`/`技能N`/`备用技N`」以及「`X2` 且列表里也有 `X`」识别旧假格子，从 `playerCard` 重建。
  （否则用户不重开一局，刷新页面看到的还是那批假格子。）
- 前端：`QUICKBAR_PAGE_SIZE` 常量；「切换」按钮上加了 `当前页/总页数`（如 `2/3`）；格子加完整名 `title`；
  `castSkill`/`useItem` 对 `empty` 槽直接 return。

## 背包 / 技能「上移 / 下移」排序按钮（追加）

用户要求：在背包和技能面板增加上下移动按钮，改变物品和技能的顺序（截图指向 ⚙ 系统面板的背包 / 技能 tab）。

### 实现
- **背包**：BagPanel.vue 每行加 `↑` `↓` 两个按钮（首项 ↑ / 末项 ↓ 自动 disabled）→ emit `move-item(i, dir)`；
  SystemPanel.vue 转发 → App.vue `onSysMoveItem` → `moveSysOrder("item", i, dir)` 提交**完整顺序数组**
  → `sys_sort {kind:"item", order}`（与原拖拽排序同一条通道）。走原 `bagOrder` + `serializeBag` 逻辑。
- **技能**：SkillPanel.vue 同样 ↑/↓ → `move-skill` → `sys_sort {kind:"skill", order}`。
  后端 `case "sys_sort"` 新增 `kind` 分支：
  - `reorderCardSkills(card, order)`：参数卡 skills 是 "源之力（lv1，失控）（lv1）" 这种脏字符串，
    **按 skillKey 分组**后按 order 重排；每组内部原始条目相对顺序不变；order 没点到的技能按原顺序排在后面。
  - `s.skillOrder` 存归一化技能名，`persistSys` / `restoreSys` 持久化；
    `syncCardFromContext` 在 build 前 `applyCardSkillOrder()` 还原（宿主参数卡可能还没收到写回，会把顺序冲掉）。
  - 只用浅拷贝改 skills，不动宿主 context 对象。
- **mockHost.ts** 补 `sys_sort` 的两条分支（item / skill），dev-host 与真宿主对齐。
- 排序后 `patchCard` → `buildItems/buildSkills` 重建 → **HUD 快捷栏顺序同步**（第 1 页前 4 个就是快捷栏）。
- 事件命名坑：`move` 已被 RingPanel（纳戒）占用，`SystemPanel` 是一个组件同时收 BagPanel/SkillPanel 事件，
  直接用 `@move` 会撞成 Duplicate attribute 导致 vite 编译失败。改用 `move-item` / `move-skill`。

  10 条 raw 条目重排后不丢且注记原样保留、脏名可匹配、未点名技能排后、空卡兜底、skillOrder 还原。

## 地图数据不匹配（dev-host `--conn` 模式地图面板出现 4 个一模一样的「森林」）

用户报：`npm run debug -- --story 赦夜人冥夜走廊-第二季 --conn` 后，「全部地图 (4)」四行全是
「森林 / Lv1-10 / 当前 / 传送」。

### 根因（4 条叠加）
1. dev-host 桩的 `entryCtx` 没传 `worldName` → `entry.ensureStoryVisualMap()` 打印 `SKIP: worldName 为空`；
2. 桩的 `tsApi.pluginData` 没有 `getTemplate` → 又打印 `SKIP: getTemplate 不存在（旧后端）`；
3. dev-host 里**没人播种** `map_visual:<story>` 模板（真宿主机由 CLI `plugin_session_data -u` 写，DB id 255805/255804）；
4. 前 3 条导致 `storyMap.loadStoryMapBundle()` 取不到包 → `bundle=null` → `listLevelNames()` 只能走兜底 →
   `reportLevels()` 兜底分支把「当前关 + 后端回显的 `mapNodes`」当列表上报，而 `mapNodes` 又是前端上报的 levels 回显的
   → **回声环** 1→2→4，于是 4 个同名「森林」。

### 修复
- **`vue/vite.config.ts`**（4 处）：
  - 新增 `seedStoryVisualMap()`：fetch `/story-data/toonflow-field-survival/map_design/<STORY>.tbg` → base64
    → `__pdSet(__pdKey(pid, "all", "map_visual:<STORY>"), {format:"tbg", encoding:"base64+zip", data, story})`，
    候选路径含 `map_design` / `map_design_pre`；在 `tf_plugin_loaded` 流程里 `await`（先播种再推状态）。
  - `buildEntryCtx()` 补 `worldName: STORY`、`worldId`/`storyId`（取 `window.__STORY_WORLD_ID__`），
    `tsApi.pluginData` 补 `getTemplate: async (k) => __pdGet(__pdKey(pid,"all",k))?.value ?? null`。
  - `loadStoryData()` 暴露 `window.__STORY_WORLD_ID__ = worldId`。
  - **story-data 中间件补二进制分支**：`.tbg/.zip/.png/.jpg/.webp/.tmx/.tsx/.bin` 改 `readFileSync(buf)` 原样回
    `application/octet-stream`。原来一律 `readFileSync(...,"utf-8")` + `application/json`，zip 的非法字节会被替换成
    U+FFFD，`PK\x03\x04` magic 直接损坏 → 解包必失败。
- **`vue/src/App.vue`**：`reportLevels()` 兜底分支**删掉 `sysMapNodes`（回声环根源）**，只报当前关；
  再加按 id 去重的双保险。
- 前端 `getTemplate` 走 `op:"get" + sessionId="all"`（`toonflowJsApi.ts:72`），dev-host `tf_plugin_data` 桥的
  `get` 分支已支持显式 sessionId，无需改。

### 踩坑
- **`vite.config.ts` 里有 207→1572 行的超长 HTML 模板字符串 `const PAGE = \`<!doctype html>…\``**。
  在它中间（480 行附近）写注释时用了一个反引号，会把模板提前闭合，esbuild 报
  `Expected ";" but found "python"`（482:6，指向注释里的 `python -m toon_plugins…`）。
  **在这个文件 207~1572 之间严禁出现任何反引号**（包括注释）。排查方法：
  `grep -n '`' vite.config.ts` 数奇偶。

## 追加：PAGE 模板里的「TS 语法直发浏览器」坑（2026-10-17 21:5x）

用户报：`(index):402 Uncaught SyntaxError: Unexpected identifier 'as' (at (index):402:56)`。

### 根因
`vite.config.ts` 的 221→1586 行是 `const PAGE = \`<!doctype html>…\``，其中整段 `<script>`
是**原样 stringify 下发浏览器的裸 JS，不经过 vite/esbuild 转译**。我在 `buildEntryCtx()` 里写了
TS 类型断言 `(window as any).__STORY_WORLD_ID__`（3 处：621-623 的 worldId/storyId、1015 的赋值），
浏览器解析到 `as` 直接 SyntaxError，整个 dev-host 页面脚本全挂。
（注：这个文件里 221~1586 之外的代码是真 TS，会被 vite 正常转译，写 `as any` 没问题 —— 分界线就是反引号。）

### 修复
3 处 `(window as any).__STORY_WORLD_ID__` → `window.__STORY_WORLD_ID__`（裸 JS 不需要断言），
并在 `buildEntryCtx()` 上方加注释说明该区间严禁 TS 语法。

### 排查手法（可复用）
1. `grep -n '`' vite.config.ts` 拿模板起止行（本次 221/1586，会随编辑漂移，别写死）；
2. 只扫区间内：`awk 'NR>=START && NR<=END' vite.config.ts | grep -n "as any\|as string\|: any\b\|: void\|: string\b\|<[A-Z][a-z]*>"`；
3. **最硬的验证**：起 dev-server → `curl --noproxy '*' http://localhost:PORT/` 存 HTML
   → 正则抽 `<script>`（排除带 src 的）→ `new Function(code)` 只解析不执行，浏览器报的行号能直接对上。
   注意 Git Bash 的 `/tmp` 与 node 的 `/tmp` 不是同一个目录，落盘用仓库内路径。
