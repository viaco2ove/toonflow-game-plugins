### 踩坑（这次调试 entry.js 测试链路的总经验）

   返回 `r.state`；测试要 `Object.assign(s, r.state)` 才能读到改动
4. **`state.version` 必须是 2/3/4** 才会被 `handle_action` 接受（否则走 `emptyState` 默认值，
   我传 version=1 时所有测试断言都不通过）

## 修复刷新丢物品（fix(plugin) 8aac570）

### 用户问题
「我在商城买了"高阶暗核" 但是我刷新页面 背包里就没了？」+ 早前反馈的
「等级我本来只是16 突然就157 级别了」（本条目只解决前者，后者见下节）

### 真正的根因（昨天只修了一半）
昨天加了 persistSys/restoreSys 持久化 `card` 字段 + syncCardFromContext
「ctx 空卡不覆盖」守卫。今天实测发现守卫条件在 dev-host 永不触发：
dev-host 的 `ctx.playerCard` 不是空模板，而是服务端角色卡快照
（`window.__STORY_PLAYER_CARD__`，8 件物品/86418 金），所以
`cardItems===0 && curItems>0` 不成立 → syncCardFromContext 每次同步
（start 时 + 之后每个 tick）都把 restoreSys 恢复出的 9 件/86323 金
整体覆盖回 ctx 的 8 件/86418 金。购买/卖出在同一会话内也会被 tick 冲掉。

### 修复：字段归属规则（syncCardFromContext）
- `items / money / skills` 归插件会话所有 → 已恢复存档（`_sysRestored`）时
  以 `s.playerCard` 为准，ctx 只兜底 s 没有的字段
- `level / exp / hp / mp` 等剧情字段仍以 ctx 为准（AI 剧情改卡回灌实体，既有设计）
- 不能做 items 并集：会把卖掉的物品从 ctx 旧快照里复活（union=max 会输错）

### 附带发现：vite.config.ts 的 esbuild「现编」一直是 no-op
`node_modules/esbuild/lib/main.js` 是**库入口不是 CLI**——直接跑 exit 0
但什么都不写。昨天为修 npx ENOENT 把它排在第一优先级，导致 dev-host
启动时的仓库 entry.js 现编静默失效。改为候选链
`bin/esbuild` → `.bin/esbuild.cmd` → `npx`，且**用 mtime 是否前进去校验成败**
（exit code 不可信）。

### 验证（dev-host :3001，bsk 端到端）
start →（恢复 9 件/86323 金，含昨天买的轻量化护具）→ 购皮甲护符
（10 件/86163 金）→ tick 7→58 不反弹 → F5 刷新 → 重新 start → 仍 10 件/86163 金。
单测：skill_sell 13/13、kill_reward 29/29、quest_board 42/42；
kill_chest_chain 4/1 失败为**存量问题**（用 HEAD 旧 entry.js A/B 同样失败）。
