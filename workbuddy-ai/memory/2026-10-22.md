## 修复：贴图替换「返回编辑器」黑屏 + 右侧面板残留（ctx 缓存 + v-if 销毁 canvas）
- 现象：点「← 返回编辑器」后画布全黑、点击无反应，右侧还挂「贴图替换」面板，必须刷新才恢复。
- 根因1：`exitTileStyle()` 漏了 `showTileStylePanel.value = false`（面板残留）→ 已补。
- 根因2（关键）：`let ctx = null` 是**模块级缓存**的 2d context（App.vue:616，`render()` 里 `if(!ctx) ctx=canvasRef.getContext('2d')`）。
  原来中间区用 `v-if/v-else` 在 `<canvas>` 和 `<TilesetWorkspace>` 之间切换，退出时 canvas DOM 被**销毁重建**，
  `ctx` 仍指向旧的已销毁 canvas → `render()` 画不到新元素 → 黑屏；指针事件虽绑在新 canvas 但 ctx 失效导致交互无响应。
- 修复：canvas 改为 **常驻 DOM + `v-show="!(tileStyleMode && currentMaterial)"`**（不再销毁重建，ctx 永不失效）；
  `exitTileStyle()` 里 `nextTick(() => { ctx = null; resizeCanvas() })` 双保险重绘；并清空 selectedTileId/selectedTileIds/selectedTileImage/materialTilesetUrl。
- **教训（通用）**：canvas/图表这类持有「模块级缓存 context」的 DOM，切换显示**必须用 v-show，绝不能用 v-if**；否则重挂载后 ctx 指向旧元素，任何重绘都无效。

- **④ 的真根因（重要）**：PIL 的 `Image.paste(img, box, mask)` 是 **alpha 混合**不是替换！半透明新图 paste 到
  有内容的格子上，结果 alpha = 新α×(旧α/255) 一类的混合值（实测半透明红 α128 贴出 (128,0,0,64)）。
  我第一版「先 paste 透明块再 paste 新图」也一样错——第二次 paste 带 mask 仍混合。
  **正确做法：`Image.alpha_composite(旧格, 新格)` 后用不带 mask 的 paste 整格替换**。
  前端 canvas 侧则用 `clearRect(该格) + drawImage`（canvas 这套本来就是 source-over 替换，clear 后无残留）。
- **③ 重置机制**：后端首次覆盖某格时把**原始 32×32 像素**存档到 `overrides/originals/<tileId>.png`（重复覆盖不覆盖存档）；
  新增 `POST /api/tile-style/reset`：从存档恢复该格（alpha_composite/paste 不带 mask）+ 从 `styleOverrides` 删条目
  + 删 `overrides/<tileId>.png`（originals 保留，可反复替换/重置）。无存档时 404「没有覆盖记录」。
  前端 `onResetTile` 改为逐格调 `api.resetTile` 落盘 + 用 workImage 回写 canvas，统计成功/失败数。
- **① 生成/替换分离**：`TileStylePanel` 重写——「✨生成候选」只产出候选加入列表（不再直接 emit replace-tile）；
  候选缩略图条（点选高亮、可删、新生成自动选中）+「⬇替换选中格」按钮用选中候选走 `onReplaceTile` 落盘。
  切换选中格时清空候选（`tileStylePanelRef.onSelectionChanged()`，defineExpose 暴露）。
- **② 原图显式参考**：参考图区第一格是带「原图」标签的缩略图（绿框），默认加入；点 ✕ 移除，点「＋原图」加回。
