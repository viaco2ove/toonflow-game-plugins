## AI 托管触发频率落地（设计 → 全量实现）
先写设计文档 `md/curr_design/.../ai/ai托管/ai托管.agent.触发频率.md`（930 行），用户问"改好了不"后把 P0 全部落地。

### 核心设计变更
- **判据从「AI 自己身边有敌人」换成「玩家战斗状态」**。原因：AI 感知半径只有 13m，敌人在 20m 外时 AI 看不到玩家被围 —— 这正是"玩家挨打、队友反应慢"的根因。宿主 `damage()`（**所有伤害的唯一入口**）打点，玩家参与伤害即 engaged。
- **三态**：engaged（刚交火，30s 保持）→ skirmish（超时但 20m 内有活敌）→ none。跃迁用**边沿触发**（只在变化那一刻派发 AI 事件），不是电平。
- **紧急层是成本能压住的前提**：`sensor.checkEmergency()` 纯程序化，在调度器之前执行，**不受预算/熔断/并发限制** —— 所以战斗间隔敢放到 5s，且预算耗尽时 AI 关键时刻依然会逃跑。
- 频率表：engaged 5s / skirmish 10s / idle 20s / 城镇 30s。`maxInterval` 15000→30000 是核心降本杠杆（省 33%）。

### 修掉的既有 bug（重要）
`damage()` 有 **3 处调用点没传第 4 参数 `attacker`**：玩家普攻（5186）、玩家技能（5155）、另一处技能（5832）。没有它们，基于 `attacker.side === "player"` 的判据永远不成立。是 smoke test 直接暴露的。

### 修掉的并发 bug
`tickAllAIs` 原为逐角色 fire-and-forget → N 个角色同拍发起 → `state.chatResult` 单槽位互相覆盖 → **静默丢决策**（一次勾选 3 角色必丢 2 次）。拆成两阶段：`evaluateBrainTrigger()`（每 tick 纯本地评估/紧急层）→ `scheduler.ts` 队列 + 全局 `inFlight` 闸门 + 0~1500ms 抖动错峰 + 每分钟/小时预算 + 全局失败冷却 30s + 连续 3 次失败熔断 2 分钟。

## dev-host PAGE 模板「反斜杠吞字符」白屏 bug（2026-10-23 15:00）
用户报 `localhost/:1536 Uncaught SyntaxError: Unexpected token ')'`，附 `enemyRe` 那行。

### 根因
`vite.config.ts` 里 `const PAGE = \`...\``（约 257~1893 行）是 **JS 模板字符串**。模板字符串对「非法转义序列的单个反斜杠」**直接丢弃反斜杠**：`\s→s`、`\d→d`、`\.→.`、`\/→/`。
- **致命型**：`\/` → 裸 `/`，正则提前闭合 → 后面 `(\d+)s+距...` 变成裸代码 → SyntaxError → 整页白屏。报错行号 1536 正好是渲染后的 `enemyRe` 行（`localhost/:1536` 是**行号**不是端口）。
- **静默型**（更阴）：`\s` `\d` → 裸字母 → 正则不再匹配 → 兜底逻辑算错但**零报错**。本次发现 3 处（bagN 背包数、resName/resDist 资源名+距离）。

### 本次共修 7 处（都在 PAGE 模板内）
| 行 | 内容 | 原后果 |
|---|---|---|
| 1792 | `enemyRe` 敌人正则 | **语法错误 → 白屏**（用户报的） |
| 1801 | `hpPct` 血量正则 | **语法错误 → 白屏**（同一段，第二个雷） |
| 1799 | `bagN` 背包数 | 静默失配 → 兜底永远当背包空 |
| 1803/1804 | `resName`/`resDist` | 静默失配 → 兜底不采集 |
| 692 | 商店物品名 `×N` 清洗 | 静默失配（10-03 引入的既有 bug） |
| 700 | `8\d` 强效药识别 | 静默失配（10-03 引入的既有 bug） |

### 修法（两种，别混用）
- **正则字面量**：反斜杠**双写** `\s` → `\\s`、`\/` → `\\/`（模板里 `\\` 才渲染成 `\`）
- **复杂正则**：改 `new RegExp("...")` 字符串形式（本次 enemyRe/bagN/hpPct/resName/resDist 用的这种）—— 更稳，不受双写层数困扰

2. 渲染 PAGE 模板 + 抽 `<script>` 做 `node --check` 语法校验
