# 2026-10-25

## cache-busting 修复连带踩坑：vite story-data 中间件 404 + ellipse 负半径

上一条修复（tilesetUrl 加 `?_=${Date.now()}`）暴露了两个下游 bug：

### ① vite `story-data` 中间件不剥查询串 → 404
- `vite.config.ts` 的 storyDataPlugin：`req.url` 带 `?_=<时间戳>` 时被原样拼进文件路径 → `existsSync("xxx.png?_=123")` 永远 false → 404。
- **修法**：`const urlPath = (req.url||"").split("?")[0].split("#")[0]` 先剥查询串再 `resolve`。
- ⚠️ connect 的 `use("/story-data")` 只剥挂载前缀，**查询串还留在 req.url 里**。
- vite dev 会监听 vite.config.ts 自动重启，改完即生效（无需手动重启）。

### ② `drawEntity` 兜底胶囊 ellipse 负半径 → IndexSizeError
- `App.vue:4390`：`ctx.ellipse(px, py-24, facingLeft ? -16 : 16, 24, ...)` —— **负 major-axis radius 直接抛异常**（这不是"翻转"语义）。
- 平时不触发是因为 tileset 加载成功走不到兜底分支；图集 404 时 `SHEET_TILESET.ready=false` → 全屏实体疯狂报错刷屏。
- **修法**：半径恒正 `r=16`，朝向改用中心偏移 `cx = facingLeft ? px-6 : px+6`。
- 审计了全文件 11 处 ellipse 调用：其余半径来源均非负（`Math.max(8,...)` 或 `16~20±sin`），只有这一处。

### 验证
- 带 `?_=` 请求 tileset：404 → **200**（1165305 字节）
- 回归：maps json / .tbg / dawnlike 带或不带查询串全 200
- `vite build` 重建 game.html

### 教训
- ★ **给固定 URL 加 cache-busting 前，先确认服务端能不能处理查询串**——所有手写 `middlewares.use` 的路径解析都要 `split("?")`。
- ★ canvas ellipse/arc 的半径参数**必须非负**，负数抛 `IndexSizeError` 而不是画反向——`facingLeft ? -16 : 16` 这种写法是错的。

## 编辑器显示「棋盘格」根因：图集 PNG 被浏览器缓存（旧图集 + 新地图数据）

**现象**：地图编辑器里网球场渲染成「绿格 + 暗紫格 + 蓝色杂点」的棋盘，而不是蓝底球场。

**根因（不是数据错）**：
- 地图 JSON 是**新的**（含 gid 13044-13078），图集 PNG 也是**新的**（有这些瓦片）。
- 但编辑器的 `api.tilesetUrl(coll)` 返回**固定 URL**（无 cache-busting），后端 `FileResponse` 只带 `etag`/`last-modified`、**没有 `cache-control`** → 浏览器启发式缓存住**旧图集**。
- 于是浏览器用「**旧图集 + 新地图数据**」渲染 → 新 gid 在旧图集里是**空槽** → 蓝地面没画出来 → 看到下层的草地/暗紫 → 棋盘格。
- 复现验证：用备份的旧图集 + 新地图数据渲染，**像素级复现**了用户截图。

**修复（三处）**：
1. `src/tools/toonflow-field-survival/map-editor/backend/server.py`
   - `GET /api/collections/{name}/tileset` → 加 `Cache-Control: no-store, no-cache, must-revalidate, max-age=0` + `Pragma`/`Expires`
   - `GET /api/tile-style/materials/{name}/tileset` → 同样
   - `GET /api/plugin-ui/{file_path}` → 同样（预览用静态资源）
2. `src/tools/toonflow-field-survival/map-editor/frontend/src/api.js`
   - `req()` 加 `cache: 'no-store'`
   - `tilesetUrl` / `dawnlikeUrl` / `dawnlike` / `sprites` / `dataSheets` 全部加 `?_=${Date.now()}`
3. `plugins/toonflow-field-survival/vue/src/assets.ts`（游戏端）
   - `resolveLocalTilesetUrl()` 的 dev 路径加 `?_=${Date.now()}`
   - 兜底 `_tilesetUrl` 也加 `?_=${Date.now()}`

**已验证**：
- 后端重启后 `curl -D` 确认响应头含 `cache-control: no-store, no-cache, must-revalidate, max-age=0`
- 5 个 API 端点全 200
- 前端 dev server (5176) 的 `/src/api.js` 含 cache-busting 与 `cache:'no-store'`
- 游戏端 vite build 通过，产物含 cache-busting
- ⚠️ 游戏端 vite 的 story-data 中间件**本来就有** `Cache-Control: no-store...`（vite.config.ts:271）→ dev 路径本来就安全，问题只在编辑器

**坑**：
- ★ **图集 PNG 换内容但 URL 不变 → 浏览器缓存**。凡是「磁盘文件会被外部改写 + URL 固定」的静态资源，都要禁缓存。图集是 1.1MB PNG，`new Image()` 加载，浏览器缓存很积极。
- ★ 判断依据：先分别验证「服务端返回的是新图集吗」「地图数据是新的吗」「按编辑器算法本地渲染对不对」——三步分离就能定位是数据问题还是缓存问题。我用「旧图集+新数据」本地渲染出用户截图，一击命中。
- ★ `map_design/base` 是**独立的旧快照**（自带旧图集 max gid 9419，地图无 court 瓦片）→ 自洽，不受影响，不用同步。
- ★ 编辑器后端默认端口 8000，前端 dev 5176；后端改了要重启（`taskkill //PID` + `python server.py local`）。

## 区域名串图修复：所有地图中央都显示「晨曦镇」

用户反馈：地图中央的「晨曦镇」文字要么去掉，要么跟随当前地图名显示，不要每张图都是「晨曦镇」。

### 根因（两层）
1. **后端**：`entry.ts` 开局时无条件把 `WORLD_REGIONS`（城镇 + 6 野区）写进 `s.map.zones`，其中 `WORLD_REGIONS[0].name` 硬编码为「晨曦镇」→ 任何地图（桑林/乱葬岗/锁灵塔…）中央都被画上「晨曦镇」，纯属串图。
2. **前端**：`getLevelDisplayName()` 调 `getStoryMapRaw(levelName)`，但 `getStoryMapRaw` 的 key 是**地图文件名**（"mulberryTown"），传进去的却是**关卡名**（"Mulberry Town"）→ 永远查不到 Tiled JSON 顶层的中文 name，退到硬编码表旧名（"城镇"）。该函数注释里本来就承诺「① Tiled JSON 顶层 name 优先」，属于**实现没兑现**的 bug。

### 改法
- `entry.ts`
  - `WORLD_REGIONS[0].name`：「晨曦镇」→「城镇」（通用默认名，不再是专属地名）。
  - 新增 `buildZonesForMap(mapDisplayName, levelName)`：城镇区名跟随当前地图名，其余野区名不变；start 里改为 `buildZonesForMap("", curLv)`。
  - `ensureTown()`：`s.town.name` 取 `s.levelName`（原来也是硬编码城镇名）。
- `vue/src/App.vue`
  - 新增 `resolvedZones()`：取 zones 并把 **safe 区（城镇）**的名字替换成 `getLevelDisplayName(currentLevelName.value)`；野区名保持不变。
  - 5 个消费点全部改走 `resolvedZones()`：主地图绘制(5179)、小地图绘制(6004)、当前区域判定(3958)、兜底刷怪判定(3289)、`activeSafeZones`(2671)、`mapZones` computed(1379)。
  - ★ 5 处必须统一，否则怪物 `zoneName` 记账（`zoneName === currentZone?.name`）会与显示名对不上。
- `vue/src/mapConfig.ts`
  - `getLevelDisplayName()`：先经 `levelNameToFile()` 把关卡名转成文件名再查故事包 → Tiled 中文名终于能命中。

**根因链**（非前端 bug）：dev-host 的 `seedStoryVisualMap()` 只认磁盘上的 `<故事>.tbg`；`map_design/黑塔：从超忆症开始成神/` 是**目录形态**（maps/ + images/ + compiled_dawnlike.json），磁盘上**没有 .tbg** → 模板 `map_visual:<故事名>` 播种失败 → 前端 `bundle=null` → `listLevelNames()` 返回空（LEVEL_FILES 已清空）→ 地图面板只剩当前关。

**修法**（`vue/vite.config.ts` 的 storyData 中间件）：
- 新增零依赖 zip 打包器（`zipDirToBuffer`：手写 local file header + 中央目录 + EOCD，deflate-raw 用 `node:zlib`；配 `crc32` 查表），规则与 `cli.py build_tbg_file` 一致：ZIP_DEFLATED、跳过 `test_data/__pycache__/node_modules/.git`、arcname 相对源目录。
- `ensureTbgBuilt()`：`.tbg` 请求时若磁盘没有 → 现场打包写 `<故事>.tbg`；若已有但源目录更新 → 写旁路包 `<故事>.tbg.devcache`，**不覆盖用户已有 .tbg**（手工/CLI 产物可能含调整，dev 调试不该静默破坏）。
- ★ 关键坑：判断必须放在 `existsSync(filePath)` **之前**。放后面则旧 .tbg 永远命中 → 源目录改动不生效（我第一版就踩了，源码改完刷新仍是旧内容）。
- 旁路包与标准包两套策略都实测过：黑塔（无 .tbg）→ 首次写标准 .tbg；赦夜人（已有 .tbg 且源更新）→ 走 .devcache，原 .tbg 字节不变。

## 地图编辑器：给实体加「形象（外观）」下拉框（换人物样子）

**用户诉求**：地图编辑器里选中实体，右侧「对象属性」面板没有换形象的地方；希望能下拉框选别的形象（实体类型也行）。

### 根因
**runtime 早就支持，但编辑器没有 UI 入口**：
- game.md 约定：**外观由 `object.gid` 指向图集，`entity_type` 只决定行为类**。
  链路已全通：`obj.gid` → `normalizeTiledMap` 提取 `npc.gid` → `injectMapNpcsToState` 写 `entity.gid`
  → `drawEntity` 走 `walkTileId(gid-1)`（第二帧读 compiled_dawnlike 的 `animated_id`）。
- 但编辑器的属性面板只有 类型/名称/显示名/阵营/等级/对话ID/目标地图，**没有任何地方能改 gid**。
- 实测：黑塔 mulberryTown 的 32 个 NPC 里 **30 个已有 gid**（外观早就设好了），
  只有**老周（id=310）和白子轩（id=311）**没 gid → 这俩就是用户截图里「形象换不了」的那两个。

### 方案（用户选定：图集贴图选择器 + 全部人物动画帧）
1. **后端新端点** `GET /api/collections/{name}/sprites`（backend/server.py）
   - 为什么不能复用 `/dawnlike`：那个端点**会丢掉全部无 description 的 tile**（3770 个），
     而人物动画帧恰好**没有 description**，只有 `animated` / `animated_id` → 编辑器根本看不到人物贴图。
   - 判定「可当形象」：有动画（人物/怪物 walk）或有 description（命名装饰）。
   - 去重：`animated_id < id` 的是别人动画的**第二帧** → 跳过（只收首帧）。
   - 黑塔实测：**1119 个 character 帧 + 1165 个 prop**。
2. **前端新组件** `frontend/src/SpritePicker.vue`
   - 缩略图网格（6 列）+ 名称/tile id 搜索 + 「只看人物」开关 + 「恢复默认（按类型）」。
   - 缩略图 = canvas 裁图集 → 2 倍放大 → `imageSmoothingEnabled=false`（像素风不能插值）→ toDataURL，带 Map 缓存。
   - 越界保护：tileId 超出图集范围返回空缩略图。
3. **接线**（frontend/src/App.vue）
   - `loadResources()` 里加 `spritesData.value = await api.sprites(collName)`。
   - `selectedObjInfo` 补 `gid: Number(selectedObj.value.gid) || 0`（回显用）。
   - 新增 `onPickSprite({gid, tileId, sprite})` → **写 `selectedObj.value.gid`**。
     ⚠️ gid 是 Tiled 对象**顶层字段**，不在 properties 数组里，**不能走 setProp**。
     gid = tileId + firstgid；gid=0 表示回退「按类型默认形象」。
   - 面板里插 `<SpritePicker>`（在「显示名」下面、「阵营」上面）。
