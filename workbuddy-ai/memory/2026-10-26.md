## 「角色加载慢数秒」修复：选人阶段不再 await 17MB 地图包

用户在 360 极速版实测：选人面板能出来（修复生效✅），但要**等很久角色才加载**。

### 耗时根因（App.vue onMounted）
生产 iframe 分支 `await loadStoryMapBundle()` **阻塞整个初始化链**：
1. `getTemplate` 拉 map_visual（17.4MB base64，数据库 → iframe）
2. `normalizeBundle` → atob + zip 解包（36.4MB 未压缩 / 1143 entries）
3. `applyTilesetImage`（1.16MB 图集 blob 解码）
4. 之后才轮到 `loadStartLevelName` / `loadMapConfig` / state 渲染

而**选人面板只需要 state.roles（十几 KB）**，完全不需要地图包。

### 修法
`App.vue` onMounted：`await loadStoryMapBundle()` → `void loadStoryMapBundle()`（后台跑）；
图集替换同样后台化（先等 bundle，再 applyTilesetImage —— 未换上前用 public/ 兜底，同源编译产物内容一致，到位后热替换 + invalidateBake）。

### 为什么安全（下游兜底链全查过）
- `loadStartLevelName`：bundle 缺失 → fetch ui/maps/first.map.json → DEFAULT_START_LEVEL（mulberryTown），且包内 first.map 声明的就是 mulberryTown → 无漂移
- `loadMapConfig`：`getStoryMapRaw` miss → fetch 前缀链兜底
- **进入 playing 时**（App.vue ~7359）已有 `loadStoryMapBundle(true)` 强制重读 + first.map 切图/重载碰撞网格的完整兜底 → 开局地图一定来自故事包
- `loadStoryMapBundle` 幂等（`loaded` 标记），后台/开局两处并发安全

### 部署
- `vite build` → `ui/game.html` → **复制到安装目录** `toonflow-app-run-db/plugins/1/com.toonflow.minigame-field-survival/ui/game.html`（宿主 getAsset 从这里 serve；静态文件即改即生效，无需重启宿主）

## 首次进小游戏「选人面板没有角色」——宿主 /plugin/tick 的 ctx.roles 取错了数据源

现象：插件安装后**第一次**进入小游戏，选人面板一个角色都没有（控制台 `[field-survival] 选人角色列表为空❗`）。
「点击开始游戏 → 退出 → 再进」就正常了。

### 根因（宿主侧，不是插件侧）
两条进入路径取 roles 的数据源不同：
- ✅ `MiniGameController.setup`（进入小游戏时）→ `roles: buildMiniGameRoleOptions(ctx?.state)` → 从**故事运行时 state** 取 → 13 个
- ❌ `routes/plugin/tick.ts`（前端开局 init 走的路径）→ `roles: Array.isArray(publicState.roles) ? publicState.roles : []`
  → `publicState` = **上次存档的 state** → 首次进入时为空 → 插件 init 拿到空 roles → 选人面板空

第二次进就好了，因为那时 `prev`/`publicState` 里已经有 roles 了。

### 修法
`toonflow-game-app/src/modules/game-runtime/engines/MiniGameController.ts`
- `buildMiniGameRoleOptions` 改为 `export`（原来私有）
`toonflow-game-app/src/routes/plugin/tick.ts`
- `ctx.roles` 改为：`liveRoles = buildMiniGameRoleOptions(state)`（state = `parseJsonSafe(session.stateJson)`，含 `player` + `npcs`），
  兜底仍用 `publicState.roles`；两者都空时打 warn 日志。

### 验证
- `npx tsc --noEmit` 通过；无循环依赖（MiniGameController 不 import tick 路由）
- 直查生产库 `toonflow-app-run-db/db.sqlite` 的 `t_gameSession.stateJson`：
  `state.player` = 陈曦(player)，`state.npcs` = 12 个（npc_1..npc_12）
- 用真实 stateJson 复刻 `buildMiniGameRoleOptions` 逻辑 → **13 个角色**
  （陈曦[player]、张晚意/林凡/老周/先生/苏晓/魏叔/陈母/百晓生/白子轩/小满[npc]、某女子/某男子[general]）
  前端 `selectableRoles` 过滤 player 后 = 12 个
- ⚠️ **宿主需重启才生效**：跑的是 `tsx src/app.ts`（**没有** `--watch`；`start-dev.ps1` 才有 `--watch`）
  → 改宿主 TS 后必须手动重启进程（pid 43404 监听 60002）

### 坑
- ★ **生产库位置**：`toonflow-game/toonflow-app-run-db/db.sqlite`（有 `t_gameSession` 表）。
  `toonflow-game-app/Toonflow-game/db.sqlite` 是旧的（无匹配 session）、`toonflow-game-plugins/db.sqlite` 是 0 字节空文件。
- ★ 宿主日志：`toonflow-game-app/logs/app-2026-10-26.log`。宿主侧排查锚点日志：
  `[worldRoles] 故事角色池(storyInfo world.settings.roles)` 和 `[minigame roles] 故事运行时角色 → 插件选人列表`。

## 插件安装后图集 401 Unauthorized（宿主 getAsset 环境）

现象：插件安装后跑起来，控制台
`GET http://127.0.0.1:60002/images/compiled_tileset_32x32.png?_=1792978304462 401 (Unauthorized)`

### 根因
上一轮给图集 URL 加 cache-busting 时，只考虑了 vite dev 的 `/story-data` 通道，没考虑**宿主（已安装插件）**的通道：

- `assets.ts` 的 `_tilesetUrl` 初值 = `_devTilesetUrl || "/images/compiled_tileset_32x32.png?_=" + Date.now()`
- 生产环境 `_devTilesetUrl` 为 null → 走裸路径 `/images/...` + `?_=`
- 宿主里 iframe 的 origin 是宿主服务（端口 60002），`/images/xxx.png` 指向**宿主自己的静态目录**，不是插件资源 → **需鉴权 → 401**
- 而且 `?_=` 查询串在 getAsset 通道也会被拦

### 修法（与 mapConfig.ts / eventEngine.ts 的既有模式对齐）
`plugins/toonflow-field-survival/vue/src/assets.ts`：
- 新增 `resolveTilesetFallbackUrl()`：
  - `location.href.includes("getAsset")` → `assetUrl("images/compiled_tileset_32x32.png")`
    → `/plugin/getAsset?pluginId=..&token=..&path=ui/images/compiled_tileset_32x32.png`（带 token → 200）
  - 否则 → `/images/compiled_tileset_32x32.png?_=<ts>`（dev/standalone 才用 cache-busting）
- `_tilesetUrl` 初值改为 `_devTilesetUrl || resolveTilesetFallbackUrl()`

**cache-busting 只能加在 `/story-data` dev 通道**：getAsset 通道带查询串会被宿主鉴权拦掉。
（生产环境的权威图集来自数据库故事视觉包 → blob URL，本来就绕过 HTTP 缓存，不需要 `?_=`。）

### 宿主环境的三种资源通道（务必分清）
| 通道 | URL 形态 | 何时用 |
|---|---|---|
| dev `/story-data` | `/story-data/<工具>/map_design/<故事>/...` | vite dev 中间件，可加 `?_=` |
| 宿主插件资源 | `/plugin/getAsset?pluginId=..&token=..&path=ui/...`（`assetUrl()`） | **getAsset 环境必须走这个**，否则 401 |
| 宿主站内绝对路径 | `${origin}/1/game/scene/xxx.webp`（`resolveAssetPath`） | 宿主 uploads 托管的资源 |

判定：`location.href.includes("getAsset")` → `inGetAssetEnv()`（mapConfig.ts:747）/ `isGetAsset`（eventEngine.ts:117）

### 验证
- 产物里确认压缩后逻辑正确：
  `function S1(){...location.href.includes("getAsset")?an("images/compiled_tileset_32x32.png"):"/images/compiled_tileset_32x32.png?_="+Date.now()...}`
  （`an` = assetUrl，`Op` = pluginBase）
- `assetUrl` 实现：`Op()` 生成 `/plugin/getAsset?pluginId=..&token=..&path=ui/` → 拼 `images/...` → 带 token 的完整鉴权 URL
- `ui/images/compiled_tileset_32x32.png` 存在且与 map_design 版 MD5 一致（`e78609cd...`），插件打包会 walk 整个 plugin_dir → 包含它

### 坑
- ★ **加 cache-busting 前必须先确认目标通道吃不吃查询串**。vite 中间件要 `split("?")`（否则 404），宿主 getAsset 通道带查询串 → 401。
- ★ **宿主里 `/images/xxx.png` 不是插件资源**，是宿主静态目录 → 401。插件自己的资源一律走 `assetUrl()`。
- ★ 端口 60002 = 插件宿主；8000 = 地图编辑器后端；5176 = 编辑器前端；3000 = 游戏 vite dev。
