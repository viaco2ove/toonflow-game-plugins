## 🐛 修 bug：面板「✕ 关闭」点了没反应（setPointerCapture 吞掉 click）

### 现象
用户截图反馈：锻造/炼丹面板右上角 ✕ 点击毫无反应，面板关不掉。

### 根因（不是 Vue 绑定问题，绑定一开始就是对的）
面板头部 `.forge-panel__head` 上有 `@pointerdown="onForgePanelDragStart"` 做拖拽，
里面调了 `setPointerCapture(e.pointerId)`。
**setPointerCapture 会把后续所有 pointer 事件（含 pointerup）重定向到捕获元素（head）**，
浏览器因此**不会在按钮上合成 click 事件** → 按钮的 `@click` 永远不触发 → 「点了没反应」。

关键点：pointerdown 在 button 上**冒泡**到了 head，head 捕获了指针 → click 丢失。
对照证据：聊天面板 `.chat-panel__header`、任务板 `.quest-panel__header` 的 header **没有拖拽**，
所以它们的 ✕ 一直正常 —— 只有「可拖拽 header + 内部按钮」的组合会中招。

### 修法（双保险）
1. **按钮上加 `@pointerdown.stop`** —— 阻止冒泡到 head，head 不会捕获指针：
   - `App.vue` 的 `.forge-panel__close`
   - `SystemPanel.vue` 的 `.sp-close`（**同一个坑，顺手一起修了**）
2. **拖拽启动时排除可交互元素** —— 抽出共享守卫，三个拖拽入口统一用：
   ```ts
   function isInteractiveTarget(t: EventTarget | null): boolean {
     const el = t as HTMLElement | null;
     return !!(el && el.closest && el.closest("button, a, input, select, textarea"));
   }
   ```
   用于 `onSysBtnDragStart` / `onSysPanelDragStart` / `onForgePanelDragStart`。

### 测试
`scripts/test-forge-panel.mjs` 新增「面板关闭按钮」分组（+12 项），含对照断言
（聊天/任务板 header 无拖拽）。套件 94 → **106 项全绿**。
全量回归 **451 通过 / 0 失败**（9 套件）。构建 v1.0.25 成功，
产物 `ui/game.html` 已确认含 `onPointerdown:...["stop"]`。

### ★ 通用教训（写进长期记忆）
**「可拖拽 header 里放按钮」= 按钮点不动。** 两个条件同时满足就会触发：
① 祖先元素在 pointerdown 时调 `setPointerCapture`；② 按钮是该祖先的后代。
修法二选一（最好两个都做）：按钮加 `@pointerdown.stop` / 拖拽启动时 `closest("button,...")` 排除。
排查口诀：**按钮渲染正常但点了没反应 → 先怀疑 pointer capture，不是绑定写错。**

## 🐛 修 bug：点「升级」只有面板关闭，没有任何反应（z-index 层级压住了弹窗）

### 现象
用户截图反馈：锻造面板 → 「⬆升级物品」页签 → 点某一行的「升级」按钮，
**只有面板被关闭了**，确认框、提示、成功弹窗一个都没出现。

### 根因：模态弹窗层 z-index 远低于面板
层级实测（修复前）：
| 元素 | z-index | position |
|---|---|---|
| `.forge-panel`（锻造面板） | **9998** | fixed |
| `.ev-confirm-overlay`（确认/多选/输入/结果/拾取 5 类弹窗共用） | **50** | absolute |
| `.hud-toast`（飘字） | **40** | absolute |
| `.sys-panel` 9997 / `.quest-panel` 9997 / `.chat-panel` 9996 | | fixed |

根容器 `.fs` 是 `position: relative` 且**没有 z-index** → 不创建层叠上下文
→ 弹窗层（50/40）与面板层（9998）在同一个根层叠上下文里直接比大小。

于是：点「升级」→ `onForgeUpgradeItem` 先 `forgePanelOpen=false`（面板关）→
`opUpgrade` → 材料检查/确认框 → **弹窗被 z-index 更高的面板盖住看不见**
→ 玩家观感 = 「只有面板关闭，什么都没发生」。

**为什么之前没暴露**：这套面板的弹窗（确认/多选/输入）大多由**脚本事件**触发，
那时面板是关的；只有「升级/打造/溶解」是**从面板内部**弹窗，才撞上这个层级问题。

### 修法
统一把「模态层」提到所有面板之上：
- `.ev-confirm-overlay`：`z-index: 50` → **10000**，`position: absolute` → **fixed**
  （fixed 才能覆盖整个视口，absolute 只覆盖 `.fs` 内容区）
- `.hud-toast`：`z-index: 40` → **10001**，`position: absolute` → **fixed**
  （飘字要在最上面，否则「材料不足」提示同样被面板吃掉）

修复后层级：
```
10001 .hud-toast（飘字）
10000 .ev-confirm-overlay（模态：确认/多选/输入/结果/拾取）
 9998 .forge-panel  .sys-btn
 9997 .sys-panel  .quest-panel
 9996 .chat-panel
```

### 测试
- `scripts/test-forge-panel.mjs` 新增「模态层级（z-index）」分组（+16 项），
  直接断言 overlay/toast 的 z-index > 各面板的 z-index。
- 新增 `scripts/check-zindex.mjs`（小工具）：打印层级表 + 检查没有面板压住模态层，退出码非 0 即失败。
- 套件 106 → **120 全绿**；全量回归 **465 通过 / 0 失败**；构建 v1.0.25 成功，
  产物已确认含 `z-index:10000` / `z-index:10001`。

### ★ 通用教训
**「从面板里弹出的模态框看不见」= z-index 分层没对齐。**
排查口诀：面板里的操作「只有面板关了」→ 先查弹窗的 z-index 与面板比大小，
再查 `position`（absolute 只覆盖父容器，fixed 才覆盖视口）。
根容器若 `position:relative` 且无 z-index → 不产生层叠上下文，
子元素的 z-index 会**跨父容器**与页面其它元素直接比较（很容易被 9998 这类大值压住）。

## 🐛 修 bug：练习假人「站桩不扣血」+「模拟实战不来打我」

### 现象（用户截图）
① 选「站桩模式」→ 打了假人，**看不到任何掉血**；
② 选「模拟实战」→ 假人**不追击、不攻击**玩家。
（截图里 dev-host 模式，地图为 mulberryTown 演武场，uid 251~254 四个假人）

### 架构前提（先搞清这几条，否则会改错地方）
- **dev-host 跑的是真 entry.ts**（vite.config.ts 的 dev-host 中间件加载 `entry.js`），
  所以 entry.ts 的敌怪 AI / damage() 就是线上的行为。
- **伤害只在宿主侧结算**：前端没有本地伤害代码 → `sendTick("attack",{targetId})` → 宿主 `damage()`。
- **练习假人是「客户端权威实体」**：前端 switchLevel 注入 `mapmob_<uid>_<ts>`，
  带 `trainingDummy:true`；前端合并时 `keptNpcs`（localNpcs 分支）**覆盖**宿主同 id 实体。
- 宿主侧 `applyLocalEnemies` 收前端上报的 localEnemies 清单并**重建**实体（走 makeEntity）。

### 坑 1：宿主重建实体时丢掉 trainingDummy / dummyMode（entry.ts）
`applyLocalEnemies` 重建时只显式拷贝了 id/name/hp/maxHp/atk/facing/cooldown/homeX/homeY/bounty/dropTable，
**trainingDummy / dummyMode 没抄** → 宿主侧 `damage()` 的 `if (target.trainingDummy === true)` 永不成立
→ ① 击碎时不写 `dummy_destroyed_<实体id>` flag（脚本轮询这个 flag 发经验 → 永远没奖励）
   ② 假人被当普通野怪结算（kills/金钱/掉落全错）。
**修**：`applyLocalEnemies` 里显式透传：
```ts
if ((raw as any).trainingDummy === true) {
  ex.trainingDummy = true;
  ex.dummyMode = str((raw as any).dummyMode, "") || undefined;
}
```

### 坑 2：站桩模式假人也会扑上来打玩家（entry.ts 敌怪 AI）
宿主 AI 的 `enemies.forEach` 完全不认 dummyMode → 站桩假人照样追击+攻击。
**修**：AI 循环开头加守卫（站桩 = 站着挨打，不追不打）：
```ts
if (ex.trainingDummy === true && String(ex.dummyMode || "") === "stand") {
  e.vx = 0; e.vy = 0; ex.aiState = "idle"; return;
}
```

### 坑 3：前端无脑覆盖 → 宿主的 hp 被改回满血（App.vue onHostState 合并）
假人属「客户端权威实体」，前端 `keptNpcs` 直接覆盖宿主同 id 实体 →
宿主 damage() 掉的血被前端旧值（满血）覆盖回去 → **玩家打了半天看不到掉血**。
但 side/dummyMode 必须保留前端版（那是事件脚本 setField 改的，以宿主为准会被每 tick 打回 neutral）。
**修**（**hp/alive 跟宿主，side/dummyMode 跟客户端**）：
```ts
// ⚠️ 必须在剔除 incoming 同 id 实体【之前】取宿主快照
const hostDummyStates = new Map<string, any>();
for (const h of incoming.entities) {
  if (typeof h?.id === "string" && h.trainingDummy === true) hostDummyStates.set(h.id, h);
}
...
const keptMerged = keptNpcs.map((e) => {
  if (e.trainingDummy !== true) return e;
  const hostSame = hostDummyStates.get(String(e.id));
  if (!hostSame) return e;
  return { ...e, hp: hostSame.hp, maxHp: hostSame.maxHp, alive: hostSame.alive, deathMs: hostSame.deathMs };
});
```

`scripts/test-training-dummy.mjs` 新增「★ 假人掉血与反击」分组（+9 项）。套件 55 → **64 全绿**。
全量回归 **474 通过 / 0 失败**（9 套件）。构建 v1.0.25 成功；
产物已确认：`entry.js` 含 trainingDummy/dummyMode 透传与站桩守卫，

### ★ 通用教训
**「客户端权威实体」与「宿主权威结算」会打架。**
- 客户端权威（脚本改的）：side / dummyMode / 位置 / 标签
- 宿主权威（结算方）：hp / alive / 伤害 / 经验 / 金钱 / 掉落
两者混在一起覆盖，就会出现「打了没反应」——**先把每个字段的权威方分清楚，再决定合并策略**。
另外：**宿主重建实体时容易丢自定义字段**（makeEntity 只认固定字段），
新增实体字段必须在重建处显式透传，否则前端有、宿主没有。
