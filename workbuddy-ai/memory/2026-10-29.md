### ★ 真 bug：eventEngine 的 flagCache 让「宿主写的 flag」永远读不到

**现象**：假人正常扣血、正常「散架了」，但**经验纹丝不动**（exp 76→76）。

**排查链**（ego-browser 读 dev-host 的 `window.__devHostPluginData`）：
1. 宿主 `damage()` 确实写了 flag：`dummy_destroyed_mapmob_252_<ts>` = true ✅
2. flag 确实落在**正确的 scope**（session scope，entry.ts 的 `tsApi.pluginData`）✅
3. 前端 SDK 读（缺省 scope）也能读到该 flag ✅
4. 但 `reloadFlags()`（强制重读）能拿到、**`getFlag()` 却拿不到** → 锁定缓存

**根因**：`eventEngine.ts` 的 `flagCache` 是会话内缓存，`loadFlags()` 里 `if (flagCache) return flagCache;`
→ **只有「切图 / 重载事件 / 面板写 flag」才 invalidate**。
战斗中的写入（entry.ts `damage()` 写 flag）**没有任何显式失效时机** →
E70 脚本的 `ctx.save.getFlag()` 轮询（1.2s 一次）永远读到旧快照 → 奖励永不发。

**修复**（eventEngine.ts）：
- `FLAG_CACHE_TTL_MS = 1000` + `flagCacheAt` 时间戳 → 缓存过期自动重读
- `save.getFlag()` 改 **强制重读**（`loadFlags(true)`）—— 它的主用途就是「脚本轮询宿主刚写的 flag」
- `saveFlags()` 落库后刷新 `flagCacheAt`（避免写-读竞态）
- `invalidateFlagCache()` / `reloadFlags()` 重置 `flagCacheAt = 0`

### ego-browser 本次用法要点（Windows/Git Bash）

- 脚本写 `.mjs`，用 `ego-browser nodejs < file.mjs`（`-e` 模式在 Git Bash 下静默失败）。
- `page.evaluate()` 回调**是同步的，里面不能 await**（`SyntaxError: await is only valid in...`）→
  需要等待就在外层循环里多次 evaluate。
- 游戏 UI 在 **iframe** 里 → `document.querySelector("iframe").contentDocument`。
- dev 模式可直接在 iframe 里 import 模块读内部状态：
  `await (iframe.contentWindow).eval("(async()=>{const m=await import('/src/eventEngine.ts'); return m;})()")`
- ★ **攻击入口是「右键」不是左键**（App.vue `onRightClick` / `@contextmenu`），左键只是移动。
  右键命中判定 = 点击位置 **1.5m** 内最近的活敌（假人也算）。
- 把世界坐标转成屏幕坐标要用 App.vue `onRightClick` 里那套相机反投影公式
  （`terrainScale.viewSizeMeters(zoom)` + `renderScale` + `sxInv`），否则点不中。
- 随机事件弹窗（如「采药」）会挡住「对打」按钮 → 先点「离去」关掉。
- 「对打」弹窗的选项按钮 class 是 `ev-select__item`（不是 `ev-confirm__btns`）。
- 读宿主 pluginData：`window.__devHostPluginData`（Map，key = `{p,s,k}` JSON，value = `{value,updatedAt}`）。

### ★★ 重要：上午那轮「假人不追击」的结论是**错的**（已推翻）

上午的采样只看了**前端** `state.entities` 的坐标，得出「坐标全程钉死 home（moved=0）」→ 判为不追。
**根因是采样方法错了，不是代码错了**：
- 前端 entities 是**合并产物**（客户端权威怪 + 宿主回推），duel 假人的 x/y 在合并时要靠
  `hostDrives`（App.vue ~7989）判定是否采用宿主值。
- 更致命的是：上午那轮**玩家已被假人打死**（phase=over → 前端 loop 停发 tick → 采样窗口里
  假人早已贴到 1m 攻击圈内停止移动，`vx=vy=0`），采样看到的就是"钉死不动"。
  **玩家死了 = loop 停 = 采样冻结**，这个坑极容易误判成"AI 没跑"。

### 下午复测（拦截 iframe 的 postMessage，直接看宿主推的真实 state）—— 三项全过

拦截手法（在 iframe 窗口上包 postMessage）：
```js
const f=document.getElementById('game'), w=f.contentWindow;
const orig=w.postMessage.bind(w);
w.postMessage=function(msg,target){
  if(msg&&msg.type==='tf_plugin_state'&&msg.state){
    const d=(msg.state.entities||[]).find(e=>/252/.test(e.id));  // 宿主侧实体快照
    // d.x / d.y / d.aiState / d.vx / d.homeX 都是宿主 AI 的真实值
  }
  return orig(msg,target);
};
```
★ `window.__devHostPluginState()` **不暴露 x/y/aiState**（只给 id/name/side/hasCS）→ 必须用 postMessage 拦截。

### 为什么 4m 边缘看着像"不追"（不是 bug，是 game.md 设计）

`MOB_DETECT_M = 4` 且 `MOB_DISENGAGE_M = 4`（entry.ts ~729-731，注释明说"与探测同值，无迟滞带"）。
玩家在 4m 边缘时：进 chase → 下一 tick preyIn>4 立刻转 `return` 归位 → **抽搐**。
再加上追击速度只有 0.72 倍（`moveTowards(e, t.x, t.y, speed * 0.72)`），玩家跑得更快。
→ 4m 外看就是"假人往回走"。这是设计，别当 bug 改。

### 本轮真正修掉的三个问题

1. **事件日志被刷屏**（entry.ts ~5440）：`localBuilt > 0` 每 tick 都 pushEvent
   「当前关卡敌怪已接入宿主 AI（4 只）」→ 实测 376 tick 里刷了 **35 条**，把战斗事件冲掉。
   修法：加 `_lastLocalBuilt` / `_lastLocalEpoch` 记忆，只在真的变了才记。
2. **epoch bump 过频**（App.vue entityRef Proxy ~7564）：bump 字段含 `hp`/`alive` →
   站桩回血定时器每秒改 hp → 宿主**每 tick 重建整张敌怪表**。
   修法：bump 只留 `side`/`dummyMode`（前端权威、宿主据此决定 AI 分支）；
   `hp`/`alive` 是**宿主权威**字段（伤害在 entry.ts damage() 结算后回推），不需要 epoch 重建。
3. **站桩假人血条不回血（改完 2 暴露出来的连带 bug）**：合并时无条件 `hp: hostSame.hp` →
   前端回的血下一 tick 被宿主回推覆盖 → 血量在 50/59 之间**震荡**而不是稳步上升。
   修法（两处配套）：
   - App.vue：合并规则按模式分流 —— **duel 假人 hp 跟宿主**（伤害在宿主结算，前端覆盖会抹掉伤害）、
     **stand 假人 hp 跟客户端**（站桩血条由 E70 脚本自己管，宿主只会因伤害下降、不会回血）。
   - entry.ts `applyLocalEnemies`：epoch 相同（不重建）时，把 **stand 假人**的 hp/alive 同步进宿主实体
     （否则前端回的血传不到宿主，宿主一直持旧值）。
   实测修复后血量单调递增：86→95→104→113→122→131→140→149→158→167→176→185（满血封顶）。
   ★ 注意：**只同步 stand 假人**，duel 假人的 hp 是宿主 damage() 结算的，前端同步会把伤害抹掉。

### 本轮确认**有效**的既有修复（工作树未提交，git diff 可见）

- `localEnemiesPayload` 上报清单**含中立假人**（trainingDummy 无视 side）—— 否则宿主敌怪表里没有假人。
- `applyLocalEnemies` 假人接管**无视 side 过滤** + 重建后 side 以前端为准 + 清旧时假人也按 id 清。
- `applyLocalEnemies` 重建时**显式透传 trainingDummy/dummyMode/dropTable**（makeEntity 会丢自定义字段）。
- App.vue 合并规则：**hp/alive 跟宿主，side/dummyMode 跟客户端，duel 时 x/y/facing 跟宿主**（hostDrives）。
- 城镇兜底刷怪守卫按「非假人 mob 数量」判定（假人不算野怪数据源 → 城镇不再凭空刷哥布林）。

★ **重要：iframe 内 rAF 被浏览器节流到 ~1Hz**（顶层窗口 60fps，iframe 只有 1.08fps）。
  → 游戏逻辑 tick 实际只有 1 次/秒 → 「10 tick 回一次」在墙钟上就是 10 秒。
  **测任何按 tick 计的频率，必须用宿主 tick 差值（dHostTick）而不是墙钟**，否则会误判成 bug。
  验证法：`window.__devHostPluginState().tick` 或拦截 iframe 的 postMessage 读 `tf_plugin_state`。

  前端 E70 只负责模式切换与 UI —— 伤害与回血同源，账才对得上。
