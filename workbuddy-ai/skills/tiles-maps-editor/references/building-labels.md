# 建筑物名称显示 — 三方案分析

> step5 分析稿。回答两个问题：
> ① 为什么每张地图中央都显示「晨曦镇」？
> ② 建筑物名称用哪个方案显示？

---

## 一、为什么地图中央显示「晨曦镇」

**它不是地图数据里的东西，是引擎的"区域划分（zones）"画上去的。**

### 渲染链路

```
entry.ts:745        WORLD_REGIONS 硬编码 7 个区域
                    └─ { name: "晨曦镇", x: 0, y: 0, r: 160, kind: "safe" }
entry.ts:4954       s.map.zones = WORLD_REGIONS...   ← 无条件覆盖每张图的 zones
App.vue:5148        allZones = s.map.zones（= 上面那 7 个）
App.vue:5211-5224   allZones.forEach: 画半透明大圆 + 圆心 fillText(z.name)
                    → 「晨曦镇」画在 (0,0) = 地图正中央
```

另外 `mapConfig.ts:619-631` 对 `mulberryTown` 还会自动生成一个
`{name: "城镇", x: 0, y: -2}` 的 safe zone（但被 entry.ts 的覆盖顶掉了）。

### 为什么"每张地图"都有

`entry.ts:4954` 是切图后的通用钩子，**不看是哪张图**，
把晨曦镇+6 野区这套"大世界区域方案"写到每张 `s.map.zones` 上。
所以延城一中、地牢、森林……每张图中央都有一个「晨曦镇」圆圈标签。

### 这是 bug 吗？

对**大世界地图**（overworld）来说这是特性；对**建筑内部/校园分区图**来说
是**配置错位**——区域方案应该跟地图走，而不是全局硬编码。

### 处理建议（本次不动代码，先记录）

| 选项 | 改动 | 影响 |
|---|---|---|
| A. entry.ts 里判断关卡：只有 overworld 才写 zones | 1 行条件 | 最小；校园图不再显示晨曦镇 |
| B. zones 写进地图 JSON（mulberryTown.json 顶层 `zones:` 字段） | 数据驱动 | `s.map.zones` 的覆盖逻辑要改成"地图自带优先" |
| C. 直接删覆盖 | 1 行 | 大世界的区域名全没了（不行） |

推荐 **A**：`if (levelName === DEFAULT_START_LEVEL || /town|overworld/i.test(...))` 才写 zones。

## 二、建筑物名称：三方案对比

| | 方案1：地面文字层 | 方案2：仿任务板悬浮牌 | 方案3：仿地图入口 label |
|---|---|---|---|
| 样式 | 文字直接印在地面 | 深底黄边圆角牌「📜 任务板」同款 | 红字黑影 + 红色脉冲箭头 + 红圈 |
| 现成代码 | 无（要新写绘制层+遮挡排序） | `drawQuestBoard` App.vue:4134，**现成** | portal 分支 App.vue:5693-5704，**现成** |
| 视觉噪音 | 最低（融进地面） | 中（牌子醒目但不闪不跳） | **高**（红圈+脉冲箭头，是"出口"语义） |
| 语义 | 像地图注记 | 像"可交互点" | 明确的"传送出口" |
| 挂载数据 | 新字段 | NPC 对象 `dialog:"BOARD"` 走公告板（会**替代原贴图**，不合适） | `full_name` → label，一处属性 |
| 缩放表现 | 随 zoom 缩放，远了看不清 | `k = ppm/20` 自适应，近大远小 | 字号随 `sx` 缩放 |
| 改动成本 | 高（新绘制管线） | 中（要新建 decoration 类型，不能借用 board——board 会吞掉原贴图） | **低**（加一个非传送的 label 分支即可） |

### 逐个说的坑

**方案1（地面文字）**：
- 要处理「墙挡字」「物体压字」——需要插进 y 排序的绘制队列，工程量不小
- 但效果最干净，适合以后做"地图模式"（M 键看全景）时用

**方案2（仿任务板）**：
- `drawQuestBoard` 是绑死在 **entity**（实体层）上的，且 `board:true` 会**整个替换**原贴图
  → 拿来标建筑会把楼画成公告板，不可直接用
- 正确姿势是抄它的**画法**（圆角深底+黄边+居中文字）写一个 `drawBuildingLabel`，
  挂在 **decoration 层**（App.vue 5630 的 building 分支后面）
- 视觉上是"醒目的牌子"，10 栋楼全挂会有点吵，可以做成**走近才浮现**（距离 < 8m 显示）

**方案3（仿地图入口）**：
- portal 的 label 文字部分（5699-5704）代码最简单，且已经在 decoration 层
- 但红圈+脉冲箭头的语义是"这里是出口"，标建筑会误导玩家以为能传送
- 若只抄**文字部分**（黑影+粉字），不抄红圈箭头，就是一个轻量的悬浮名

### 推荐

**推荐方案2 的画法 + 方案3 的挂载点**：
在 decoration 层的 `building` 分支后面加一个 `sign` 类型的 decoration，
画法抄任务板（深底黄边圆角牌，但文案用建筑名、去掉 📜、颜色改中性），
**近距离才显示**（< 10m 全亮，10~20m 半透明，>20m 隐藏）——
既不像传送门那样吵，又比地面字清晰，且完全复用现有绘制管线。

数据挂载：地图 JSON 的 Actors 层加 `entity_type: "SIGN"` 对象
（`full_name: "高三教学楼"`，gid 指向一块"告示牌"瓦片），
`mapConfig.ts` 加一个分支把它解析成 `{kind:"sign", label, x, y}` 装饰；
`NON_MOB_ENTITY_TYPES` 加 `"SIGN"` 防告警。

## 三、关于「晨曦镇」的位置

如果后续要做"校园区域名"（如「教学区」「生活区」），
应该走 **zones 数据驱动**（地图 JSON 顶层 `zones: [{name, x, y, rx, ry}]`），
`normalizeTiledMap` 已经会读 `json.zones`（App.vue:6727），
再让 entry.ts 别覆盖地图自带的 zones —— 区域名就会画在指定位置而不是中央。
